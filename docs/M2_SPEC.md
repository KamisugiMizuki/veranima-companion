# M2 专项细化：通道适配层（docs/M2_SPEC.md）

> 依据：DESIGN.md 4.8（通道感知）、4.9（通道绑定表达）
> **定位锚点**：本项目 = 给予用户真实感的情感陪伴 agent，双端存在（IM 文字 + 桌宠语音）。
> M2 是「同一灵魂，不同媒介的得体表达」——同一个角色在打字时和说话时，应该像同一个人
> 在两种场景下的自然切换，而不是两个不同的 AI。

---

## 1. 设计原点（为什么需要通道层）

**核心命题**：人类在不同媒介下的表达天然不同，但灵魂是同一个。

- 发微信 ≠ 打电话：打字利落、有打字节奏；说话有填充词、有语气、有停顿
- 真人不会在微信里发「嗯…那个…」——那是口语填充词硬搬到文字里，出戏
- 真人也不会在电话里说「嘛」「确实」——那是文字口癖硬搬到语音里，同样出戏

**通道适配 = 让表达形态随媒介自然变化，但记忆、情绪、关系、性格完全共享**。

## 2. 通道模型

### 2.1 通道定义

| 通道 | 媒介 | 表达特征 | 表情/形象 |
| --- | --- | --- | --- |
| `im` | 文字聊天（QQ/CLI） | 打字利落、短句、标点表情绪、文本口癖 | 无（文字本身是全部） |
| `tts` | 语音对话（桌宠） | 口语化、填充词、停顿、语速变化、非语义发声 | 表情标签驱动形象（M4） |

### 2.2 通道上下文（生成时注入）

Agent 生成回复前必须知道自己在哪个通道，prompt 注入通道语境：

- `im`：「你正在打字聊天。打字要利落，不用『嗯…那个…』这类口语填充词；长内容拆短句，标点表达情绪」
- `tts`：「你正在用户旁边说话。可以口语化，允许『嗯…』『那个…』填充词、自我修正和重复」

**prompt 引导为主**（生成时就带通道风格），**规则后处理为辅**（机械可逆的：感叹号限频、波浪号亲密度阈值、换行压缩）。

## 3. 通道渲染器（规则后处理）

### 3.1 接口

```
render(text, state, channel) -> text     # 纯函数，无副作用
```

### 3.2 IM 渲染规则（机械可逆，按优先级）

| 规则 | 行为 | 依据 |
| --- | --- | --- |
| 感叹号限频 | 每段 ≤1 个 | 满屏感叹号是营销号不是真人 |
| 波浪号阈值 | 亲密度 <80 时「～」→「。」 | 波浪号是亲密期解锁项（4.8 亲密度阈值差异化） |
| 换行压缩 | 3+ 连续空行压为 1 | 排版卫生 |
| 表情限频 | 按角色卡 `emoji_frequency`（never/low/medium/high） | 表情密度是角色性格的一部分 |

### 3.3 TTS 渲染规则（M3 落地）

- 填充词保留（生成时已带）
- 停顿标签 `[pause=0.5s]` → 合成时留白
- 语速/音量标签（兴奋快+高、沮丧慢+低）
- 非语义发声（嗯- / 啧 / 哎）保留

## 4. 渲染器挂载点（统一出口）

**所有输出走一个出口**：主回复 / 问候 / 主动消息 / 打断 / 撤回——adapter 的发送函数前执行 `render()`。

- 挂一个点全覆盖，不遗漏（设计红线：不允许任何消息绕过渲染器直接发送）
- IM 渲染器 M2 实现；TTS 渲染器 M3 实现（无消费者不写，接口先留）

## 5. 跨通道共享（不精分的保证）

### 5.1 共享 Agent 核心

- QQ adapter 与桌宠都是**同一个 Agent 实例**的前端——记忆/情绪/依恋度/精力/话题计数完全共享
- **不精分**：用户在 QQ 上聊了半小时，回到桌宠前，她记得刚才聊了什么

### 5.2 无缝衔接

- 用户回到电脑前（L0 在场检测识别 absent→present）→ 从共享历史接续最近话题
- 「你刚才 QQ 上说的那个…后来怎么样了？」——**跨通道连续性本身就是真实感**（真人不会失忆）

### 5.3 通道互斥（资源保护）

- 某通道活跃时（如 QQ 有消息），视觉调度器进低功耗（暂停截图，只监听系统事件）
- 避免「手机聊天 + 桌宠盯屏」的双线程 token 浪费

## 6. 通道差异化表达（同一角色的两种形态）

### 6.1 口癖分通道

| 通道 | 口癖形态 | 例子 | 密度 |
| --- | --- | --- | --- |
| IM | 句尾语气词 + 固定开场 + 打字习惯 | 句尾「嘛」「确实」「啧」；错字缩写 | 每 2~3 条消息一次（辨识度非噪声） |
| TTS | 语音填充词 + 自我修正 + 非语义发声 | 「嗯…」「那个…」「怎么说呢」；「哎，我刚说错」 | 口语自然密度 |

**铁律**：IM 通道零语音填充词；TTS 通道零文本口癖。

### 6.2 亲密度阈值差异化

- 波浪号（文字亲昵）需关系分 >80
- 语音语气软化可更早触发（声音比文字更能承载亲昵）
- **依据**：文字亲昵是显性表态，语音亲昵是隐性温度——两者阈值天然不同

### 6.3 表达瑕疵分通道（联动 M1）

| 瑕疵 | IM | TTS |
| --- | --- | --- |
| 撤回 | 低确信时追加「撤回一下，我刚才打错了」限频 15~25% | — |
| 填充词 | 禁止 | 低确信时增多 |
| 标点退化 | 低确信时句号变空格 | 停顿 `[pause]`、语速变化 |

## 7. 表情标签（M4 前置，通道间传递）

- tts 通道输出结构化 `{"text", "tone", "portrait"}`——tone 驱动 TTS 语气，portrait 驱动形象
- im 通道纯文本（文字没有立绘，不强制 JSON，不牺牲 IM 表达质量）
- portrait 标签是**语义层**：LLM 只输出标签，渲染器映射到具体表现（静态图/Live2D 动作）——换渲染实现不换协议

## 8. M2 验收清单（体验级）

| 项 | 验收 |
| --- | --- |
| 通道语境注入 | 同一问题在 QQ 和桌宠得到的回复风格不同：QQ 利落短句，桌宠口语化带填充词——但内容/记忆一致 |
| 渲染器全覆盖 | 主回复/问候/主动消息全部过渲染器（无绕过路径） |
| 口癖隔离 | IM 回复中零「嗯…那个…」；TTS 回复中零「嘛/确实」文本口癖 |
| 波浪号阈值 | 低亲密度时「～」自动降为「。」，高亲密度保留 |
| 跨通道记忆 | QQ 聊过的事，桌宠无缝衔接提起（同一 Agent 不精分） |
| 通道互斥 | QQ 活跃时桌宠视觉降频（不烧双份 token） |

## 9. 暂缓内容（YAGNI）

- IM 通道流式（QQ 消息一次性发送，流式无意义）
- 多通道同时活跃的完整仲裁（MVP 只做互斥降频）
- 通道级独立记忆（不需要——共享记忆正是真实感来源）
