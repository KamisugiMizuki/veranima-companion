# Veranima 联网搜索策略设计

> 状态：设计稿 v2.3；Phase 0–4 的规则触发、未知实体兜底、相对/绝对时间归一化、2025-01 知识截止线闸门、生活安排排除、邻近指令重试复用、动态查询相关性过滤、IM/TTS 分通道结构化 JSON 回复、混合分析文本中的最后有效 segments 提取、busy 场景短答偏好（完整性优先、不做后处理截断）、内部 prompt/思考过程回显清理、有限多策略定位、候选聚合、验证搜索和有界页面正文补充已实现；独立 LLM 蒸馏、无限制全文抓取和长期外部事实记忆仍暂缓。
>
> 本文依据 `docs/newly_added/design_append.md` 逐条整理，并针对当前 Veranima 的人格、记忆、双通道和远程 LLM 架构收敛为可实现契约。当前实现范围以本文的状态说明和“未实现”标注为准。

## 1. 目标与非目标

### 1.1 目标

解决 chatbot 的“时代割裂感”：当用户谈到近期游戏、软件更新、新闻、社区争议或其他时效性主题时，Agent 能够在需要时通过本地 SearXNG 获取外部信息，并以当前角色的自然口吻回应。

联网搜索应当表现为：

```text
用户话题
→ 判断是否需要最新信息
→ 生成最小搜索计划
→ 查询 SearXNG
→ 清洗、去重、排序、保留证据
→ 将短期外部信息注入本轮上下文
→ 主 LLM 结合证据和角色生成回复
→ 按需保留“搜索见闻”索引，但不默认写入长期记忆
```

核心体验不是“让模型变成搜索引擎”，而是让它在聊到现实世界时不再完全失去上下文，同时保持角色连续性和事实诚实。

### 1.2 非目标

本阶段不做：

- 自动持续爬取网站或建立新闻数据库；
- 后台无用户话题的定时搜索；
- 广告推荐、用户画像出售或跨服务追踪；
- 自动把搜索结果写入永久记忆；
- 用搜索结果替代模型的常识回答；
- 让模型自行访问任意 URL、执行任意网络请求；
- 用“我刷到过”伪造模型真实经历；
- 为每条消息都调用搜索判断模型。

## 2. 设计原则

### 2.0 语境化新知注入

联网搜索的产品目标不是让 chatbot 变成搜索引擎，而是让它在用户谈到现实世界时具备“消息灵通但不卖弄”的连续感。搜索链路可以理解为：

```text
用户输入 → 意图/时效嗅探 → 搜索意图精炼 → SearXNG → 结果预处理
→ 证据约束下的角色化表达 → 本轮临时上下文 → 主 LLM 回复
```

原始搜索结果不能直接堆给模型，也不能被伪装成角色亲身经历。这里的“人格化蒸馏”采用保守定义：角色只改变语气、详略和表达顺序，不删除来源、不提高事实强度、不把“搜索到”改写成“我昨天刷到过”。

搜索结果不足时，宁可返回“没找到可靠信息”，不要用角色口吻掩盖不确定性。

### 2.1 证据优先，风格后置

搜索结果是外部证据，不是角色记忆。系统内部必须保留：

- 原始标题、摘要、URL；
- 来源域名；
- 搜索时间；
- 结果对应的查询词；
- 发布日期（若能解析）；
- 来源数量和一致性；
- 可信度与不确定原因。

角色口吻只负责表达方式，不能删除来源信息、改变事实强度或把未确认内容说成确定事实。

对用户输出时可以自然地说“我刚查到”“我看了几处资料”，但不应说成“我昨天刷到过”或“我亲眼看到”，除非这是明确的虚拟表达且不会造成现实身份误解。搜索结果若被具体引用，应允许用户追问来源。

### 2.2 确定性闸门优先，LLM 只做有限判断

搜索是否发生、查询次数、超时、结果数量、隐私过滤、证据注入和失败降级由代码控制。LLM 只承担：

- 在规则无法判断时，对“是否依赖当前信息”做轻量分类；
- 从用户原话中抽取搜索实体和查询意图；
- 在已有证据范围内生成最终回复。

不得让 LLM 自由生成工具名称、URL 或多轮搜索计划。

### 2.6 轻量优先与升级条件

第一版优先用代码完成关键词触发、实体候选提取、去重、质量标记和冲突提示。独立 LLM 蒸馏器不是默认依赖；只有在摘要过长或冲突无法由规则处理，且真实样本证明收益大于额外延迟时才启用。当前系统的主 LLM 直接在 EvidencePack 约束下生成最终回复，避免一次用户消息变成两次推理。

### 2.3 搜索失败不阻塞聊天

SearXNG 超时、空结果、引擎异常，都必须回退到普通聊天流程。普通闲聊或对上一条内容的纠正（例如“现在夏天呢姐姐”）不因“现在/目前/当前”等词单独触发搜索，也不能从上一轮图片识别文本推断搜索实体。HTTP 200 但模型没有遵守 JSON 形状时，不重复请求：把已有 content 交给 IM/TTS Reply 解析器，能提取普通文本就正常回复；只有空 content、连接/超时、鉴权或服务端错误才进入角色化卡顿兜底。远程 LLM 读取超时与“服务未启动”是不同错误，不能使用同一可见文案。回退时主 LLM 收到明确的“没有可用外部证据”状态，不得根据搜索失败继续猜测近期事实。

### 2.4 搜索上下文是短期上下文

搜索证据默认只在当前轮有效，不进入 `messages` 之外的长期记忆。只有用户明确确认某个事实，或后续产品明确需要建立可追溯外部事件记忆时，才另行设计写入协议。

### 2.5 双通道表达分离

QQ 和桌宠共用搜索结果数据契约，但表达渲染不同：

- QQ：简洁文字，可包含来源链接或“来源”折叠信息；
- 桌宠：语音优先，正文不朗读长 URL，必要时通过聊天窗展示来源。

搜索触发不应因为 TTS 或桌宠视觉事件自动发生。只有用户对话进入搜索策略，才允许产生本轮搜索。

## 3. 系统边界与调用链

```text
Agent.handle(user_text, channel)
    │
    ├─ 1. 输入规范化与隐私过滤
    ├─ 2. SearchTrigger.determine()
    │      ├─ NO_SEARCH → 普通 Agent 流程
    │      └─ SEARCH → SearchPlanner.plan()
    ├─ 3. SearchExecutor.search(plan)
    │      └─ GET http://127.0.0.1:8080/search?...&format=json
    ├─ 4. SearchProcessor.clean_dedupe_rank()
    ├─ 5. EvidencePack.build()
    ├─ 6. 将 EvidencePack 注入本轮主 LLM prompt
    ├─ 7. 主 LLM 生成角色化回复
    └─ 8. ResponseRenderer(channel) 输出；必要时附来源
```

建议采用一个普通的 core 服务对象，而不是把 HTTP 请求散落在 QQ adapter、桌宠 server 或 prompt builder 中：

```text
core/search/
  policy.py       # 触发判断、边界、查询预算
  planner.py      # 实体与查询计划
  client.py       # SearXNG HTTP 客户端
  processor.py    # 清洗、去重、日期与排序
  evidence.py     # EvidencePack 契约和 prompt 注入
```

这些模块是设计目标，不代表当前仓库已经存在；实现时应先扫描现有工具、LLMClient 和 Agent 入口，优先接入已有调用链，不平行造第二套对话管线。

## 4. 搜索触发策略

### 4.1 触发结果

```json
{
  "decision": "no_search | search | search_if_needed",
  "reason": "explicit_request | freshness | unknown_entity | current_state | stable_knowledge | casual_chat | privacy_blocked",
  "confidence": 0.0,
  "topic_key": "normalized topic",
  "user_requested": false
}
```

`decision` 不是直接等于“调用 HTTP”：还要经过隐私、冷却、预算和查询计划校验。

### 4.2 第一层：显式指令

出现以下意图时强制进入搜索：

- “帮我查一下”“搜一下”“看看最近”“查最新消息”；
- “现在怎么样”“目前版本”“刚更新了吗”；
- “这是真的吗”“有没有官方说法”；
- 用户明确要求链接、来源、对比多个说法。

显式搜索仍受隐私过滤、请求频率和超时约束；如果被安全规则拦截，必须解释无法搜索的原因，而不是静默伪装成普通回答。

### 4.3 第二层：规则识别时效需求

命中下列任一项，进入 `search_if_needed` 或 `search`：

| 类型 | 示例 |
|---|---|
| 时间词 | 最近、今天、昨天、刚刚、这周、目前、现在、最新 |
| 变化词 | 更新、上线、下架、改版、修复、发布、泄露、争议 |
| 当前评价 | 现在风评、最近社区怎么说、这波反响如何 |
| 事实核验 | 真的吗、官方确认了吗、有没有后续 |
| 状态依赖 | 当前价格、可用性、版本兼容、活动时间 |

“最近”不是固定等于 7 天。时间范围由用户词和主题类型共同决定，并写入 `SearchPlan.time_range`。

### 4.4 第三层：实体未知或知识不确定

如果用户提到的实体不在当前上下文、角色记忆、已确认的外部事实缓存或稳定常识中，且消息具有事实/介绍意图，默认进入 `search_if_needed`。这里的兜底原则是：**宁可多搜一次，不要瞎编一次**。

实体候选可由代码从以下信号提取：`《》`/引号包围的名称、中英文混合专有名词、连续大写字母或数字串、用户明确说“有个叫 X 的东西”。实体候选不等于事实，但它是搜索决策的输入。

应触发兜底搜索的示例：

- “最近出了个叫《X》的游戏，你知道吗？”；
- “一个叫 X 的东西是什么？”；
- “你听过 Project X 吗？”；
- “X 是谁做的/什么时候发布/现在还有后续吗？”。

“你听过吗”不再作为免搜例外：对疑似未知实体先搜索一次，再据结果回答是否找到。搜索失败时明确说没查到，并邀请用户补充上下文。

以下情况仍不兜底：纯情绪、玩笑、角色互动、没有实体且没有事实问题。已知实体的主观陪伴问题（如“你觉得这个好玩吗”）也不必自动搜索，除非带有“最近风评/现在评价”等外部状态要求。

### 4.5 第四层：轻量不确定性分类兜底

规则无法判断时，可调用轻量分类器输出受限 JSON：

```json
{"has_entity": true, "needs_factual_answer": true, "likely_out_of_knowledge": true, "should_search": true}
```

分类器输入只包含当前用户消息和必要的短上下文，不注入完整记忆，不执行工具调用。当前已实现同契约的标准库规则版；独立 LLM 分类器属于暂缓增强项，不能阻塞当前显式/规则搜索链。

分类器不得自行执行工具调用。单轮最多允许一次搜索计划。

### 4.5.1 知识截止线

为避免依赖模型自评“不确定”，默认将 `2025-01-31` 作为通用模型知识截止日：

- 请求范围完全落在截止日前，继续按旧的稳定知识规则处理；
- 请求范围的结束日期为空，或晚于 `2025-01-31`，强制联网核对；
- “今年/明年/最近/当前”等经归一化后落在截止日之后时，即使未开启隐式时效搜索，也进入搜索；
- 日期词本身不构成事实查询：`“明天补作业”`、`“今天没力气，明天把高数补上”`等生活安排/承诺不搜索；`“明天杭州天气”`、`“明天是什么节日”`等动态事实仍强制搜索；
- 这只决定是否查，不代表搜索结果自动可信；仍需经过来源质量、相关性和 EvidencePack 约束。

当前实现使用代码常量 `KNOWLEDGE_CUTOFF = 2025-01-31`，后续若更换模型，只需修改该常量并更新行为测试。

### 4.5.2 结构化回复协议

IM 与 TTS 的主对话都要求模型返回 JSON object，字段随通道分支：

```json
// IM / 单语 TTS
{"segments":[{"text":"可见且要朗读的文本","tone":"语气标签","portrait":"表情标签"}]}

// 双语 TTS
{"segments":[{"ja":"送 TTS 的日语台词","zh":"聊天窗口显示的中文","tone":"语气标签","portrait":"表情标签"}]}
```

- IM 只消费 `segments[].text`；单语 TTS 的 `text` 同时用于显示和朗读；双语 TTS 使用 `ja` 朗读、`zh` 显示；
- `thinking`、`analysis`、`reasoning` 等字段永远不消费；
- Agent 只把解析后的可见文本写入历史和消息表，再交给 QQ/桌宠渲染；
- OpenAI 兼容服务若支持 `response_format`，客户端发送 `{"type":"json_object"}`；
- 服务端拒绝该参数时自动退回普通文本请求，仍经过确定性清理，不因兼容性造成对话中断；
- 结构化协议不是安全边界的唯一保障，文本回退仍必须清理思考过程和内部 prompt。

### 4.6 明确不搜索的情况

以下情况直接普通聊天：

- 纯情绪表达、闲聊、角色互动；
- 用户正在谈论已经给出的确定内容，且没有追问当前变化；
- 稳定常识问题，且不含时效词；
- 搜索只会暴露隐私而没有必要；
- 当前轮已经搜索过同一主题且短期缓存仍有效；
- 用户明确说“不用查”“别联网”。

## 4.7 动态内容的语义定位

关键词触发解决“要不要搜”，不能解决“用户指的是哪一类动态内容”。例如“帮我找找现在明日方舟开启的活动复刻”同时包含游戏实体、事件类型和当前时间约束；直接把整句丢给搜索引擎，结果可能混入旧活动、玩家闲聊和非当前公告。

### 4.7.1 查询类型

| 类型 | 示例 | 默认策略 |
|---|---|---|
| 静态知识 | 明日方舟是哪家公司的 | 普通回答；未知实体仍走兜底搜索 |
| 动态状态 | 现在有什么活动、当前能不能玩 | 时间锚定 + 多来源候选定位 |
| 动态事件 | 最近出了什么新游戏 | 时间过滤 + 结果摘要（基础规则已实现） |
| 观点/评价 | 现在玩的人多吗、最近风评如何 | 社区/媒体结果并列，不当作客观人数事实 |
| 模糊指代 | 那个复刻活动叫什么 | 结合最近对话实体和候选结果，必要时追问 |

### 4.7.2 时间锚定

查询计划必须把相对时间翻译为绝对检索上下文：

- “现在”：当前日期附近，默认 `now-3d` 到 `now+1d`，允许未来预告；
- “最近/这几天”：默认过去 7 天；
- “昨天”：默认过去 48 小时；
- “最新”：默认过去 3 天；
- 没有时间词但因为未知实体兜底搜索：不强行伪造发布时间范围，使用当前日期作为查询词/排序信号。

#### 4.7.2.1 绝对日期归一化

代码必须使用本机当前日期（不调用 LLM）将常见中文相对时间转换为 `TimeRange`。范围端点按日历日、两端均包含；查询词同时追加可读的绝对日期锚点：

| 用户表达 | 语义 | 例：当前日期为 2026-08-22 |
|---|---|---|
| 今年/去年/前年/明年/后年 | 对应完整自然年 | 2026 / 2025 / 2024 / 2027 / 2028 |
| 今年七月、去年 7 月 | 指定年份的完整自然月 | 2026-07-01 至 2026-07-31 |
| 上个月/下个月 | 上一个/下一个完整自然月 | 2026-07-01 至 2026-07-31 / 2026-09-01 至 2026-09-30 |
| 今天/昨天/明天/后天 | 单个自然日 | 2026-08-22 / 2026-08-21 / 2026-08-23 / 2026-08-24 |
| N 天前、N 日前 | 单个历史日期 | 五天前 → 2026-08-17 |
| N 天之前、N 天以前 | 截止日期以前 | 五天之前 → 不晚于 2026-08-17 |
| 近/过去 N 天内 | 包含今天的滚动窗口 | 近五天内 → 2026-08-18 至 2026-08-22 |
| 后面/接下来/未来 N 天里 | 从明天开始的未来窗口 | 后面五天里 → 2026-08-23 至 2026-08-27 |
| N 天后 | 单个未来日期 | 五天后 → 2026-08-27 |
| N 个月前 | 以同一日为参考的单日 | 三个月前 → 2026-05-22 |
| N 个月之前/以前 | 参考日期以前 | 三个月之前 → 不晚于 2026-05-22 |
| 近/过去 N 个月 | 滚动月份窗口 | 过去三个月 → 2026-05-22 至 2026-08-22 |

`N` 支持阿拉伯数字和常见中文数字（如 `5`、`五`、`十五`）。无法完整解析的表达保留原文并不伪造范围；只追加当前日期或继续使用已有粗粒度规则。`TimeRange.start/end` 可以为空，分别表示“从最早记录开始”和“截至该日期”。天气、番剧、活动等查询必须把绝对日期写入 SearXNG 查询词，而不仅仅把范围留在内部过滤器。

SearXNG 不保证所有引擎严格遵守日期过滤，因此时间范围既用于查询词、结果排序，也用于主 LLM 的不确定性提示；没有可解析发布日期的结果不能被当作“当前正在发生”。

### 4.7.3 有界语义定位升级链

动态状态或明显模糊指代进入升级链时，执行以下有限步骤：

```text
意图解构 → 实体/事件类型消歧 → 时间锚定
→ 生成最多 3 个查询策略 → 结果聚合与候选实体提取
→ 只有候选无法区分或证据不足时，最多 1 次二次精确搜索
```

查询策略按需选择，不默认全部执行：

1. 官方公告/官网渠道；
2. 社区或媒体近期讨论；
3. 当前月份/日期锚定的泛搜索。

本升级链的硬上限：单轮最多 3 个初始查询、最多 1 个二次验证查询、总结果最多 5 条注入 EvidencePack。普通显式事实查询继续使用现有单查询路径。

### 4.7.4 候选不确定时的对话闭环

如果结果给出多个无法区分的候选，不应编造唯一答案。主 LLM 应：

- 列出最多 3 个候选及各自证据；
- 询问用户“你是指哪个”；
- 保留当前候选只在本轮上下文，不写长期记忆。

如果结果为空或完全不相关，应说明没找到可靠信息，并邀请用户提供看到它的页面、截图、关键词或其他线索。下一轮可用新线索重新规划，不自动累积旧查询。

## 5. 隐私与查询脱敏

搜索请求会离开本机到外部搜索引擎，虽然 SearXNG 部署在本地，但其后仍可能访问公网。因此搜索前必须执行：

1. 删除 API key、密码、token、邮箱、手机号、QQ 号、精确地址、文件路径、数据库内容；
2. 将用户姓名、账号名和私人实体替换为泛化占位符；
3. 不把完整历史上下文发给 SearXNG，只发送最小查询词；
4. 对“搜索某个人的私人信息”默认拒绝或要求用户缩小到公开、非敏感事实；
5. 查询日志只记录哈希后的 `topic_key`、时间、状态和耗时，不记录原始私密查询。

隐私过滤失败时采用 fail-closed：不发请求，走普通回复或明确说明无法查询。

## 6. SearchPlan 契约

```json
{
  "topic_key": "game:black-myth-wukong",
  "intent": "recent_update",
  "queries": [
    "黑神话 悟空 最新补丁 更新"
  ],
  "time_range": {
    "from": "now-7d",
    "to": "now"
  },
  "language": "zh-CN",
  "categories": ["general", "news"],
  "max_queries": 2,
  "max_results": 5,
  "timeout_seconds": 8,
  "user_requested": false
}
```

约束：

- 默认最多 1 个查询；只有“需要多方核验”才允许最多 2 个；
- 每次最多保留 5 条原始结果，注入主 LLM 的证据最多 3 条；
- 查询词必须来自用户当前话题，不得夹带角色卡虚构内容；
- 时间范围只作为排序/过滤信号，不能假设所有引擎都严格支持它；
- 使用 SearXNG JSON API：`http://127.0.0.1:8080/search`，参数至少包含 `q`、`format=json`、`language`；
- HTTP 超时、响应体大小和 JSON 数量必须有硬上限。

## 7. SearXNG 结果处理

### 7.1 统一结果结构

```json
{
  "title": "结果标题",
  "snippet": "搜索摘要",
  "url": "https://example.com/article",
  "domain": "example.com",
  "engine": "baidu",
  "published_at": null,
  "retrieved_at": "2026-08-22T12:00:00+08:00",
  "rank": 1
}
```

未提供的发布日期必须保持 `null`，不能用抓取时间冒充发布时间。

### 7.2 清洗与去重

按以下顺序处理：

1. 丢弃缺少标题、URL 或摘要的结果；
2. 只允许 `http`/`https` URL，拒绝 `file://`、内网管理地址、脚本协议；
3. HTML 转纯文本，限制标题和摘要长度；
4. 规范化 URL，去掉明显的追踪参数；
5. 用规范化标题、域名和摘要指纹去重；
6. 同一新闻转载只保留一到两条，不让单一媒体刷满结果；
7. 按相关性、来源多样性、日期新鲜度和来源质量排序。

### 7.3 来源质量

质量分不是“真伪证明”，只用于排序和表达谨慎程度：

- 高：官方公告、官方补丁说明、项目原始仓库；
- 中：多个独立媒体或专业站点一致报道；
- 低：单一论坛、未证实爆料、标题党聚合页。

只有一个低质量来源时，主 LLM 必须使用“有人提到”“目前还不能确认”等表达，并明确不要下定论。

### 7.4 有界页面正文补充

当搜索摘要过短且 `search.fetch_pages=true` 时，客户端可对最多 `max_page_results` 条公开 HTTP(S) 结果补充正文摘录。该能力不是无限全文爬取：

- 默认关闭；
- 默认最多 2 个页面；
- 只接受 `text/html`，禁用自动跳转；
- DNS 解析出的地址必须全部是公网地址，并固定连接到已校验 IP（保留原 Host/SNI），防止 DNS 重绑定；拒绝回环、私网、链路本地和保留地址；
- 单页响应有 `max_page_bytes` 上限，正文有 `page_char_limit` 上限；
- 使用标准库 HTMLParser 丢弃 script/style/noscript/svg/template，只保留可见文本；
- 页面失败、非 HTML、超限或解析异常时保留原搜索摘要，不阻塞主对话；
- 页面正文只进入当前 EvidencePack，不写文件、数据库或长期记忆。

### 7.5 动态查询相关性闸门

SearXNG 的单个引擎可能返回与主题无关的结果。对包含明确动态主题的查询（如游戏联动、天气、活动、新番、更新）执行轻量相关性过滤：

- 从查询中提取实体主体，去掉年份、时间词、查询动作和“联动/活动/预报”等意图词；
- 标题、摘要或 URL 至少命中主体实体，否则丢弃；
- 普通泛查询不强制套用该闸门，避免误杀没有专名的宽泛问题；
- 过滤后为空时按“没有找到可靠信息”降级，不能把后端噪声当作证据。

## 8. EvidencePack 与 Prompt 注入

### 8.1 内部结构

```json
{
  "topic": "黑神话悟空最新补丁",
  "searched_at": "2026-08-22T12:00:00+08:00",
  "facts": [
    {
      "claim": "某版本补丁说明包含卡顿相关修复",
      "support": "high",
      "source_ids": ["s1", "s2"],
      "published_at": null,
      "uncertainty": "未确认所有平台是否同时更新"
    }
  ],
  "sources": [
    {"id": "s1", "title": "...", "url": "...", "domain": "..."}
  ],
  "expires_at": "2026-08-22T12:15:00+08:00"
}
```

### 8.2 注入规则

证据注入必须明确告诉主 LLM：这是本轮外部检索材料，不是系统事实，也不是角色亲身经历。

推荐内部区块：

```text
【本轮外部信息，仅供核对】
检索时间：...
主题：...
- [高可信] 事实……（source: s1, s2）
- [中可信] 事实……（source: s3）

使用规则：
1. 只能使用上述证据支持的内容；
2. 证据不足时说不确定，不补写细节；
3. 不得把搜索结果说成亲身经历或长期记忆；
4. 用户要求来源时，返回对应标题和 URL；
5. 角色口吻可以自然，但不能改变事实强度；
6. 这是临时上下文，不要写入长期记忆。
```

这比把搜索结果伪装成“昨天刷到”更诚实，也能避免角色卡身份边界被联网功能穿透。

### 8.3 外部信息与普通记忆分层

- `EvidencePack`：仅本轮，带来源和过期时间；
- `messages`：只保存用户和 Agent 的实际对话，不把整份搜索结果塞进消息正文；
- `memories`：默认不写入；用户确认后如需保存，应只保存“用户确认的事实”和来源引用；
- 缓存：可做短期 topic cache，但必须带 TTL、来源和隐私清理，不得当作长期记忆。

## 9. 主 LLM 表达规则

主 LLM 的表达顺序：

1. 先回应用户真正关心的内容；
2. 再用证据补充近期变化；
3. 最后给出不确定性、来源或下一步建议。

不要求每次都提“我搜索了”。只有以下情况需要显式说明：

- 用户要求查证或来源；
- 信息存在争议；
- 结果只有低可信来源；
- 搜索结果与模型原有常识冲突；
- 搜索失败或结果不足。

禁止：

- “根据搜索结果”后直接堆标题；
- 把多篇转载当成多方独立确认；
- 将摘要中的推测改写成事实；
- 用搜索内容补造角色经历；
- 以角色口吻掩盖证据不足。

## 10. 缓存、重复搜索与刷新

### 10.1 短期缓存

按 `topic_key + normalized_intent + time_range` 缓存 EvidencePack，默认 TTL 15 分钟。缓存只减少重复请求，不改变证据的过期时间。

### 10.2 需要强制刷新

以下情况跳过缓存：

- 用户明确说“再查一下”“有新消息吗”；
- 主题是突发事件、服务状态或实时价格；
- 上次结果为空或来源质量过低；
- 用户指出结果可能过时或错误。

### 10.3 话题切换

每轮只处理当前主话题。新话题到来时，不把旧话题的 EvidencePack 继续注入；同一轮多个问题只在查询预算允许时拆成最多两个相关查询，不并行无限扩张。

### 10.4 无指明操作的重试

当用户说“再试试”“再试试看”“再来一次”等短句且没有新的操作对象时：

- 若上一轮存在搜索请求，复用最近一条搜索主题和规范化查询；
- 自动跳过短期缓存，执行一次强制刷新；
- 若上一轮没有搜索请求，不凭空联网；
- 用户同时提供新对象或新指令时，按新消息重新规划，不复用旧主题。

## 11. 失败与降级矩阵

| 情况 | 行为 |
|---|---|
| SearXNG 连接失败 | 记录状态，普通回复；不声称已查到 |
| 超时 | 截止请求，普通回复或说明暂时查不到 |
| 空结果 | 告知没有找到可靠近期信息，邀请用户补充关键词 |
| 只有低可信结果 | 可回答，但使用不确定措辞并附来源 |
| 结果互相矛盾 | 明确存在不同说法，列出来源，不强行裁决 |
| JSON/字段损坏 | 丢弃损坏条目，剩余条目继续；全损坏按空结果 |
| 隐私过滤失败 | fail-closed，不发请求 |
| 主 LLM 失败 | 使用现有普通降级回复；不得直接把原始搜索摘要发给用户 |
| 来源 URL 不安全 | 不注入、不展示，保留其他来源 |

## 12. 配置设计

真实配置保留在 ignored 的 `config/config.yaml`，示例配置只放无敏感默认值：

```yaml
search:
  enabled: false
  base_url: "http://127.0.0.1:8080"
  timeout_seconds: 8
  max_queries: 1
  max_results: 5
  prompt_results: 3
  cache_ttl_seconds: 900
  max_response_bytes: 1048576
  default_language: "zh-CN"
  default_categories: [general, news]
  allow_user_explicit_request: true
  allow_implicit_freshness_search: false
  semantic_locator_enabled: false       # 动态状态多策略/二次验证，默认关闭
  semantic_locator_max_queries: 3
  semantic_locator_max_verify_queries: 1
  fetch_pages: false
  max_page_results: 2
  page_char_limit: 1200
  max_page_bytes: 524288
  write_to_long_term_memory: false
```

设计上默认关闭，避免用户没有意识到时产生外部请求。设置页已提供：启用开关、SearXNG 地址、超时、隐式搜索、缓存、动态语义定位和有界页面正文补充；不提供“全局共享主动间隔”之类与联网搜索无关的配置。

## 13. 实现分期

### Phase 0：契约与探活

当前状态：规则版语义定位升级链已实现；默认关闭，不影响现有单查询路径。

## 14. 行为级验收

### 14.1 触发

- 普通闲聊不发 HTTP 请求；
- “帮我查最近的某游戏更新”必发一次搜索；
- “某游戏是哪年发布的”若配置允许隐式搜索，则触发搜索（避免新游戏超出模型知识范围）；
- “某游戏是什么”仍不因实体存在而自动搜索；
- 疑似未知实体 + 事实/介绍问题触发兜底搜索；
- “你听过 Project X 吗”对疑似未知实体先搜索一次；
- “再试试”在上一轮确实搜索过时复用上一轮主题并强制刷新，没有上文搜索时不发请求；
- “现在风评怎么样”触发隐式搜索；
- “今年七月新番”会按本机当前日期解析为对应年份的七月并把绝对月份写入查询；
- “明天杭州天气预报”会解析为具体日期并把绝对日期写入查询；
- “五天前/近五天内/后面五天里”分别使用单日、含今天的历史窗口和从明天开始的未来窗口；
- “去年/前年/明年/后年/上个月/三个月之前/过去三个月”使用自然年、自然月或滚动窗口边界；
- “现在有什么活动”不会只把原句机械搜索；启用语义定位后应先做时间锚定和事件类型定位；
- 动态状态搜索最多 3 个初始查询，最多 1 个二次验证查询；
- 多个候选无法区分时询问用户，不输出伪确定答案；
- 用户说“别联网”不发请求；
- 同一主题 TTL 内不重复请求，明确刷新除外。

### 14.2 证据与表达

- 主 prompt 包含 EvidencePack，但不包含完整聊天历史中的隐私字段；
- 结果有来源、检索时间和可信度；
- 摘要不足且开启 `fetch_pages` 时，最多补充两条受限 HTML 正文摘录；
- 一条低可信结果不会被表达成确定事实；
- 结果不足时不生成补造细节；
- 模型回显内部 EvidencePack、风格参数或搜索规则时，最终回复出口必须清理，不向用户暴露内部 prompt；
- 模型输出 `思考过程/分析输入/草拟回复/最终调整` 或 `<think>...</think>` 时，只保留最终答案；清理发生在持久化、IM 渲染和 TTS 之前，避免内部草稿进入下一轮历史。IM/TTS 结构化 JSON 与当前远程 OpenAI 兼容 API 已完成真实环路验证。
- 搜索 URL 可按用户要求返回；
- 搜索内容默认不进入长期记忆。
- 低可信来源带有不确定性提示；来源冲突不会被合并成单一确定事实。

### 14.3 故障

- SearXNG 连接拒绝、超时、非法 JSON 都能回退普通聊天；
- 一个坏结果不影响其他合法结果；
- 主 LLM 失败时不直接转发未经处理的搜索摘要；
- QQ 和桌宠使用同一证据契约，但渲染规则不同；
- 搜索不会被视觉注意力、TTS 或主动消息调度间接触发。

### 14.4 真实入口验收

实现时不能只测试 `SearchExecutor`：必须通过 `Agent.handle(..., channel="qq")` 和桌宠对应入口各跑一次 ProbeLLM，确认：

1. 触发判断确实接入生产调用链；
2. SearXNG 返回值确实进入当轮主 prompt；
3. 回复输出没有泄漏内部 JSON、tool call 或异常信息；
4. assistant 消息只保存最终回复，不保存原始搜索结果；
5. 新建 Agent/重启后没有把 EvidencePack 误当成长期记忆恢复。

## 15. 暂缓与升级条件

| 暂缓内容 | 触发条件 |
|---|---|
| 多轮搜索计划 | 单次查询在真实样本中经常不足，且延迟预算允许 |
| 专用搜索摘要 LLM | 代码清洗无法解决长摘要或冲突，且测得收益高于额外延迟 |
| 外部事实长期记忆 | 用户明确需要跨会话追踪，并完成来源、修正和删除契约 |
| 无限全文抓取 | 摘要不足以回答问题，且需要更大页面范围、分页或复杂站点解析 |
| 自动后台情报 | 用户明确开启，并独立设计通知频率、来源和撤销机制 |
| 结果个性化排序 | 具备足够用户反馈，且不会把偏好误当事实可信度 |


### 最终收敛

当前实现已收敛在“显式搜索 + 规则时效搜索 + 未知实体事实兜底 + 动态状态语义定位 + 绝对日期归一化 + 2025-01 知识截止线 + 邻近指令重试复用 + 动态查询相关性过滤 + IM/TTS 分通道结构化 JSON + HTTP 200 非结构化内容无重试解析 + 内部 prompt 回显清理 + 时间过滤 + 有界验证 + SearXNG + 证据注入 + 有界页面正文补充 + 失败降级 + 缓存/质量/冲突提示”。独立 LLM 分类器、后台情报、无限制全文抓取和长期知识养成仍不引入，除非行为测试证明规则版不足。
