# Veranima 真人感设计审计与修订记录

基线：`275a1bc`。范围：当前 Veranima，重点为安卓文字陪伴、人物与关系、记忆、主动性及虚拟生活；不将独立 isekai 世界引擎的需求倒灌本项目。

**本次交付是设计审计与设计规范修订。新增行为未改码、未完成实机验收。** 下文的“已修订”只指契约。实现探针发现的缺陷另列，不能以文档修正冒充修复。

## 1. 结论

这个项目已经有许多支持真人感的零件：独立日程、睡眠、自己的心境、关系历史、牵挂与记忆。主要问题是这些零件之间的规则有时互相抵消，而且系统事实、角色认知与对用户的表达未充分分开。

用户最容易看穿的地方，不是她少一个情绪值，而是：自己刚解释完她仍在生气；聊了很久却突然像不认识；你一接话她挂心的事情就算完成；另一角色知道没对她说过的情绪；每次出现都在交代日程；技术故障被解释成“她不想说话”。这些是连续性破裂，增加文风修饰不能补救。

修订方向：保留已有机制，把事实、解释、意向、权限和表达的边界讲清；补齐恢复、纠错与实际后果。没有引入新数据库、通用代理框架、身体数值模拟器或多智能体社交系统。

## 2. 方法与证据边界

> 本节记录设计审计那一轮的取证（56 passed 为当时的定向测试快照）。落码与全量回归结果见 §7–§9。

- 完整阅读总纲、人格循环、关系张力、共同创作、连续性方案、内心生活、用户情绪、多角色动态、连发协议、安卓范围、Harness 与文档地图。
- 定向核对日程的生活主题、睡眠、活动后果、自我分享、离线恢复；空间的场景恢复与表达；记忆的召回、置信度、删除及版本规则。对身体、目标、社会关系等候选做跨文档关键词反查。不是全仓逐段穷尽审查。
- 读取相关人格、张力、主动消息与记忆注入实现及测试；运行隔离对象探针，不接触用户私聊、生产库或实际密钥。
- 已运行相关测试：**56 passed**，覆盖关系状态、冲突、张力、情绪接线与人格评测。它们是现有断言的基线，不证明新增设计已实现。
- 上轮四路独立审查均遭服务商 HTTP 429，未取得可用审查结论；本报告采用主代理自行核对的证据，不冒称多方独立复核。
- 用户视角结论是基于具体使用场景的风险判断，未在本轮进行用户盲测、真机长跑或真实模型连续对话。因此“会破坏真人感”表示有明确触发路径的风险，不是测得发生率。

### R01：原因、自己知道原因、告诉用户原因被混成一件事

**依据**：总纲 §8.1 允许无法归因的波动；人格规范 §3.6 却要求状态必须有原因，§9.4 要求每次联想可追溯，§9.5 又要求情绪主要隐含表达。张力规范的克制型还要求不主动命名原因。

**用户后果**：她可能像诊断程序一样解释每种情绪，也可能让用户猜“是不是我惹她了”。

**修订**：系统来源、角色自知、可见解释分开；未知与多因合法。影响当前对话的负面简短说明有及可知原因，未知就说未知，不编造用户过错，不逐轮播报。

**归属与验收**：PERSONA_LOOP §3.6、§9.4–9.5、P-9 与验收；RELATIONAL_TENSION §9；DESIGN §1。同一烦躁跨轮有惯性但不重复报幕，未知原因不被补成用户责任。

### R02：情绪恢复与关系修复缺少分离

**依据**：张力规范 §6.3 把高档退出绑定有效互动轮次，§4.3 只让数值衰减；§8.3 软化仍主要降数值。

**实测**：隔离对象从高张力状态经过七天无新事件，数值降为零而表达档仍为 high。现有相关测试未覆盖这个反例。

**修订**：自然冷却可以退出情绪档；仍需坚持的边界单独保留。确认误判时撤销错误的派生影响，不受日正向额度与道歉轮次约束。真实伤害后的修复不由次数自动宣告完成。

**归属与验收**：RELATIONAL_TENSION §3.2、§6.3、§8.2、§14.3；PERSONA_LOOP §10。无新负面证据且数值归零必须退出高档；纠错后重启不复活指控。**对应实现尚未修复。**

### R03：自动问句容易变成关系负债

**依据**：张力 §4.1/§5.1 允许主动问题超窗加张力；已有“发送不等于已读”限制，但与安卓通知、暂停和跨角色期待的关系不充分。

**修订**：入库、发送、通知展示、已读和愿意回答分别处理。沉默可以带来角色自身轻微失落，不能证明恶意或违约。不可达与明确拒绝暂停或取消期待，不借同义追问绕过。收到回应可以停止催问，不等于相关事项已完成。

**归属与验收**：RELATIONAL_TENSION §5.1.1。通知失败不扣关系；拒谈后不换词催；不同角色的期待不互相误结算。

### R04：关系像升级游戏，失信像失忆

**依据**：人格 §3.4 的单线阶段；共同创作 §3.6 原要求当前阶段不低于登记阶段才能使用私人词。隔离探针中，高熟悉低信任得到“初识”。

**修订**：关系类型、熟悉史、信任与局部许可分别保留。友情不靠数值自动升级为恋爱；旧梗是否使用看语境与明确拒绝，不能因掉阶而失忆。

**归属与验收**：PERSONA_LOOP §3.4；SHARED_CREATION §3.6。熟人争执后仍记得往事，禁止称呼立即生效，升档不解除禁令。

### R05：人格独立性不能变成越界权限

**依据**：人格 §6.1 原将角色核心置于明确互动规则和关系边界之上，与同文不得突破用户边界冲突。

**修订**：隐私、删除、暂停和明确交互权限先确定允许空间；角色在其中保持独立意见。用户可以拒谈，不能要求角色必须赞同；角色可以不同意，不能继续纠缠。

**归属与验收**：PERSONA_LOOP §6.1。拒绝称呼或话题后，即使高亲密与强势人设也停止该动作。

### R06：生活有日程，缺少跨天后果的完整约束

**依据**：日程 §5.7 已有 LifeTheme、疲惫与社交透支；世界卡将家人同事名册归角色卡。因此不能说“没有生活或社会关系”。真正欠缺的是目标进展、身体限制和第三人职责如何连续影响安排。

**修订**：复用主题、牵挂、活动事件承载目标下一步、阻碍和退出条件；疲劳或有来源临时不适影响安排并有恢复条件；已有社会关系维持稳定身份和约定。无依据不造病，不强制每张卡有朋友，不新增模拟器。

**归属与验收**：VIRTUAL_SCHEDULE §5.7.1。多日追问目标可见一致进展或停滞；不适未恢复不会凭空消失；普通聊天不自动取消职责。

### R07：意向和挂心不能证明事情发生

**依据**：MIND_LOOP §3.1 示例用“两天后结果出了”驱动脚本，消亡条件包含用户接话和剧本走完。

**修订**：到期只允许检查；结果必须来自事件。接话减少牵挂强度，完成、取消、放弃另由事实确定。休眠也不是完成。

**归属与验收**：MIND_LOOP §3.1。用户说“知道了”不会把考试、训练或承诺标为完成；未获结果时不生成成功分享。

### R08：残响容易被写成负担或现实见面承诺

**依据**：MIND_LOOP §3.3 的“一宿都在想”与睡眠事实可能冲突；§3.4 的“去你那的高铁”会跨越现实行动边界。

**修订**：睡前心境可延续，但整理不等于整夜清醒；失眠须有真实模拟的延迟入睡依据。探访只在角色世界合法范围内，不向现实用户作线下约定。写回仍受职责、窗口和已有权限约束。

**归属与验收**：MIND_LOOP §3.3–3.4。整夜正常睡眠后不宣称被用户害得失眠；生活选择有自己的职责限制。

### R09：弱推断容易全天生效并跨角色泄漏

**依据**：USER_MOOD §2.3 当日态共享并按日期过期，未明确同日否认、恢复与知情角色。

**修订**：日期只是最晚保留边界；用户澄清当轮解除不适用约束，无证据不续期。预筛未命中不是恢复结论。推断保留来源角色，只供知情者消费；不新增情绪面板或长期标签。

**归属与验收**：USER_MOOD §2.3.1。说“我只是在赶工”后不继续哄低落；重启不复活；另一角色不突然知道原因。原 P0 校准要求仍保留，本次未实施情绪感知。

### R10：数据库共享不能等于所有角色共同在场

**依据**：MOMENTS §2 允许记忆共享；现有注入已存在在场标注，说明不是从零缺功能，但记忆主规范未把它与自然回忆、查记录统一说清。

**修订**：保留共享事实；亲历、转述、共同经历、承诺持有人分清。查得到原文不等于每次自然回忆都逐字精确。纠正使用当前解释，不加随机失忆或出口内容硬过滤。

**归属与验收**：MEMORY §10.5。跨角色不冒领“你对我说过”；自然回忆与受请求翻记录可区分；纠正跨重启有效。

### R11：连发时输入自由，回答却未必跟得上

**依据**：TURN_MERGE §2 原称历史足以承载回复归属、不需额外机制；§5 恢复依赖有限时间窗。

**修订**：保留生成中不打断，增加发送前明确取消/更正复核；回复保留原批次归属。入队、持久化、处理、交付分开；超窗不补答也不能标成已处理。合并保留图片与各条文本对应关系，重试不重发。

**归属与验收**：TURN_MERGE §2、§5.1。连发纠正、不同图片不同问题、切角色、入队后杀进程、交付前中断逐项验收。

### R12：降级可能直接暴露素材，补算可能伪造生活

**依据**：MOMENTS §4.2 原要求织文失败把素材原文分条入库；§5.1 允许补一条动态，但未明确事件时间与实际发布时间。

**修订**：合格自然摘要才可降级发布，否则保留素材或留白。补发区分发生和发布时间，不把离线未知活动改成完成。

**归属与验收**：MOMENTS §4.2、§5.1。故障不把内部标签送进信息流；重启不出现倒填的“早已发布”；无有效摘要不编经历。

### R13：全能、全透明也不像具体的人

**依据**：人格 §3.1 有能力边界，但运行表达侧缺少“会而不全说、不懂就查”的集中契约；内部状态多于表达的上位原则已有。

**修订**：不强制披露全部状态；可只说一部分或暂不想说，但不随机拒绝、吊胃口。兴趣不等于专业能力，搜索不等于亲历。认真求助仍在能力范围内帮助。

**归属与验收**：PERSONA_LOOP §11.2。不同专业设定回答的熟悉程度有差别；用户换话题后不追推自我独白。

### R14：验收配额会反过来制造表演

**依据**：DESIGN §8 把离场存在作为单一判据；MIND_LOOP §6 给出自我话题比例、每周回调次数和沉默解释率。

**修订**：把指标限定为观察与采样工具，不成为生成目标。独立生活、有限认知、稳定身份、因果连续、边界与对话自然度并行判断。安静角色与无新事件日允许留白。

**归属与验收**：DESIGN §8；MIND_LOOP §6。没有新事也不为了指标强发；技术全绿不冒充体验通过。

### R15：接得住不等于二十四小时即时在线

**依据**：DESIGN §8.1 原“始终接得住”与日程 §6 的明确不可交流状态存在歧义。

**修订**：维持已有睡眠裁决；不因情绪惩罚性拒绝，但睡眠与明确不可交流活动可以延后，恢复后接续。技术失败由应用说明并可重试，不能让用户以为角色在冷暴力。

**归属与验收**：DESIGN §8.1、TURN_MERGE §5.1。睡眠消息可恢复接续；网络失败不写成关系事件或角色作息。

### R16：旧设计状态与当前方向交错

**依据**：总纲仍以 QQ/桌宠为唯一产品表述，文档地图把已落地 Harness 标成待动工、内心生活标成草案；连续性旧方案包含已被后续机制吸收的建议。

**修订**：总纲明确当前安卓主端与 Windows 保留边界；更新地图相关状态，连续性稿标为历史候选来源；所有本轮修改规范标明设计修订不等于实现。

**验收与限制**：下一次开发能够从所属规范找到本轮契约。README、旧 Windows 分期、完整设置页与各历史实现矩阵仍有漂移，不在本轮冒称全部清理；重写这些入口须另做真实启动与界面核验。

## 4. 已有或有意保留，不能误报为缺漏

- 生活主题、睡眠债务、空间锚点、离线 unknown、负向情绪与恢复：已有设计与部分实现；本次补连续性和边界，不宣称新发明。
- 共享记忆是既有产品选择，保留物理共享，修正知情与表达。
- 她可以有负面情绪和带刺回应，保留；不改成永远温柔或全面服从。
- 主动发言不恢复统一每日硬配额；待织池仍服务语义连贯，沉默不算失败。
- 世界数据支撑自洽是产品愿景，保留；不以 YAGNI 砍掉既定地理设计，也不引入完整经济或社会仿真。
- 不通过随机错字、失忆、延迟和冷淡制造真人感。
- 不新增内部心智报表。已有明确要求保留的设置和关系页面不借此擅自删除。

## 5. 实现缺陷与实施次序

| 项 | 已有证据 | 当前状态 | 实施验收 |
|---|---|---|---|
| 高张力档无法仅靠时间退出 | 隔离真实对象探针，数值零仍 high | **已落码**（§7 第一批） | 自然恢复、误判撤销、跨重启、边界仍有效 |
| 非相邻关系事件重放累加 | 同一事件、另一事件、再次同一事件，信任再次增加 | **已落码**（事件账本） | 非相邻重放与重启重放均不重复应用 |
| 高熟悉低信任显示初识 | 隔离阶段派生探针 | **已落码** | 熟悉史不被关系降温覆盖 |
| 其余体验契约（R03/R06/R09/R11/R12 等） | 设计已回填 | 见 §8 差别表 | 按各条用户场景做行为验收 |

建议实施顺序：先修关系恢复、误判撤销与幂等；再处理消息归属、交付与恢复；随后补知情与推断纠正；最后做目标、身体与社会职责的持续后果。每阶段用真实生产调用链和连续对话验证，不一次新增所有模型。
