## 1. 设计结论

一句话：**世界层不是给用户看的地图，是一台把「地点 × 时刻」变成「通行时间、走法、可讲素材」的机器——并且它必须完整到经得起追问。**

四个判断：

1. **世界为主体的是数据面，角色为表达面。** 用户永远看不到地图；他能感知世界的唯一通道是追问她与她的表达。所以世界要"存在"（完整、自洽、有来源），不必"被看见"（无需地图 UI）。
2. **静态世界是角色资产，不是运行时产物。** 地方长什么样——锚点相对位置、路网、周边小店——生成一次、落盘在角色目录（独立世界文件）、可手编、可 diff、随角色包导出。运行期不允许再发明世界。
3. **动态部分是确定性纯函数，零运行期 LLM。** 今天走多久、走哪条路、路上挤不挤、哪家店周二休息，全部由「路网 × 时刻 × 天气 × 日期哈希」算出，与虚拟天气（D02）同款模式：同一天、同一角色，任何消费者看到同一个答案。
4. **不新建消费链。** 世界层产出的仍是 VIRTUAL_SPACE_SPEC 已定义的东西：`places`、`routes`、`ambient_context`、`virtual_life_events`——世界文件在加载期合并进既有结构，运行期下游零改动。

## 2. 世界感的设计原则与自洽不变式

**立规范目的（2026-09-16 二次裁决）**：本项目对世界的诉求不是"世界好玩"，也不是"世界精细"，而是——**用户能感觉到她背后有一个合理的世界在支撑她**。世界为主体的是数据面（她生活的地方存在、有约束、可被追问）；角色是表达面（世界只通过她与氛围被感知）。

三条原则：

1. **世界感 = 可被追问的一致性，不是物理完备性。** 用户不会看到地图；他能感受到世界的唯一方式是追问她，然后得到一个有根据、不打架的答案。世界的第一验收面是"被追问"。
2. **世界作为约束，不是作为景观。** 它的首要功能是限制她（做不了的事有具体原因）、给她背景（不属于当前对话的细节）——约束越完整，她越像生活在一个地方，而不是一个对话框。
3. **留白是合法状态，现编不是。** 世界没覆盖的地方，她坦然承认不知道；世界覆盖的地方，必须一致。两条合起来才是"合理"。

**自洽不变式（世界数据必须保证；验收逐条探）**：

| # | 不变式 | 用户追问出的样子 |
|---|---|---|
| I1 | 存在性封闭：她提到的每个地名 / 店 / 线路都在世界文件里 | "你说的那家店在哪儿？" → 有答案且指向世界数据 |
| I2 | 时空可行：她待过的地方与时刻能拼成一条无瞬移、无时间穿越的行程 | "你今天怎么过去的？" → 走法、时长、时刻自洽 |
| I3 | 节律一致：天气 / 时段 / 营业时间 / 末班车不互相打架 | "这么晚还有地铁？" → 不会出现违反末班车的说法 |
| I4 | 理由可溯：她的"去 / 不去 / 为什么"能落到世界的一条约束或她自己日程的一条真值 | "为什么不去那家？" → 有具体原因（关门 / 太远 / 累） |
| I5 | 描述稳定：同一地点的方位、性质、营业习惯跨轮跨日一致 | 三问同一家店 → 同一个答案 |
| I6 | 留白有边界：世界之外的东西她承认不知道 | "你那边有 X 吗？"（世界无）→"不知道 / 没注意" |

**运行期预算条款（世界厚、引擎薄）**：世界数据是全量的（供生成、校验、追问、日后可视化或游戏线复用）；运行期只消费两样——计划期烘焙的时长表 + 罕见事件的局部重算。逐段实时流量、车辆级模拟不属于陪伴线的预算（那是"世界被玩"的产品的成本表）。

## 3. 设计原点

现状（真实盘点）：地图上只有几张彼此无关的卡片。

- `space.places` 是几个独立地点；`space.routes` 是手写的两两配对加固定分钟数（例：出租屋 → 公司工位 40 分钟）；
- 地点没有相对位置——没有方向、没有远近、没有"路上经过什么"；
- 通行时间是常数——同一个 40 分钟在凌晨和早高峰完全相同；
- 周边世界只有被手写进 places 的零星个体（"楼下便利店"），没有"一片地方"。

后果是三种可见的薄：

| 薄在哪 | 用户看到的样子 |
|---|---|
| 地点之间没有关系 | 她永远说不出"顺路"的东西：上班路上带早饭、下班路上拐进便利店 |
| 时间是固定弦 | 通勤永不变化，也说不出"今天堵死了 / 今天绕了一截 / 今天车厢空得吓人" |
| 世界里只有三四个点 | 问她"中午吃什么""附近有什么"，答案要么在同一个短名单里打转，要么让 LLM 现编——后者直接踩真实性红线 |

因此设计原点只有一句：**地理的验收面不是地图精度，是她的表达与安排的形状。** 路网只需要承载两件事——通行时间与走法；场所只需要承载两件事——可去与可讲；节律只需要承载一件事——同一个地方在不同时间的不同感觉。

## 4. 目标与非目标

### 4.1 目标

1. 既有锚点之间产生稳定的相对位置与通行时间，且时间随时刻、日期、天气、路段状态变化；
2. 支持"顺路"与"绕行"：路径级判断（可停靠 / 改道）能被日程与表达使用；
3. 每个锚点周边有受控的场所池（餐饮 / 生活 / 娱乐），供日程选择与对话引用；
4. 场所带营业节律与低频生命周期事件，能产生虚拟生活素材；
5. 城际往返（异地卡）有真实的时间重量；
6. 一切世界数据可生成、可手编、可校验、可导出；任何缺失退化为现状，零阻断；
7. **世界可被追问**：§2 的 I1–I6 可被用户以探针式追问验证，答不出或打架即为缺陷。

### 4.2 非目标（明写不做）

- 真实地图数据、真实地理坐标、真实街道 / 店铺 / 公交线路；
- **全城尺度的道路复刻**：路网只为"被命名的活动点"服务，有规模预算（§5.3），不追求覆盖每一寸地面；
- **逐段实时流量与车辆级模拟**：世界厚引擎薄（§2 预算条款），流量的实时性不进陪伴线；
- 无限或全城尺度的场所生成；
- 地图 UI、可视化编辑器、空间调试面板；
- 由用户设备位置驱动角色世界；
- 角色之间共享同一座城市（v1 每角色独立世界，跨角色共享另立规范）。

## 5. 世界模型

```text
virtual_world.json（静态角色资产）
  锚点坐标 + 分级路网 + 线路 + 周边场所
        ↓ 加载期合并（单向，确定性）
既有 SpaceProfile：places / routes（手写值优先，几何值补缺）
        ↓ 运行期纯函数 + 计划期烘焙
TravelModel：路径 / 通行时长 / 段级流量 / 氛围档 / 稀有事件
        ↓ 写入既有字段
DayRoute / CurrentScene / prompt / virtual_life_events / 动态素材
```

### 5.1 坐标系与规模

- 本地平面坐标，单位=米，原点=该角色的家；只存整数坐标。
- 生活半径上限：距家 ≤ 8000 米（城际通道除外）。
- **禁止**：经纬度、以真实城市中心为原点、真实地标锚定、含真实城市名的方位描述。
- 坐标是角色资产的一部分，按 `role_id` 隔离，不进入共享记忆与用户可见文本。

### 5.2 锚点几何（AnchorGeometry）

世界文件里按 `place_id` 给既有地点挂几何：

```json
{"place_id": "xm_room", "at": [0, 0], "district_flavor": ["residential", "old_block"], "poi_radius_m": 700}
```

- `at`：坐标（家 = `[0, 0]`）。
- `district_flavor`：锚点周边气质（老城区 / 写字楼 / 江边 / 大学城），供生成器与表达使用。
- `poi_radius_m`：周边场所池半径（默认 700，市区 500–900）。
- 无几何的锚点：走既有手写 route 机制，不参与路网计算——部分退化是合法状态。

### 5.3 路网图（RoadGraph）

v1 的路网是**分级有向图**：节点（路口 / 车站 / 挂载点）+ 边（路段）+ 线路（地铁 / 公交）。

```json
"nodes": [
  {"id": "n_gate_home", "at": [0, 0], "kind": "gate", "ref": "xm_room"},
  {"id": "n_j_0017", "at": [320, -180], "kind": "junction"}
],
"edges": [
  {"id": "e_0031", "a": "n_gate_home", "b": "n_j_0017", "kind": "local",
   "length_m": 367, "modes": ["walk", "bike", "car"], "oneway": false}
],
"lines": [
  {"id": "l_ring", "kind": "rail", "label": "环线地铁",
   "stops": ["n_st_01", "n_st_02", "n_st_03"], "headway_minutes": 6,
   "first": "06:00", "last": "23:00"}
]
```

- **节点 kind**：`junction`（路口）/ `station`（站点）/ `gate`（命名点的挂载点）/ `poi_gate`（POI 挂载点）。
- **边 kind**：`arterial`（主干）/ `secondary`（次干）/ `local`（支路）/ `walkway`（步道）/ `rail`（轨道）/ `bridge`（跨江等）。
- **边属性**：`length_m`、`modes`（可通行方式）、`oneway`。边不记录车道数、红绿灯、转向——那是全城复刻，超出预算。
- **线路**：站点序列 + 发车间隔 + 首末班。轨道只走 `rail` 边；公交复用道路边但按线路站序停靠。
- **路径**：`path(from, to, mode, 日型, 档)` = 最小通行时间的边序列（Dijkstra，并列取边 id 序保证确定性）。轨道/公交需在 station 节点进出 + 换乘开销。
- **规模预算（硬上限，校验强制）**：节点 ≤ 600、边 ≤ 1200。生成器裁剪优先级：主干 > 锚点局部密度 > 其余；**命名点可达性优先于密度**。
- **挂载规则**：每个带坐标的锚点与每个 POI 必须挂到图节点（`gate` / `poi_gate`）——路由只认命名点，不认任意坐标。
- **叙述与追问收益**（保留它的理由）：走法可以讲（"今天从河边那条路绕的"）、路段可以有事（施工 / 管制）、高峰自动改道、被追问"你怎么去的"能给出具体走法。

### 5.4 周边场所（POI）

POI 是锚点周边的二等地点，**在数据上仍是 place**（加载期合并进既有 places 结构与校验），以 `tier: minor` 区别于锚点。

世界文件中的 POI 字段：

```text
id / label
category: meal | supply | leisure | walk    # 可承载的活动类别
subtype: noodle / cafe / convenience / cinema / ...
at: [x, y] + gate: 挂载节点 id
anchor_place_id: 所属锚点（必填）
windows[]        # 营业节律
flavor_tags[]    # 气质标签（平价 / 安静 / 网红 / 深夜）
lifecycle: {state, since, events[]}
```

子类默认集（生成与匹配用；角色卡气质可增删，这是默认集不是白名单）：

| 大类 | 子类（默认营业窗口） | 可承载活动类别 |
|---|---|---|
| 餐饮 | 早餐铺(06–11) / 快餐(10–21) / 咖啡(08–22) / 面馆(10–22) / 夜宵摊(20–03) | meal |
| 生活 | 便利店(24h) / 超市(08–22) / 生鲜(07–21) / 药店(08–22) / 快递点(09–20) | supply |
| 娱乐 | 影院(13–24) / 游戏厅(11–23) / 公园(05–22) / 沿江步道(24h) / 书店(10–21) / 健身房(06–23) | leisure, walk |
| 其他 | 理发 / 裁缝 / 修车铺 / 社区医院 | supply, leisure |

**POI 与日程的关系**（D3-A）：minor place 只在四类活动（用餐 / 采购 / 散步 / 消遣）中作为低权重候选，其余活动只在锚点间进行。日程里 POI 只会以「锚点 → POI → 回到同一锚点」或「顺路停靠」的形态出现，不会出现 POI 串 POI 的自由漫游。

**顺路判定**（路网版）：POI 作为路径插入点的代价

```text
detour(poi, a, b) = T(a → poi → b) − T(a → b)
en_route ⇔ detour ≤ 6 分钟
```

命中即为该 POI 生成到其 gate 邻点的可用边组，并在计划期作为低权重停靠候选参与地点选择（仅限 minor 允许的活动类别）。顺路停靠不占独立日程块，是移动缓冲内的可选点。

### 5.5 交通节律（TrafficProfile）

段级流量系数 + 修正项 + 抖动 + 路段事件，见 §7。表是设计值，可标定。

### 5.6 世界文件与加载契约（D2-B）

**文件**：`characters/<role_id>/virtual_world.json`（独立于 `virtual_schedule.json`）。

```json
{
  "schema_version": 1,
  "world_scope_id": "xm_work_city",
  "seed": "xumian-v1",
  "anchors": [],
  "nodes": [], "edges": [], "lines": [], "pois": [],
  "generator": {"tool": "worldgen", "generated_at": "", "notes": ""}
}
```

**职责划分（单一来源，互不重复）**：

| 数据 | 真值位置 |
|---|---|
| 锚点定义（label / kind / tags / sleep_allowed / 手写 routes / 手写 duration） | `virtual_schedule.json.space`（现状不变） |
| 锚点坐标、路网、线路、POI、生成器元数据 | `virtual_world.json` |

**加载期合并（单向、确定性、幂等）**：

```text
virtual_world.json
  → 校验（§11；引用完整性、连通性、规模、命名规范）
  → POI 转 minor place 并入 places 池
  → 由路网计算 route 基准时长，补缺（手写值优先）
  → 得到完整 SpaceProfile（消费方零改动）
```

- 世界文件缺失或校验失败 → 世界层整体关闭，`virtual_schedule.json` 自带内容照常运行（零回归）。
- 引用完整性：世界文件引用的锚点 `place_id` 必须存在于日程文件（否则丢弃该条）；POI id 不得与既有 place id 冲突；每个 POI 必须有合法 gate 节点。
- 导出：`.charpkg` 携带世界文件（受既有导出规则与隐私约束，无任何真实地理信息）。

## 6. 通行模型（TravelModel）

### 6.1 计算

```text
通行时间(from→to) = Σ 段[长度 / 段速(mode, kind)] × 段流量系数 × 天气系数
                    + 换乘 / 进出站 / 候车开销
                    + 模式切换惩罚
路径 = 最小通行时间的边序列（Dijkstra；并列取边 id 序）
```

设计值（可标定）：

| mode | 基础速度(米/分) | 固定开销 |
|---|---|---|
| walk | 75 | 0 |
| bike | 210 | 0 |
| bus | 340 | 5 分钟候车 |
| rail | 550 | 8 分钟（进出站 + 候车）|
| car | 420 | 3 分钟 |
| intercity_rail | 2200 | 25 分钟 |

路段等级修正（乘在段速上）：`arterial` 1.00 / `secondary` 0.85 / `local` 0.70 / `walkway` 不适用于机动车。

**确定性**：同一输入（起终、mode、日型、档、天气）恒定输出同一路径与时长；路径按上述输入缓存。这是"同一家店三问同一答案"（I5）的底层保障。

### 6.2 与既有结构的关系

- `routes[].duration_minutes` 的语义升级为**基准时长**（平峰、常规天气、无路段事件）。**手写值优先于计算值**——这是卡作者的校准旋钮：路网算出的 42 分钟若不符合角色设定，手写 40 即可覆盖。
- 未手写的边由路网算基准时长；两边都不可得时不生成边，保持既有"无合法路线"的失败语义。
- **计划期烘焙**：前一日生成次日计划时把当日流量系数烘进 transition 时长——纯函数、同日重算同值，不产生漂移。这是运行期的主路径。
- **运行期只做两件事**（预算条款，§2）：罕见延误/路段事件的局部重算；把世界素材放进既有通道。不做瀑布式顺延（单次 ≤ 15 分钟；紧邻的低优先级活动由既有弹性压缩机制吸收）。
- 路网不可达的对：不瞬移，不估造——按既有"减少地点变化 / 回退"处理。

### 6.3 顺路判定

见 §5.4：以插入代价 `detour ≤ 6 分钟` 为准（垂距只作生成器的预筛，不作运行期判据）。

## 7. 交通流量结构

### 7.1 时段表（工作日）

| 档 | 时段 | bus/rail/car | bike | walk |
|---|---|---|---|---|
| 早高峰 | 07:30–09:30 | 1.35 | 1.05 | 1.00 |
| 平峰 | 09:30–17:30 | 1.00 | 1.00 | 1.00 |
| 晚高峰 | 17:30–19:30 | 1.40 | 1.05 | 1.00 |
| 深夜 | 23:00–06:30 | 0.75 | 0.95 | 1.00 |
| 其他 | — | 0.90 | 1.00 | 1.00 |

### 7.2 段级修正（路网图的直接收益）

```text
段流量系数 = 时段档 × 路段等级修正 × 天气系数 × 抖动
路段等级修正：arterial 高峰 ×1.10 / local 高峰 ×0.90 / walkway 恒 1.00
天气：雨天 ×1.15、大风 / 雪 ×1.25（与 virtual_weather 同源同城）
抖动：±8%（段 id + 日期哈希）
```

段级修正让高峰改道成为自然结果（主干更慢 → 路径选择自动偏向次干），也让不同路线在同时段有不同感觉。段级系数在**计划期**参与路径与时长计算；运行期不逐段刷新（§2 预算条款）。

### 7.3 稀有事件（上限明确）

| 事件 | 触发与上限 | 效果 |
|---|---|---|
| 线路故障 / 大延误 | 晚高峰，每角色每周 ≤ 1 次 | 该 line 时段内不可用（rail 改 bus / 打车） |
| 路段施工 / 事故 / 管制 | 每世界同时 ≤ 1 条，持续 2–24h | 经过该段的路径重算并产生"绕行"素材 |
| 末班车已过 | 每日，rail line 首末班之外 | rail 不可用 → 打车或改日 |
| 暴雨困在路上 | 与天气联动，每角色每季 ≤ 2 次 | 到达推迟 + 素材 |

事件一律写入 `virtual_life_events`（source = world）→ 既有 D01/D05 素材；不自动广播。

### 7.4 氛围输出

系数映射到 AmbientContext 的拥挤档：< 0.9 空 / 0.9–1.15 正常 / 1.15–1.40 拥挤 / > 1.40 爆满。表达层只允许使用感觉词（挤 / 空 / 正常 / 绕了路），不得出现系数、百分比或计算过程。

## 8. 场所生态

### 8.1 营业节律

`windows[]` 参与地点校验：不营业时段不可被安排（接入既有地点校验点，与"地点关闭窗口"同一条纪律）。POI 歇业日可产生"今天没开门"级的小素材（低优先级）。

### 8.2 生命周期事件

新开 / 关张 / 换季 / 装修：每 POI ≥ 90 天冷却，每世界每周 ≤ 1 次进入素材池。事件只改 POI 状态与素材，不删除历史引用——她可以怀念一家关掉的店。

### 8.3 用户提到的店

只能匹配已有 POI：命中则正常引用；未命中则按"不知道 / 没注意"处理，**不得现编**（不变式 I6）。用户给出的现实信息不进入世界数据。

## 9. 城际（异地卡的世界接缝）

- 两座城市 = 两个世界文件（各含自己的锚点 / 路网 / POI），由一条 `intercity` 线路连接两端车站（时长 + 首末班）；
- 跨城日是重块（往返 ≥ 6 小时），只能落在休息日 / 假期；计划期标记为 notable（既有机制）→ D06 预告素材；
- 跨城语义仍是她自己的世界，不产生"现实见面"暗示（沿用 VSP §15 与现实行动红线）。

---

## 10. 表达与注入边界

允许注入：

- 当前位置的类型词 / 角色化名称；
- 通行感觉（挤 / 空、绕了路、走了多久的模糊说法）；
- 走法叙述（"从河边那条路过来"——路段 / 线路名必须是虚构或通用词）；
- 周边摘要（≤ 5 个 POI 的类型词，如"巷口面馆、街角便利店"）。

禁止注入：坐标、距离数值、路径长度、系数、内部 ID、完整 POI 表、路网结构、生成器元数据。

一致性：同一家店的存在性与大致方位必须跨轮一致（三问同一答案，I5）——由"世界数据是静态资产 + 路径确定性"保证。

红线继承 VSP §15 全部十条，另加三条：

1. 不得以真实城市为背景绑定真实店名 / 地址 / 真实道路或线路名；
2. 不得声称在真实场所消费或与人相会；
3. 用户地址永不进入世界数据。

## 11. 校验与回退

全部 fail-open，分级失败：

| 缺失 / 错误 | 行为 |
|---|---|
| 世界文件缺失 | 世界层关闭，既有手写 routes 照常运行（零回归） |
| 世界文件整体校验失败 | 同上；错误入日志，不阻断 Agent |
| 部分锚点无坐标 | 该锚点走手写 route；不参与路网计算 |
| 路网不可达的一对点 | 退化手写值；仍无则按既有"减少地点变化 / 回退" |
| 条级非法（POI / 边 / 段） | 丢弃该条，不整体失败 |
| 流量数据缺失 | 系数 1.0 |
| 生成器不可用 | 世界保持上次落盘版本（资产是文件，不是即时生成物） |

校验硬规则：

1. 坐标为整数且 |x|, |y| ≤ 8000；
2. 规模：节点 ≤ 600、边 ≤ 1200（超限 = 校验失败，生成器必须裁剪）；
3. 连通性：每个 `gate` / `poi_gate` 节点与家双向可达；所有锚点两两可达；
4. 边合法性：`length_m` > 0、`modes` 非空、oneway 不制造单向孤岛；
5. 线路合法性：站点必须是 `station` 节点、首末班合法、站序单调；
6. 命名规范：POI / 路段 / 线路名不得含门牌、电话、网址、坐标、真实城市名与真实品牌全称；
7. 引用完整性：世界文件中的 `place_id` 必须存在于日程文件；POI id 不得与 place id 冲突；
8. `windows` 合法且不自相重叠。

## 12. 生成器（角色创作期，一次性离线工具）

- 输入：角色卡的锚点集合、`virtual_life` 文本气质、城市规模档、`seed`；
- 结构由代码定（路网拓扑、边属性、线路、窗口模板、坐标布局）；命名与描述可由 LLM 产一次，不通过就手编；
- 路网生成骨架：主干网格（约 1km 间距，轻微抖动 + 少量斜线）→ 锚点局部密化（约 150m）→ 挂 `gate` / `poi_gate` 节点 → 铺线路（1–3 条轨道 + 0–4 条公交）→ 按预算裁剪（§5.3）；
- 生成后跑校验器（§11）+ 人工抽查（每锚点抽 2 条 POI 名称核对不可证伪性）；
- 产出落盘为角色资产：可手编、可 diff、可随 `.charpkg` 导出。

生成器的质量目标不是"像真城市"，是"**所有命名点可达、没有一条素材会被用户抓住现编**"（对应 I1–I6）。

## 13. 实现分期

| 期 | 内容 | 可见效果 | 相对体量 |
|---|---|---|---|
| W-0 | 世界文件契约 + 加载合并 + 校验 + 回退 | 零变化（保证零回归） | M |
| W-1 | 路网寻路 + 通行模型 + 顺路判定接入计划期 | 时间随距离 / 时刻变化；走法与顺路素材 | M |
| W-2 | 段级流量 + 氛围档 + 路段事件 | "今天堵 / 绕了 / 今天空"进入表达 | M |
| W-3 | 世界生成器（路网 + 线路 + POI + 命名；离线工具） | 世界可用、可手编 | L（最重） |
| W-4 | 生命周期事件 → 动态素材 | 低频"新开 / 关门 / 修路"话题 | S |
| W-5 | 设置页摘要 + 角色迁移（现有四卡世界生成） | 可开关、可查看 | S–M |
| W-6 | 真实链路验收（真实 API + 连续对话 + 追问探针） | 验收 | S |

**体量与风险（诚实分账）**：大头全在 W-3——路网生成质量与可达性保障是关键路径，不是运行期数学（运行期是寻路 + 纯函数 + 计划期烘焙）。三个已知风险与对策：

| 风险 | 对策 |
|---|---|
| 生成的路网"不像地方"（网格感、断头路） | 抖动 + 斜线 + 局部密化；质量线只卡"可达 + 命名不可证伪"，不卡城市学拟真 |
| 寻路性能与不确定性 | 按输入缓存；并列取边 id 序；图规模硬上限 |
| 图膨胀成全城复刻 | 节点 / 边预算写进校验（§11），超限即失败 |

## 15. 体验级验收

1. 工作日早高峰与凌晨的同一条路线，在耗时 / 拥挤感觉上可区分；高峰改道可被叙述（"绕了河边那条路"）；
2. 一周内自然出现 ≥ 1 次"顺路"表达（带早饭、下班拐进某店），且该店存在于她的世界数据；
3. 问"你家 / 你公司附近有什么"，答案来自该锚点的 POI 集；同一家店三问存在性与方位一致；问到世界外的东西，她承认不知道；
4. 同一地点在不同时段有不同氛围，拥挤四档中至少三档被触发过；
5. 路段事件发生当口，她的行程叙述与之自洽（绕行说法与路径一致）；
6. 连续 20 轮对话无坐标 / 距离数值 / 内部 ID / 路网结构泄漏；
7. 世界文件删除或损坏后，日程与对话行为回到现状且不报错；
8. 生成器验收：每个命名点双向可达；规模在预算内；抽查名称无真实信息。

**世界感三测**（§2 不变式的探针式验收，观察窗口须包含用户不在场的时间）：

| # | 测什么 | 通过判据 |
|---|---|---|
| I-边界感 | 她因世界约束而做不了 / 改了安排 | 每两周 ≥ 1 次，原因具体（末班车 / 店关门 / 太远 / 今天不顺路），不是空话 |
| I-背景感 | 出现不属于当前对话的背景细节 | 每周 ≥ 1 次（路况 / 天气 / 店的变化 / 别人的日常），且能在世界文件里找到来源 |
| I-一致感 | 对世界元素连续追问三次 | 答案不打架（存在性 / 方位 / 性质 / 时刻）；世界之外 → 承认不知道 |

## 17. 反事实与边界表

| 场景 | 必须发生 | 禁止发生 |
|---|---|---|
| LLM 被要求描述周边 | 从世界数据的 label 与类型词里选 | 现编店名 / 门牌 / 真实品牌门店 |
| 用户问"附近有 X 吗"且世界里有 | 正常引用并有稳定细节 | 同一家店两次说法矛盾 |
| 用户问"附近有 X 吗"且世界里没有 | 承认不知道 / 没注意 | 当场造一家出来 |
| 用户给出真实地址 | 只当普通文本处理 | 进入世界数据、锚点或坐标 |
| 用户追问一天的形成 | 行程、时刻、走法能拼成一条可行链 | 瞬移、时间穿越、答不出走法 |
| "这么晚还有地铁吗"类追问 | 首末班 / 营业窗为真值 | 深夜照常坐地铁 |
| 路段施工 / 管制 | 重算路径 + 绕行叙述，落素材 | 无视事件照常走该段 |
| 深夜需要通勤 | 按末班车规则改选方式或留宿 | 让 rail 在末班后照常可用 |
| 世界文件损坏 | 退回日程文件自带内容，日程与对话继续 | 阻断 Agent 或丢失回复 |
| 计划期算出的时长与手写值冲突 | 手写值优先 | 用路网覆盖卡作者的校准 |
| 图不可达的一对点 | 退化手写值 / 减少地点变化 / 回退 | 凭空瞬移或估造路径 |
| 图规模超预算 | 生成器裁剪后重新校验 | 让超限世界进入运行期 |
| 延误事件发生 | 推迟到达 + 落素材，单次 ≤ 15 分钟 | 瀑布式顺延导致整日崩坏 |
| 跨城出行 | 占用重块、走她自己的通道时间 | 产生"现实见面"暗示 |
| 角色切换 | 各自的世界互不可见 | 继承上一角色的 POI / 坐标 / 路网 |
