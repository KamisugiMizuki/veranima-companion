## 1. 设计结论

一句话：**世界层不是地图，是一台把「地点 × 时刻」变成「通行时间、顺路关系、可讲素材」的机器。**

三个判断：

1. **静态世界是角色资产，不是运行时产物。** 地方长什么样——锚点相对位置、走廊、周边小店——生成一次、落盘在角色目录、可手编、可 diff、随角色包导出。运行期不允许再发明世界。
2. **动态部分是确定性纯函数，零运行期 LLM。** 今天走多久、路上挤不挤、哪家店周二休息，全部由「坐标 × 时刻 × 天气 × 日期哈希」算出，与虚拟天气（D02）同款模式：同一天、同一角色，任何消费者看到同一个答案。
3. **不新建消费链。** 世界层产出的仍是 VIRTUAL_SPACE_SPEC 已定义的东西：`places`、`routes`、`ambient_context`、`virtual_life_events`。DayRoute / CurrentScene / prompt / 动态引擎零改动——世界的全部价值通过既有管道流出去。

## 2. 设计原点

现状（真实盘点）：地图上只有几张彼此无关的卡片。

- `space.places` 是几个独立地点；`space.routes` 是手写的两两配对加固定分钟数（例：出租屋 → 公司工位 40 分钟）；
- 地点没有相对位置——没有方向、没有远近、没有"路上经过什么"；
- 通行时间是常数——同一个 40 分钟在凌晨和早高峰完全相同；
- 周边世界只有被手写进 places 的零星个体（"楼下便利店"），没有"一片地方"。

后果是三种可见的薄：

| 薄在哪 | 用户看到的样子 |
|---|---|
| 地点之间没有关系 | 她永远说不出"顺路"的东西：上班路上带早饭、下班路上拐进便利店 |
| 时间是固定弦 | 通勤永不变化，也说不出"今天堵死了 / 今天车厢空得吓人" |
| 世界里只有三四个点 | 问她"中午吃什么""附近有什么"，答案要么在同一个短名单里打转，要么让 LLM 现编——后者直接踩真实性红线 |

因此设计原点只有一句：**地理的验收面不是地图精度，是她的表达与安排的形状。** 几何只需要承载两件事——通行时间与顺路关系；场所只需要承载两件事——可去与可讲；节律只需要承载一件事——同一个地方在不同时间的不同感觉。

## 3. 目标与非目标

### 3.1 目标

1. 既有锚点之间产生稳定的相对位置与通行时间，且时间随时刻、日期、天气变化；
2. 支持"顺路"：移动路径上的可停靠场所能被日程与表达使用；
3. 每个锚点周边有受控的场所池（餐饮 / 生活 / 娱乐），供日程选择与对话引用；
4. 场所带营业节律与低频生命周期事件，能产生虚拟生活素材；
5. 城际往返（异地卡）有真实的时间重量；
6. 一切世界数据可生成、可手编、可校验、可导出；任何缺失退化为现状，零阻断。

### 3.2 非目标（明写不做）

- 真实地图数据、真实地理坐标、真实街道 / 店铺 / 公交线路；
- 节点级路网图（路口 / 单行 / 红绿灯）——见 §4.3 与 D1 备选；
- 车辆级、行人级交通流模拟；
- 无限或全城尺度的场所生成；
- 地图 UI、可视化编辑器、空间调试面板；
- 由用户设备位置驱动角色世界；
- 角色之间共享同一座城市（v1 每角色独立世界，跨角色共享另立规范）。

## 4. 世界模型

```text
WorldMap（静态角色资产）
  地理布局：锚点坐标 + 走廊 + 周边场所
        ↓ 派生（确定性纯函数，零 LLM）
TravelModel（通行与节律）
  通行时长 / 顺路候选 / 氛围档 / 稀有事件
        ↓ 供给（写入既有字段，消费方零改动）
VIRTUAL_SPACE_SPEC 的 places / routes / ambient_context / virtual_life_events
        ↓
DayRoute / CurrentScene / prompt / 动态素材
```

### 4.1 坐标系与规模

- 本地平面坐标，单位=米，原点=该角色的家；只存整数坐标。
- 生活半径上限：距家 ≤ 8000 米（城际通道除外）。
- **禁止**：经纬度、以真实城市中心为原点、真实地标锚定、含真实城市名的方位描述。
- 坐标是角色资产的一部分，按 `role_id` 隔离，不进入共享记忆与用户可见文本。

### 4.2 锚点几何（AnchorGeometry）

已有 place 增加几何块：

```json
{
  "id": "xm_room",
  "at": [0, 0],
  "district_flavor": ["residential", "old_block"],
  "poi_radius_m": 700
}
```

- `at`：坐标（家 = `[0, 0]`）。
- `district_flavor`：锚点周边气质（老城区 / 写字楼 / 江边 / 大学城），供生成器与表达使用。
- `poi_radius_m`：周边场所池半径（默认 700，市区 500–900）。
- 无 `at` 的地点视为坐标未知：参与既有手写 route 机制，不参与几何计算——部分退化是合法状态。

### 4.3 走廊（Corridor）

v1 的路网不是图，是 1–3 条命名干线：

```json
{
  "id": "ring_rail",
  "label": "环线地铁",
  "kind": "rail",
  "path": [[0, 0], [2400, 300], [4200, 2100]],
  "detour": 1.0,
  "fixed_minutes": 8
}
```

- `kind` 枚举：`road`（公交 / 驾车）、`rail`（轨道）、`river`（沿河步道）、`walkway`。
- 作用一：**绕行系数来源**——两地点沿走廊的距离占比越高，绕行系数越接近走廊值；轨道另加固定进出站时间。
- 作用二：**叙述素材**——走廊名是她可以说出口的空间词（"沿着河边走"），必须是虚构或通用词，不得是真实路名 / 线路名。
- 明写：走廊不是通行图，不记录路口与转向。做不到"具体怎么走"级别的叙述，这是 D1-A 的已知代价。

### 4.4 周边场所（POI）

POI 是锚点周边的二等地点，**在数据上仍是 place**（复用现有 places 结构与校验），以 `tier: minor` 区别于锚点。

在既有 place 字段之上的增量：

```text
tier: "anchor" | "minor"
anchor_place_id      # minor 必填：所属锚点
at: [x, y]           # 相对坐标
windows[]            # 营业节律
flavor_tags[]        # 气质标签（平价 / 安静 / 网红 / 深夜）
service_categories[] # 可承载活动类别（meal / supply / walk / leisure）
lifecycle: {state, since, events[]}
```

子类默认集（生成与匹配用；角色卡气质可增删，这是默认集不是白名单）：

| 大类 | 子类（默认营业窗口） | 可承载活动类别 |
|---|---|---|
| 餐饮 | 早餐铺(06–11) / 快餐(10–21) / 咖啡(08–22) / 面馆(10–22) / 夜宵摊(20–03) | meal |
| 生活 | 便利店(24h) / 超市(08–22) / 生鲜(07–21) / 药店(08–22) / 快递点(09–20) | supply |
| 娱乐 | 影院(13–24) / 游戏厅(11–23) / 公园(05–22) / 沿江步道(24h) / 书店(10–21) / 健身房(06–23) | leisure, walk |
| 其他 | 理发 / 裁缝 / 修车铺 / 社区医院 | supply, leisure |

**POI 与日程的关系**（见 D3）：minor place 只在四类活动（用餐 / 采购 / 散步 / 消遣）中作为低权重候选，其余活动只在锚点间进行。

**地理边界**：minor place 只与所属锚点直连（生成器自动补往返边），跨锚点行程仍锚点对锚点。日程里 POI 只会以「锚点 → POI → 回到同一锚点」或「顺路停靠」的形态出现，不会出现 POI 串 POI 的自由漫游。

**顺路停靠**：POI 到两锚点连线的垂距 ≤ 500 米且绕行增量 ≤ 6 分钟时，生成器为它补上到第二个锚点的边——这就是"上班路上买早饭"的实现面。

### 4.5 交通节律（TrafficProfile）

按 mode 分区的时段系数表 + 修正项 + 抖动，见 §6。表是设计值，可标定。

### 4.6 数据落点（见 D2）

推荐：扩展角色目录 `virtual_schedule.json` 的 `space`，追加 `geography` 块（锚点几何、走廊、生成器元数据）。理由：一个加载器、一个导出路径、一个手编面。

## 5. 通行模型（TravelModel）

### 5.1 计算

```text
有效路程 = 直线距离 × 绕行系数(走廊, mode)
通行时间 = 有效路程 / 速度(mode) × 流量系数(mode, 时刻, 日型) × 天气系数
           + 固定开销(mode)
```

设计值（可标定）：

| mode | 速度(米/分) | 绕行 | 固定开销 |
|---|---|---|---|
| walk | 75 | 1.20 | 0 |
| bike | 210 | 1.25 | 0 |
| bus | 340 | 1.35 | 5 分钟（候车）|
| rail | 550 | 1.00 | 8 分钟（进出站 + 候车）|
| car | 420 | 1.30 | 3 分钟 |
| intercity_rail | 2200 | 1.00 | 25 分钟 |

### 5.2 与既有结构的关系

- `routes[].duration_minutes` 的语义升级为**基准时长**（平峰、常规天气）。**手写值优先于计算值**——这是卡作者的校准旋钮：几何算出的 42 分钟若不符合角色设定，手写 40 即可覆盖。
- 未手写的边由几何算基准时长；两边都不可得时不生成边，保持既有"无合法路线"的失败语义。
- 计划期（前一日生成次日计划）把当日流量系数**烘焙**进 transition 时长——纯函数、同日重算同值，不产生漂移。
- 运行期只处理**稀有延误事件**（§6.3）：只推迟到达时间与产生素材，不做瀑布式顺延（单次 ≤ 15 分钟；紧邻的低优先级活动由既有弹性压缩机制吸收）。
- 无坐标、无走廊、无手写值的荒地对：不估造，按既有"减少地点变化 / 回退"处理。

### 5.3 顺路判定

```text
en_route(poi, a, b) = 垂距(poi.at, 线段 ab) ≤ 500 米
                      且 绕行增量(poi) ≤ 6 分钟
```

命中即为该 POI 生成第二条边，并在计划期作为低权重停靠候选参与地点选择（仅限 minor 允许的活动类别）。顺路停靠不占独立日程块，是移动缓冲内的可选点。

## 6. 交通流量结构

### 6.1 时段表（工作日）

| 档 | 时段 | bus/rail/car | bike | walk |
|---|---|---|---|---|
| 早高峰 | 07:30–09:30 | 1.35 | 1.05 | 1.00 |
| 平峰 | 09:30–17:30 | 1.00 | 1.00 | 1.00 |
| 晚高峰 | 17:30–19:30 | 1.40 | 1.05 | 1.00 |
| 深夜 | 23:00–06:30 | 0.75 | 0.95 | 1.00 |
| 其他 | — | 0.90 | 1.00 | 1.00 |

修正项：周末峰值后移 1–2 小时且最大系数 ×0.9；节假日（复用既有日历源）×0.8；雨天 ×1.15、大风 / 雪 ×1.25（与 `virtual_weather` 同源同城）；日哈希抖动 ±8%（角色 + 日期）。

### 6.2 氛围输出

系数映射到 AmbientContext 的拥挤档：< 0.9 空 / 0.9–1.15 正常 / 1.15–1.40 拥挤 / > 1.40 爆满。表达层只允许使用感觉词（挤 / 空 / 正常），不得出现系数、百分比或计算过程。

### 6.3 稀有事件（上限明确）

- 线路故障 / 大延误：晚高峰触发，每角色每周 ≤ 1 次；
- 末班车已过：深夜 rail 不可用 → 只能打车或留宿，转成计划偏离候选；
- 暴雨困在路上：与天气联动，每角色每季 ≤ 2 次。

事件一律写入 `virtual_life_events`（source = world）→ 既有 D01/D05 素材；不自动广播。

## 7. 场所生态

### 7.1 营业节律

`windows[]` 参与地点校验：不营业时段不可被安排（接入既有地点校验点，与"地点关闭窗口"同一条纪律）。POI 歇业日可产生"今天没开门"级的小素材（低优先级）。

### 7.2 生命周期事件

新开 / 关张 / 换季 / 装修：每 POI ≥ 90 天冷却，每世界每周 ≤ 1 次进入素材池。事件只改 POI 状态与素材，不删除历史引用——她可以怀念一家关掉的店。

### 7.3 用户提到的店

只能匹配已有 POI：命中则正常引用；未命中则按"不知道 / 没注意"处理，**不得现编**。用户给出的现实信息不进入世界数据。

---

## 8. 城际（异地卡的世界接缝）

- 两座城市 = 两个 scope（各含自己的锚点 / POI / 走廊），由一条 `intercity` 通道连接（时长 + 首末班窗口）；
- 跨城日是重块（往返 ≥ 6 小时），只能落在休息日 / 假期；计划期标记为 notable（既有机制）→ D06 预告素材；
- 跨城语义仍是她自己的世界，不产生"现实见面"暗示（沿用 VSP §15 与现实行动红线）。

---

## 9. 表达与注入边界

允许注入：

- 当前位置的类型词 / 角色化名称；
- 通行感觉（挤 / 空、走了多久的模糊说法）；
- 顺路提示；
- 周边摘要（≤ 5 个 POI 的类型词，如"巷口面馆、街角便利店"）。

禁止注入：坐标、距离数值、绕行 / 流量系数、内部 ID、完整 POI 表、生成器元数据。

一致性：同一家店的存在性必须跨轮一致（三问同一答案）——由"世界数据是静态资产"保证。

红线继承 VSP §15 全部十条，另加三条：

1. 不得以真实城市为背景绑定真实店名 / 地址；
2. 不得声称在真实场所消费或与人相会；
3. 用户地址永不进入世界数据。

## 10. 校验与回退

全部 fail-open，分级失败：

| 缺失情形 | 行为 |
|---|---|
| 整个 geography 块缺失 | 世界层关闭，既有手写 routes 照常运行（零回归） |
| 部分锚点无坐标 | 涉及该点的计算退化为"城市平均绕行 × 直线"，标注为估算 |
| 走廊缺失 | 绕行系数取 mode 默认值 |
| 流量数据缺失 | 系数 1.0 |
| 单条 POI 非法 | 丢弃该条，不整体失败 |
| 生成器不可用 | 世界保持上次落盘版本（资产是文件，不是即时生成物） |

校验硬规则：坐标为整数且 |x|, |y| ≤ 8000；POI 名称不得含门牌 / 电话 / 网址 / 坐标；走廊名不得含真实城市名或真实线路名；minor place 必须有所属锚点；windows 合法且不自相重叠。

## 11. 生成器（角色创作期，一次性）

- 输入：角色卡的锚点集合、`virtual_life` 文本气质、城市规模档；
- 结构由代码定（坐标布局、边、窗口模板）；命名与描述可由 LLM 产一次，不通过就手编；
- 产出落盘为角色资产：可手编、可 diff、可随 `.charpkg` 导出（受既有导出规则与隐私约束）；
- 生成后跑校验器（§10）+ 人工抽查（每锚点抽 2 条 POI 名称核对不可证伪性）。

生成器的质量目标不是"像真城市"，是"**素材里没有一条会被用户抓住现编**"。

## 12. 实现分期

| 期 | 内容 | 可见效果 | 相对体量 |
|---|---|---|---|
| W-0 | 数据契约 + 加载校验 + 缺失回退 | 零变化（保证零回归） | S |
| W-1 | 通行模型 + 顺路判定接入计划期 | 时间开始随距离 / 时刻变化；顺路素材 | M |
| W-2 | 流量节律 + 氛围档 + 延误事件 | "今天堵 / 今天空"进入表达 | S |
| W-3 | POI 生成器 + 营业校验 | 周边场所池可用、可手编 | M–L（最重） |
| W-4 | 生命周期事件 → 动态素材 | 低频"新开 / 关门"话题 | S |
| W-5 | 设置页摘要 + 角色迁移（现有四卡世界生成） | 可开关、可查看 | S–M |
| W-6 | 真实链路验收（真实 API + 连续对话） | 验收 | S |

体量的大头在 W-3 生成器与一致性校验，不在运行期数学——运行期全部是几行纯函数。

## 13. 规模自检（如果只想要一部分）

| 档 | 内容 | 得到 | 放弃 |
|---|---|---|---|
| 最小档 | 手写 POI 名单，不建坐标与流量 | 她偶尔提到周边小店 | 顺路、时间变化、营业节律 |
| 推荐档 | 坐标 + 走廊 + 流量 + POI 限类进池（D1-A / D3-A / D4-A） | §3.1 的全部目标 | 路径级叙述精度（绕行 ±20%） |
| 完整档 | 真路网图 + 车辆级流量 + 全城生成 | 叙述细节更细 | 体量 ×3–5，且需先证明路径叙述真被消费到 |

## 14. 体验级验收

1. 工作日早高峰的移动回复与凌晨同路线的回复，在耗时 / 拥挤感觉上可区分；
2. 一周内自然出现 ≥ 1 次"顺路"表达（带早饭、下班拐进某店），且该店存在于她的世界数据；
3. 问"你家 / 你公司附近有什么"，答案来自该锚点的 POI 集；同一家店三问存在性一致；问到世界外的东西，她承认不知道；
4. 同一地点在不同时段有不同氛围，拥挤四档中至少三档被触发过；
5. 连续 20 轮对话无坐标 / 距离数值 / 内部 ID 泄漏；
6. 关闭世界层后，日程与对话行为回到现状且不报错。

## 16. 反事实与边界表

| 场景 | 必须发生 | 禁止发生 |
|---|---|---|
| LLM 被要求描述周边 | 从世界数据的 label 与类型词里选 | 现编店名 / 门牌 / 真实品牌门店 |
| 用户问"附近有 X 吗"且世界里有 | 正常引用并有稳定细节 | 同一家店两次说法矛盾 |
| 用户问"附近有 X 吗"且世界里没有 | 承认不知道 / 没注意 | 当场造一家出来 |
| 用户给出真实地址 | 只当普通文本处理 | 进入世界数据、锚点或坐标 |
| 深夜需要通勤 | 按末班车规则改选方式或留宿 | 让 rail 在末班后照常可用 |
| 世界层文件损坏 | 退回手写 routes，日程与对话继续 | 阻断 Agent 或丢失回复 |
| 计划期算出的时长与手写值冲突 | 手写值优先 | 用几何覆盖卡作者的校准 |
| 延误事件发生 | 推迟到达 + 落素材，单次 ≤ 15 分钟 | 瀑布式顺延导致整日崩坏 |
| 跨城出行 | 占用重块、走她自己的通道时间 | 产生"现实见面"暗示 |
| 角色切换 | 各自的世界互不可见 | 继承上一角色的 POI / 坐标 / 路线 |
