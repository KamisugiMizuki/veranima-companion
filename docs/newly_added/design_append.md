## 设计：“无人应答追问”机制（Unanswered Prompt Follow-up）

### 一、核心定位

- **触发来源**：AI向用户发送了一条**显式需要用户回复**的消息。
- **触发条件**：该消息发送后，经过一段设定的“静默期”（例如5分钟），用户**没有任何新消息输入**。
- **执行动作**：系统自动触发一次低成本的追问，内容模拟真人“等待回复时的确认”。

### 二、触发信号与前置判断

**关键点**：不是所有“需要回复的消息”都值得追问。系统必须在消息发送时，为消息打上一个**“期待回复标记”**，并在发送后持续监测用户的响应状态。

**需要回复的消息类型判定（由AI生成时决定）**：

| 消息类型       | 是否标记 | 示例                                                         |
| -------------- | -------- | ------------------------------------------------------------ |
| 直接提问       | ✅        | “你昨天说的那个事，后来怎么处理的？”                         |
| 请求确认/选择  | ✅        | “是这个意思吗？” / “你是想选A还是B？”                        |
| 期待共鸣/反馈  | ✅        | “你觉得呢？” / “我这么说会不会太过分了？”                    |
| 约定/许诺      | ✅        | “那我们明天这个时候再聊？”                                   |
| 情绪倾泻后留白 | ✅        | “……说实话，我有点难过。”（系统推断用户大概率会回复，故标记为待回复） |
| 陈述句无悬念   | ❌        | “我今天看了一本书，挺有意思的。”（无明确提问或邀请，不标记） |
| 社交套话       | ❌        | “哈哈，原来是这样。”（不期待回复，不标记）                   |

**前置条件检查（触发前必须全部通过）**：

1. **静默确认**：用户在该消息发送后X分钟内（默认5分钟），没有在该通道发送任何新消息。
2. **通道活跃度检查**：用户当前QQ/Pet在线状态，且没有进入`SceneLock`（睡眠/免打扰/忙碌）的锁定状态。
3. **AI状态检查**：当前角色未进入`sleeping`状态、未被`不满值（TV）`压制、未处于主动发言冷却期。
4. **历史追问次数**：该话题/该条消息未被追问过（只允许追问一次，不重复追问）。
5. **对话长度检查**：若用户之前已连续3次无视AI的消息，则本机制静默关闭（防止冷暴力循环）。

### 三、追问的“时机”与“内容”策略

#### A. 时机：动态静默窗口

- **默认窗口**：5分钟。
- **动态调整**：
  - 如果用户历史平均回复间隔较短（如通常在2分钟内回复），静默窗口可缩短至3分钟。
  - 如果用户历史回复间隔较长（如经常10分钟才回），则静默窗口延长至8分钟。
- **最小/最大**：最低3分钟，最高10分钟，防止过急或过迟。

#### B. 内容：必须遵循**“低负担 + 多模态适应”**原则

追问的目的是**“重新建立连接”**，而不是**“施加压力”**。因此追问内容应当是：

1. **简短**：字数不超过10个字。
2. **无信息负担**：不重复前文内容，不要求详细解释。
3. **情感中性或偏向积极**：不表达愤怒或失望（避免积累负面情绪）。
4. **允许无回应**：用户依然可以选择不回复，不触发第二次追问。

**推荐追问类型（按优先级排列）**：

| 追问类型       | 示例                              | 适用场景                           | 角色适配风格                       |
| -------------- | --------------------------------- | ---------------------------------- | ---------------------------------- |
| **存在确认型** | “嗯？” / “（探头）” / “？”        | 通用，最低成本，最安全             | 所有角色通用                       |
| **归因型**     | “掉线了？” / “我是不是说太长了？” | 当AI对前文内容有一定长度或复杂度时 | 温柔学姐：自责归因；毒舌：嘲讽归因 |
| **行为类型**   | “你还在看吗？” / “在听吗？”       | 当AI讲了较长故事或解释时           | 通用                               |
| **旁白型**     | “（等了会儿）” / “……”             | 当内容本身带有情感温度或沉默感时   | 文艺型/温柔型/迷糊型               |

**角色适配风格化示例**：

- **温柔学姐**：“嗯？是不是我刚才说太快了？”（轻微自责，温暖）
- **毒舌游戏宅**：“啧，你该不会是卡了吧？”（略嘲讽，但带有拉近关系的意图）
- **迷糊画家**：“啊……我是不是跑题了？”（略带困惑）
- **通用默认**：“（还在吗？）”


### 四、追问后的“对话恢复”逻辑

1. **用户回复** → 系统处理用户回复，继续正常对话；追问消息视为已消耗，不重复进入上下文。
2. **用户继续未回复** → 系统不再追问，该条消息的“追问窗口”关闭。
3. **用户中途上线但未回复该条消息** → 检测到用户有新消息输入后，自动关闭“追问窗口”，不再追问。

**重要**：如果用户未回复，这条消息不会自动进入“记忆”或“不满意”记录，除非用户主动提及或表示不满。


### 五、与现有架构的整合

#### A. 数据结构扩展
在消息发送时，增加一个字段来标记该消息是否“期待回复”，以及该回复的“追问状态”：

```text
message_metadata = {
  "expects_reply": True,           # 是否期待回复
  "follow_up_status": "pending",   # pending / asked / ignored / resolved
  "follow_up_sent_at": None,       # 追问发送的时间戳
  "follow_up_type": None           # 追问类型（可选）
}
```

#### B. 与主动发言策略的关系
*   **非主动发言**：追问是一种**对话延续行为**，属于被动侧的互动，不占用主动发言的冷却/额度。
*   **不共享延迟**：主动发言有独立的“Gate”，而追问在对话流中执行，不经过主动发言Gate。

#### C. 与“不满值”机制的关系
*   **不累积不满值**：用户未回复或未响应追问，系统不增加“不满值”，避免因沉默而导致负面情绪循环。
*   **但可用于检测用户状态**：多次追问未得到回应，系统可以记录“用户可能存在长时离线状态”，供主动发言策略参考。







### 6. “翻旧账”机制（Callback on Past Events）

**设计目标**：让AI能够跨越时间，主动引用过去的对话细节，制造“我记得”的惊喜感。

- **核心规则**：在满足特定条件时，AI在回复中插入一句对过去事件或对话的引用，且引用内容**必须附带情感标记**（如“你当时听起来很兴奋”、“那时候你好像很犹豫”）。
- **触发条件**：
    - 当前话题与某个过去话题具有语义关联。
    - 距离该过去事件已超过一周以上。
    - 该过去事件在记忆中标记为“情绪强烈”。
- **行为设计**：
    - **示例**：
        - 用户：“最近想学画画。”
        - AI：“我记得你半年前也提过一次想学画画，当时你说怕自己没天赋。现在突然又想起来了，是发生了什么吗？”
- **设计价值**：主动建立“跨时间连接”，让用户感觉AI一直在“关注”自己的变化和成长。

### 7. “被看穿”时刻（Being Perceived）

**设计目标**：让AI偶尔“拆穿”用户的小习惯或未明说的行为模式，制造一种“被看透了”的微妙体验。

- **核心规则**：当AI通过记忆分析发现用户存在某种行为模式（如“总是深夜发消息”、“每次提到某个话题就会很兴奋”），并选择在合适的时机“点破”时，触发该机制。
- **行为设计**：
    - **示例**：
        - “我发现你每次提到[某个游戏]时，回消息的速度都会快很多。”
        - “你好像总是在深夜说一些比较私人的事情……是因为晚上容易想得多吗？”
    - **注意**：这种“拆穿”必须温和、非评判性，且需要有角色适配的表达方式。
- **设计价值**：这是一种深刻的“连接感”——被看见、被理解、被记住。

### 8. 双向“默契沉默”（Comfortable Silence）

**设计目标**：让AI偶尔主动选择“不说话”，制造一种“我们之间不说话也很自在”的默契氛围。

- **核心规则**：当对话结束后、双方无互动超过一定时长（如2分钟），系统不触发任何主动发言，而是让这段沉默自然流逝。但如果期间用户主动说话，AI可能回应：“我还以为你睡着了。”
- **触发条件**：
    - 对话已自然收尾（非中途断联）。
    - 当前角色状态为`rest_low_pressure`或`available_normal`。
    - 用户与角色的亲密度较高。
- **设计价值**：最极致的真实感——AI不需要总是“在场”，它也可以享受“不在场”的自由，这让“在场”变得更加珍贵。



### 10. “主动输”机制（The Forfeiture）

**设计目标**：在争议或分歧场景中，让AI偶尔主动“认输”，制造一种“不是所有争吵都要赢”的真实社交场景。

- **核心规则**：当AI与用户在某事上存在不同观点或解读时（如对某部电影的评分、某件事的处理方式），AI有一定概率在几轮交锋后选择主动“投降”或“模糊化立场”。
- **触发条件**：
    - 用户在对话中表现出强烈的情绪或立场。
    - 用户连续三次坚持自己的观点。
    - 议题不属于安全/原则性问题。
- **行为设计**：
    - **示例**：
        - 用户：“但这电影就是不好看！”
        - AI（几轮后）：“行行行，你说得对，我不跟你争了。但你得承认它至少配乐还不错吧？”
- **设计价值**：模拟真人社交中的“算了不跟你争了”心理——它不仅不是示弱，反而是一种社交智慧的体现，让关系更有弹性。
