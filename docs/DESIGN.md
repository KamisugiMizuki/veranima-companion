## 1. 项目定位

**桌宠 + QQ chatbot 双端**的 AI 陪伴应用。同一人格在两端的表现不同但同源：
- QQ 端：打字利落的文字朋友（IM 文字通道）
- 桌宠端：坐在旁边的语音伙伴（TTS 语音通道 + 屏幕感知）

核心目标：通过模拟真实人类的表现（认知限制 / 社交摩擦 / 时空锚定 / 表达瑕疵）增强用户的情感寄托程度。

**总设计哲学**：不追求更像 AI，追求更像「某个人」。
1. 能力有边界——「不会」和「会」同样构成真实感
2. 表达适媒介——同一意图在不同通道说出来的样子完全不同
3. 行动需翻译——Agent 执行任务的过程必须被人格化转译后才呈现给用户

## 2. 总体架构

**架构原则（2026-08 定案，后续所有模块实现必须遵守）**

第一层·结构约束（模块怎么切分）：
1. **分层单向依赖**：`adapters（通道/输入输出） → core（决策与协调） → memory/llm/tools（基础设施）`。禁止反向依赖，禁止跨层直调（如 adapter 直接碰 memory 的表结构）。
2. **模块边界（SRP）**：每个模块独立成篇，一个模块只有一个变化原因；只通过**明确定义的接口**（函数签名/协议/事件）交互，不共享内部状态；模块间的数据流转走「输入 → 处理 → 输出」的显式管道。例：需求翻译层只负责「模糊指令 → 结构化工单」，不直接调 API；人格化转译器只负责「状态码 → 角色口吻」，不决定何时发起对话。
3. **状态收敛**：可变状态（依恋度/耐心值/场景锁/打断计数）集中在 `core/state` 相关模块，其他模块只读或经接口更新，不各自持有副本。
4. **通道解耦（LoD）**：双端（QQ/桌宠）只依赖「语义核心层 + 通道接口」，互不知道对方存在；模块间只传递规范化数据对象（DTO），不读取对方内部状态。新增通道 = 新增一个 adapter，不触碰 core。
5. **可替换基础设施（DIP）**：LLM/embedding/记忆存储均为可替换实现（接口在前）；核心层依赖抽象接口而非具体实现。例：任务执行定义 `ITaskExecutor` 协议，桌面 Agent/本地 API/云端工具都是其插件，换实现不碰 core。

第二层·边界防御（模块间的「盔甲」）：
6. **开闭原则（OCP）**：新增主动发起机制、新增输出通道时，**不修改**核心决策引擎与表达渲染层的现有代码——通过新增配置/插件类实现。为加功能重写核心引擎的 if-else 即架构失败。
7. **接口隔离（ISP）**：不设计「万能能力接口」；能力拆为细粒度迷你接口/配置项（游戏评论/办公助理/情绪支持……），角色卡只声明自己用到的部分，防误调用、防 OOC。

第三层·演进纪律（项目的生命力）：
8. **YAGNI**：先跑通骨架再谈智能——五机制仲裁器先做优先级队列，不预建权重计算/训练管道；等真实数据积累再优化。
9. **KISS**：能用简单逻辑解决的不用复杂算法。任务/闲聊分流优先用关键词+正则规则表，规则覆盖不到的长尾才透传 LLM。
10. **组合优于继承**：角色卡 = 标准组件（性格/语气/能力/记忆偏好）组合而成，不做庞大基类+子类重写；换组件即可出新角色，不写新子类。

> 一句话：**好的架构不是为了防止出 bug，而是为了让你以后敢放心大胆地改代码。**

## 3.1 桌宠前端选型风险（技术栈中唯一未验证项）

MacroPhonic 的 Tauri 桌宠端**未调通**（当时卡在窗口行为/GPU flags/退出码处理，最终只交付了 TTS sidecar）。因此桌宠前端不能沿用「已验证」假设，M3 前需重新选型：

| 候选 | 优势 | 风险 |
| --- | --- | --- |
| Tauri v2 | 轻量（~10MB）、Rust 后端性能好、已有部分调试经验（虽然未通） | MacroPhonic 的前车之鉴：Windows 窗口/GPU 问题调试成本高 |
| Electron | 成熟、koodo-reader 本身就是 Electron（React 栈可复用） | 体积大（~100MB+）、内存占用高；桌宠常驻场景不理想 |
| WPF/.NET | Windows 原生、常驻轻量、屏幕感知 API 直接 | 技术栈与现有 Python/TS 生态割裂 |

**决策时点**：M2（通道适配层）完成、TTS sidecar 已验证后再定，不提前绑定。核心诉求：常驻轻量 + TTS 播放 + 截屏/窗口感知 + 与 Python 后端通信（HTTP/WS 均可）。

## 4. 模块设计

### 4.1 角色决策引擎

**职责**：判定输入是「闲聊」还是「任务指令」，分派后续流程。

- 维护「可转交任务类型清单」（可配置）：文档处理 / 信息检索 / 系统操作 / 自动化流程
- 匹配 → 任务管道（需求翻译层）；不匹配 → 闲聊管道（记忆 + 社交 + 表达）
- **复用**：object_design 无此模块，重写（小，关键词/规则匹配）

### 4.2 需求翻译层（暂缓，随外部 Agent 一起）

**职责**：模糊指令 → 结构化任务工单 → 桌面 Agent Prompt。

- 意图补完五维：目标澄清 / 来源路径 / 用户偏好注入 / 优先级约束 / 异常预案
- 信息不足主动追问（附带猜测建议）
- 工单协议 `TASK_TRANSFER_PROTOCOL`（YAML），发送后必须给「已安排」反馈
- **里程碑**：M4，独立系统

### 4.3 能力匹配层

**职责**：判定角色「能不能做」，触发「懂但不多」模式。

- 角色卡绑定 `capabilities`：`擅长` / `略知` / `完全不懂`
- 「懂但不多」话术库：好奇型 / 共情型 / 关联型 / 走神型（每角色 ≥3 种）
- **复用**：object_design 角色卡机制（CharacterCard），扩展 capabilities 字段

### 4.4 记忆调度器

**职责**：五层记忆 + 模糊检索 + 断片机制。

- 五层：短期缓存 / 情境记忆 / 长期语义 / 关系记忆 / 事件记忆
- 确信度分级：>90% 斩钉截铁；60% 附「如果我没记错」；<40% 主动反问
- 断片机制：长对话后段允许「话到嘴边想不起来」并坦然承认
- **复用**：object_design 的 memory/store.py + embedding.py（strength/confidence 已存在），补断片与确信度措辞注入

### 4.5 社交博弈引擎

**职责**：耐心余额 + 互惠原则 + 打断逻辑。

- 情绪资本账户：深度共情消耗，低于阈值触发「节能模式」（回应变短/委婉拒绝）
- 关系亲密度：影响亲昵表达开放度（波浪号/称呼/调侃阈值）
- 互惠原则：频繁索取不分享 → 主动索取信息
- 打断逻辑：同一话题重复抱怨超阈值 → 切「解决问题模式」
- **复用**：object_design 的 state.py（attachment 已有），补 patience 账户 + 打断计数器

### 4.6 视觉注意力调度器（桌宠端核心）

**职责**：极低成本「AI 在看着你」的感知。

- 兴趣锚点（1~3 个）：游戏血条/小地图/对话框；办公光标/地址栏/通知区
- 三态切换：稳定期（30s 低频小截图）→ 触发期（显著变化高频+扩窗）→ 游离期（2min 无变化低分辨率全屏扫描）
- 注意力惯性：3~5min 随机瞥一眼周边
- 分级管线 L0-L3：系统 API 文本状态 → 事件驱动截图 → 本地小模型筛选 → 云端/本地大模型理解
- **复用**：object_design 无此模块，重写；依赖多模态模型（已有）+ 桌面截屏能力（Tauri/Python 均可）

### 4.7 时空沉浸引擎 + 主动发起机制

**职责**：共同时钟 + 场景状态锁 + 后台心跳 + 内部动机驱动的主动发起。

- 场景状态锁：用户说「在看电影/写稿」→ 主动慢回、短回，场景结束再深聊
- 后台心跳：非对话时「离线成长」（整理聊天记录/读书），下次破冰素材；主动对话核心调度器
- **复用**：object_design 的 proactive.py（GreetingScheduler/OfflineThinkTimer）改造为场景状态驱动

**主动发起机制**（五种内部动机，替代「定时闹钟」式的生硬触发）：

| 机制 | 人性逻辑 | 触发条件 | 示例 |
| --- | --- | --- | --- |
| 联想式 | 触景生情 | 视觉锚点捕获的屏幕元素 × 事件记忆层模糊匹配（强/弱关联） | 「咦？你又开这个了？上次卡了三天的 BOSS 过了吗？」 |
| 社交疲劳 | 憋不住了 | 社交博弈引擎：倾诉量/索取量 vs 表达量比值超阈值，表达欲积压到临界 | 「等一下我得插句嘴，你说了这么多，我也有个巨离谱的遭遇憋半天了」 |
| 闲适性 | 没话找话 | 视觉稳定期 + 距上次发起超静默期 | 「好安静啊，你在干嘛呢？」（不求结果，只求在场感） |
| 时间仪式化 | 共同计时 | 时间线模块：相识满月/连续互动 N 天/第一次任务等里程碑 | 「今天是咱俩认识整整三个月的日子」 |
| 认知冲突 | 看不明白了 | 屏幕内容与用户历史行为画像冲突 / 低效重复操作 | 「嗯？你怎么突然用起这个了？上次你还骂它难用来着」 |

**发起仲裁器**：五机制并行产生请求，汇入仲裁器统一裁决：
- 打扰系数评估（场景白名单：全屏游戏战斗中/视频会议/全屏放映 → 禁止发起）
- 优先级：冲突类 > 仪式类 > 联想类 > 疲劳类 > 闲适类
- 近期发起频率限制（防刷屏）
- 连续失败抑制：连续 2 次被无视/打断 → 冷却期，时长随失败次数指数增长（模拟「热脸贴冷屁股后的识趣」）

**实现分期**：
- M0/M1：时间仪式化（里程碑扩展 OccasionChecker）+ 社交疲劳（并入 patience 账户）+ 闲适性（扩模板池）——纯 QQ 端可做
- M4：联想式 / 认知冲突 / 场景白名单——依赖视觉注意力调度器

### 4.8 表达渲染层（双端地基）

**职责**：同一意图按通道渲染。语义核心层 → 通道适配路由器 → 通道渲染器。

**核心原则：表达风格挂在输出通道上，不挂在角色卡上**——同一人格在不同媒介呈现不同质感：
QQ 里是「打字利落但有温度的朋友」，桌宠里是「坐在旁边絮絮叨叨的伙伴」。
真实感不是统一风格，而是「对话形态」与「媒介生态」的共振；在文字框里加「嗯…那个…」像演话剧，在语音里用书面语像 AI 念报告。

**IM 文字通道（QQ）**（模拟「正在打字的人」）：
- 去口语填充词（那个/就是/嗯…）；标点即情绪（句号=平静/问号=好奇/省略号=犹豫）；感叹号每段最多一次；波浪号需亲密度阈值
- 分段即呼吸：长文本拆短句+换行，模拟「打一句、想一下、再打一句」；禁止连续换行模拟「正在输入」（那是系统层的事）
- 表情符号克制植入：按性格卡设频率上限——高冷型几乎不用；温柔型每 3-5 句可带一个温和表情；活泼型可玩组合梗，但不替代文字

**TTS 语音通道（桌宠）**（模拟「正在你身边说话的人」）：
- 植入口语填充词（嗯…/那个…/怎么说呢）做呼吸感——「边想边说」的外显
- 重复与自我修正（「我昨天去了那个……哦不对，是前天」）——语音里自然，文字里累赘
- 语速标签（`<加快>`/`<低声>`/`<拖长音>`）+ `[pause=0.5s]` 停顿即留白；兴奋快+高、沮丧慢+低
- 非语义发声：允许纯语气词（嗯—/啊？/啧…）

**亲密度阈值差异化**：同一表达在不同通道的开放度不同——波浪号需文字通道关系分 >80；语音通道的语气软化可更早触发（声音比文字更能承载亲昵）。

- **复用**：object_design 的 adapters/qq.py 消息流，新增通道抽象层

### 4.9 表达瑕疵层（通道绑定）

**职责**：输出前过「粗糙化滤镜」。**瑕疵类型必须绑定通道**——脱离媒介的瑕疵会出戏：
- IM 通道：文字版瑕疵——撤回（「不对不对，我重说」）、错字/改口、口癖植入（角色卡绑定）；不做填充词（那是 TTS 专属）
- TTS 通道：语音版瑕疵——嘴瓢/重复/语法紊乱（情绪传染）、填充词（「那个…怎么说呢」）；声音里的自然，文字里的噪声
- 低配实现：随机替换 1~2% 词 / 随机插入撤回括号（按通道选瑕疵池）
- **实现方式**：prompt 级引导为主（LLM 生成时直接带该通道允许的瑕疵），规则后处理为辅（撤回收尾）

### 4.10 人格化转译器（随需求翻译层）

**职责**：Agent 状态回传 → 角色口吻。`PROGRESS: 40%` →「那家伙手速还行，干了一半了」。

## 7. 安全边界（沿用 object_design 定案）

- **保留红线**：不参与现实社交（约定见面/寄送/代为联系）、不声称参与现实活动、不编造可证伪精确事实、不助长伤害
- **身份拟真放开**：默认自认 AI 但不主动强调；允许虚构个人经历；身份追问前两次带过第三次承认（纯 prompt）
- **表达放开**：允许问句/动作描写/轻度粗口/暧昧直白（角色卡 initial_affection 承载）
- **初始依恋度 0.5**（亲密期门槛起步）
- **项目层零内容过滤**（uncensored 本地模型，不做额外拦截）
