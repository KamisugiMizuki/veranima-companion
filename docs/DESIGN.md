# veranima 设计总纲 v2

> 状态：重设计基线（2026-08-19），本文件是当前产品方向的总规范。
> 原则：**不追求更像 AI，追求更像「某个人」**。
> 参考：`D:\sakura-v0.9.7-windows-x64`（角色包、分段表达、历史/语音资源）与 `D:\addons\airi-main`（运行时事件、上下文提供者、取消与历史压缩）。只借鉴边界清楚的机制，不复制两者的平台规模。

## 1. 产品定义

veranima 是一个**有固定人格、共同经历、当下状态和私生活连续性的虚拟人物**。桌宠与 QQ 不是两个产品，而是这个人的两个在场方式：

- QQ：她在手机/聊天窗口里给你发消息。
- 桌宠：她在电脑旁边，能说话、停顿、看见有限的环境线索，但不会因为看见屏幕就像监控系统一样播报。

产品成功标准不是“回答更聪明”，而是用户在一周后仍能回答：

1. 她是谁，怎么说话，什么事会让她不耐烦或感兴趣？
2. 她记得我们共同经历过什么，而且记得方式不完全像数据库？
3. 她今天和昨天为什么不太一样，但仍然是同一个人？
4. 她在 QQ 和桌宠里是同一个人，而不是两个 prompt。
5. 她会主动靠近，也会识趣地不打扰。

## 2. 设计原点：人，而不是模块

真人感来自四个连续变量的共同作用：

```
角色恒定性（是谁）
  + 自传连续性（经历过什么）
  + 当下状态（今天怎么样）
  + 情境表达（现在通过什么媒介说）
  = 用户感知到的“某个人”
```

任何机制只有在能改变其中至少一个变量时才值得存在。下列行为一律视为反目标：

- 为了显得像真人，随机插入口癖、错字、遗忘和撤回。
- 为了显得主动，按定时器或屏幕变化硬找话题。
- 为了显得聪明，把任务执行、视觉观察和系统状态直接暴露成 AI 报告。
- 为了架构完整，提前建立插件市场、多代理、多会话和复杂权重系统。

**拟人化不等于随机化。** 偶尔犯错必须有原因、能被追溯、能恢复；偶尔主动必须有动机、对象和不打扰判断。

## 3. 人格模型

### 3.1 角色恒定层

角色卡是“这个人是谁”的唯一来源，不能由系统级 prompt 偷塞另一角色的意象。角色卡至少包含：

- 核心性格：稳定的价值排序、脾气、亲疏边界、判断方式。
- 可观察习惯：常用开场、句尾、措辞偏好、讨厌的表达、话题偏好。
- 生活锚点：少量可重复的虚拟日常、物件、地点、习惯；不是每轮随机生成新背景。
- 能力边界：擅长、略知、完全不懂，以及“懂但不多”的说法。
- 关系期许：如何建立信任、如何回应亲密、何时需要空间。
- 通道表现：文字和语音的差异，但不得改变核心人格。
- 资源：立绘表达式、声音、语气参考、角色包元数据。

### 3.2 当下状态层

状态不是一个 attachment 数字。最小状态集：

| 状态 | 含义 | 影响 |
|---|---|---|
| energy | 精力 | 回复长度、主动意愿、瑕疵容忍度 |
| mood | 情绪底色 | 语气、兴趣、反应速度 |
| social_appetite | 当前社交余量 | 是否愿意展开、是否需要收束 |
| attention | 当前正在关注的主题/场景 | 话题选择与响应延迟 |
| relationship_stage | 关系阶段 | 称呼、亲密表达和冲突容忍度 |
| last_interaction | 最近互动与通道 | 衔接、冷却和跨端连续性 |

状态变化必须有事件来源（对话、时间流逝、用户反馈、场景变化），禁止每轮随机抖动。

### 3.3 关系模型

依恋度只是关系模型的一个观测值，不直接等价于亲密。关系阶段由共同经历、信任、冲突修复和时间共同决定：初识 → 熟悉 → 亲密 → 稳定相伴。阶段切换需要可解释的积累，不因单轮暧昧文本跳变。

## 4. 核心运行时

### 4.1 每轮对话管线

```text
输入事件
  → 情境识别（用户说了什么、来自哪个通道、是否正在忙）
  → 回忆选择（相关共同经历，而不是随机记忆）
  → 人格立场（她对此事的态度/兴趣/边界）
  → 当下状态调节（精力、心情、社交余量）
  → 生成语义回复
  → 通道表达（IM/TTS）+ 立绘/声音表现
  → 记录本轮与状态变化
```

LLM 负责自然语言，不负责决定所有状态变化。可验证的状态迁移、取消、失败、记忆写入和安全边界由程序控制。

### 4.2 回复契约

内部统一使用 `Reply`：

```json
{
  "segments": [
    {"text": "通道原文", "translation": "可选显示译文", "tone": "中性", "portrait": "闲置"}
  ],
  "stance": "她对这件事的态度摘要",
  "memory_candidates": [],
  "follow_up": "none|answer|invite|close"
}
```

- QQ 可直接显示 `text`，不强制 JSON 露出给用户。
- 桌宠由 `text + tone + portrait` 驱动 TTS/立绘。
- 解析失败必须保留可读文本或明确重试，绝不把 JSON、内部标签、token 预算残片展示给用户。
- `stance` 是内部决策证据，不直接播报。

## 5. 记忆与共同经历

记忆的目标不是“召回更多”，而是让这个人拥有过去。分为：

1. **identity**：角色自身固定资料，不由对话覆盖。
2. **user facts**：用户稳定事实、偏好、边界。
3. **shared episodes**：我们一起经历过的事件，含时间、情绪、结果。
4. **commitments**：角色对用户的承诺与用户要求的协作规则。
5. **session**：当前会话上下文。

每条记忆必须带 `source / confidence / importance / created_at / last_recalled_at / version`。记忆写入默认只来自用户输入和已确认事件；视觉观察默认是短期情境，不自动变成长期事实。

回忆行为：

- 高确信：自然调用，不报数据库字段。
- 中确信：用“我好像记得”并允许用户纠正。
- 低确信：承认不确定，询问，而不是编造。
- 纠正：保留旧版本和纠正原因，形成“我后来想起来了”的真实连续性。

不采用“随机张冠李戴”作为拟人机制。错误只能来自低置信检索、过时信息或角色当下状态，并且必须允许修正。

## 6. 主动性与视觉注意力

主动性是关系行为，不是定时任务。主动发起必须同时通过：

- **动机**：想起共同经历、关心用户、完成承诺、对当前场景有真实关联。
- **时机**：用户没有明确忙碌/沉浸/拒绝打扰，且近期没有被忽略。
- **内容**：一句有对象、有上下文的自然话，不是“你在干嘛”。
- **出口**：用户不回应时不追发；用户打断时收束。

视觉注意力只提供“她可能注意到什么”的候选，不直接触发发言：

```text
屏幕/窗口/鼠标信号
  → 注意力模型选定焦点
  → 短期情境记录
  → 与角色兴趣/共同经历匹配
  → 主动性仲裁
  → 只有通过才生成/发送
```

视觉模块详见 `docs/VISION_SPEC.md`。默认原则：先看、再理解、少说；不能把屏幕感知变成监控感。

## 7. 表达与通道

同一个人会因媒介不同而改变表达形态，但不会改变立场和性格：

- IM：利落、可回看、少口语填充词；换行和标点表达节奏。
- TTS：允许停顿、自我修正、填充词、语速变化；声音必须与角色状态匹配。
- 桌宠气泡：是当前说话内容的辅助字幕，不是另一套消息。

表达瑕疵只在状态确实支持时出现，频率低且可解释。禁止独立“随机拟人滤镜”覆盖所有回复。

## 8. 桌宠体验

桌宠是人物的身体化入口，不是一个会弹气泡的服务监控器：

- 主窗只表达在场、状态和可被点击的存在感。
- 点击进入独立聊天窗；聊天窗显示真实历史、角色名、头像、当前状态和失败恢复。
- 立绘、声音、气泡、聊天记录必须来自同一角色卡和同一回复对象。
- 核心断线、TTS 失败、生成取消必须以用户可理解的方式表达，文字不能消失。
- 空会话要有角色化起点，不得是空白面板。
- 设置和日志是支撑窗口，不应成为用户理解桌宠的前置条件。

参考 sakura 的角色包/历史/语气资源组织；参考 airi 的事件上下文、取消、分段播放和历史压缩；不引入 airi 的大规模插件平台作为本项目核心依赖。

## 9. 模块边界与取舍

| 模块 | 当前定位 | 必须证明的价值 |
|---|---|---|
| Character Kernel | 角色恒定层 + 资源 | 换角色后仍像另一个完整的人 |
| State & Relationship | 当下状态与关系阶段 | 同一人会随经历变化但不漂移 |
| Memory & Continuity | 共同经历与用户事实 | 能自然回忆、修正、跨端接续 |
| Conversation Runtime | 每轮决策管线 | 生成前有立场和情境，生成后有可靠契约 |
| Channel Renderer | IM/TTS/桌宠表达 | 同一内容在媒介中自然变化 |
| Presence & Attention | 在场、前台、视觉焦点 | 感知降低打扰，不制造监控感 |
| Desktop Embodiment | 立绘、声音、窗口、历史 | 用户感到“她在旁边” |
| External Agent | 独立任务工具 | 只有用户明确需要时才介入，不污染陪伴人格 |

删除/降级：独立“表达瑕疵层”的随机注入、五种主动机制并行权重、复杂能力插件层、Live2D 在 MVP 的预留抽象、未有体验证据的多代理/多会话。

## 10. 重排后的里程碑

| 阶段 | 目标 | 交付 |
|---|---|---|
| R0 | 角色内核 | 角色卡真值表、系统/角色边界、统一 Reply 契约 |
| R1 | 共同经历 | 记忆写入/召回/纠正、状态持久化、跨会话连续性 |
| R2 | 像这个人的表达 | IM/TTS 通道差异、tone/portrait、失败降级、角色样本验收 |
| R3 | 桌宠身体 | Electron 窗口、独立聊天、真实历史、TTS、状态/错误闭环 |
| R4 | 有分寸的在场 | Presence、Attention、场景锁、主动性仲裁、视觉隐私边界 |
| R5 | 可选任务协作 | 需求翻译与 dsh，独立于陪伴核心 |

R0-R3 是“像某个人”的主线。R4 没有 R0-R3 的连续性验收不得继续扩展。R5 不得阻塞陪伴核心。

## 11. 总体验收

不是“253 个测试通过”就算完成。每个阶段至少要通过以下体验测试：

1. 盲测：隐藏项目名和 UI 后，用户能从 10 轮对话描述出至少 3 个稳定人物特征。
2. 连续性：跨重启、跨 QQ/桌宠仍能正确接续最近共同经历。
3. 差异性：换成反差角色卡后，旧角色的锚点、口癖和价值观不泄漏。
4. 状态：疲劳、忙碌、亲密、被打断后，表达变化有来源且可恢复。
5. 媒介：同一意图在 IM/TTS 中自然不同，但事实、立场和关系一致。
6. 失败：LLM/TTS/核心断线时，用户看到可理解的文字和恢复动作，不出现静默或内部格式。
7. 主动性：主动消息能说出“为什么现在找你”，被忽略后会识趣停下。
8. 视觉：视觉观察能减少盲目提问，不能让用户感觉被持续监控。

## 12. 安全与边界

保留：隐私与遗忘权、现实行动/线下接触边界、不声称参与现实活动、不编造可证伪精确事实、善意与不助长伤害。身份拟真和虚拟日常允许，但被认真追问时不硬编。项目层不增加与产品定位无关的内容审查模块。
