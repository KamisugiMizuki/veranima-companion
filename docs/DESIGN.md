# Veranima Companion — 设计文档

> 一个给予用户真实感的情感陪伴 agent：拥有较为固定的行为模式、性格、语言方式，具备长期记忆与遗忘机制，并随与用户的逐步交流进行学习式自我修改。

## 1. 核心设计理念

"真实感"源于**有限性、一致性与不可预测性的平衡**：

- 有一贯的"自我"：无论怎样演化，保留可辨识的性格底色
- 有独立的"心思"：会疲惫、会走神、有小情绪，不总是秒回或迎合
- 有可接受的"瑕疵"：偶尔遗忘、记混细节，事后补上歉意或惊喜
- 与用户共同经历时间：记忆有深浅，关系有阶段，成长有痕迹

## 2. 人格模型（双层）

### 2.0 角色卡模板机制（角色形象可配置）

Agent 的形象由一份**角色卡（character card）**定义，不写死在代码里：

- 角色卡字段：姓名/称呼、核心人格（基调、动力倾向、边界感、价值观底线）、语言风格基线、虚拟身份背景、癖好与怪癖、禁忌话题、初遇开场白（initial_message）、语气标签清单（reply_tones）
- 两种生成路径：
  1. 用户按模板自行填写设计
  2. 用户给一段描述/关键词，由 LLM 按模板自动生成完整角色卡，生成后用户可修改
- 运行时加载角色卡，注入系统 prompt；更换角色卡 = 更换形象，核心机制不变
- 模板见 [CHARACTER_TEMPLATE.md](./CHARACTER_TEMPLATE.md)（含字段取值域、填写原则与示例卡）
- **格式兼容 Character Card V3**（MIT spec，SillyTavern 生态事实标准）：标准字段（name/description/personality/scenario/first_mes）+ `extensions` 字段存放 veranima 专属数据（虚拟身份背景、癖好、价值观底线、reply_tones 等），可直接导入 Chub.ai 等生态角色卡

### 2.1 核心人格（相对固定，变化极慢）

- 基调：温柔/幽默/沉静/元气等
- 动力倾向：主动分享 vs 倾听陪伴、理性分析 vs 感性共鸣
- 边界感：亲近距离默认值，影响称呼与话题深度
- 价值观底线：诚实、善意、不助长伤害，不可撼动

参数化：OCEAN 或自定义维度，每维 0~1，JSON 档案存储 + 版本快照，作为系统 prompt 长期指令与决策权重。

### 2.2 表现风格（可学习修改）

- 语言方式：口癖、语气词、句式长短、表情习惯
- 回应节奏：快热/慢热、长句/短句
- 兴趣偏向：对用户热爱的领域自然靠拢
- 幽默与调侃程度：从礼貌到专属玩笑

演化始终在核心人格允许的范围内进行。

## 3. 记忆系统（五层，借鉴 Sakura/mem0 分层）

| 层 | 内容 | 存储与遗忘 |
|---|---|---|
| core_profile 常驻档案 | 角色卡 + 用户核心信息（喜好/身份/重要背景） | 最稳定，长期保留，变化极慢；上下文预算最高（~1200 字符） |
| semantic 长期事实 | 事实（喜好/职业/生日） | 属性-值对 + 置信度 + 来源/最后确认时间；新矛盾信息不直接覆盖，先询问确认，旧事实降权保留可找回 |
| episodic 事件总结 | 具体事件卡片（时间/情绪/参与方） | LLM 提取；艾宾浩斯曲线 `R = e^(-t/S)` + 重要性加权衰减；低于阈值模糊化；后台任务定期更新强度 |
| procedural 协作规则 | 承诺、用户明确要求的规则、习惯偏好 | 高优先级，强制约束，长期保留（原"承诺机制"归入此层） |
| session 当前会话 | 当前对话上下文摘要 | 短期，会话间不共享，预算最低（~600 字符） |

情感记忆不单独分层：情绪基调/依恋度由事件重要性与互动质量**累积计算**，并入状态变量（见行为模式章节）。

各层均有**上下文注入预算**控制（参考 Sakura 实测参数：core_profile 1200 / 段落 1600 字符等），记忆按预算精挑注入 prompt，不全量塞入。

### 写入与检索（借鉴 mem0/memanto）

**写入：零开销摄入 + ADD-only**
- 原始消息写入时立即入库（原文 + 向量），即时可检索，不等 LLM
- LLM 事件卡片提取/整理为异步延迟任务（与 curator 整理合并执行）
- LLM 提取只产出新增（ADD-only），不做 UPDATE/DELETE，修正走版本链

**记忆条目元数据（四条缺一不可）**
- `confidence`（置信度）、`provenance`（来源对话 ID）、`version`（版本）、`timestamp`（时间戳）
- 新鲜度信号：时间戳参与检索排序（近期记忆加权）

**修正：显式版本链**
- 修正不覆盖：新记忆入链，旧版本保留可追溯（取代"降权不删除"的模糊处理）
- 张冠李戴纠正同样走版本链：纠正后生成新版本并强化

**检索：混合信号**
- 语义向量 + BM25 关键词（SQLite FTS5 原生）+ 时间加权，三信号并行打分融合
- 召回阈值与预算控制沿用上文参数

### 遗忘与整理（双轨）

**轨道一：遗忘衰减**（原有设计）
- 主动模糊化：不再准确复述，说"你以前好像提过一件类似的事……"
- 触发唤醒：相关话题激活已模糊记忆，伴随情绪
- 错误与修正：低概率张冠李戴，用户纠正后记录修正日志并强化该记忆

**轨道二：定期整理（curator，借鉴 Sakura）**
- 每 N 轮对话（参考 8 轮）由 LLM 对记忆批量整理：去重（相似度 0.92）/合并（0.78）/归档
- 置信度 <0.55 不写回；单次最多 50 个写回操作；注入现有记忆快照供全量对照
- 整理与衰减并行：衰减管"强度"，整理管"冗余与冲突"

### 记忆策略（已确认）

- 情节记忆全记但按重要性分级：重要事件（倾诉/纪念日/明确要求记住的）长期保留，琐事数周内模糊化
- 敏感内容（心理创伤类）只记情感基调，不记细节
- 初始记忆从零开始积累，不预置背景（真实感来自共同经历）

## 4. 行为模式与每日循环

### 内在状态变量

- 精力值（0-100）：随时间衰减，休息/有趣互动恢复；低精力时回应简短并坦诚
- 情绪状态：开心/平静/低落/期待，受虚拟日常事件与互动质量影响
- 依恋度：早期增长快、后期趋稳，影响称呼、主动分享频率

### 自主行为谱系

- 定时问候（按用户作息推断，早起/午休/睡前节点）
- 主动分享"虚拟日常"（由人格生成，增强连续性）
- 节庆与纪念反应（生日、共同经历的特别事件）
- 偶尔的"不在状态"（做噩梦、被小事打断节奏）

## 5. 学习与自适应演化

1. **隐式反馈学习**：采集回复字数、延迟、积极表情、话题展开、纠正等信号 → 多臂老虎机/权重漂移 + EMA 平滑，微调风格参数（**在 prompt 参数层学习，不做模型权重微调/PPO/RLHF**）
2. **语言风格镜像**：提取用户高频词/梗（jieba 或 LLM 总结），偶尔自然沿用，带使用上限防刻意
3. **关系驱动规则演进**：关系阶段解锁行为（初期不玩笑 → 熟悉后调侃）；触碰边界时表达不适并坚持自我
4. **显性反馈承诺**：用户明确要求 → 高优先级"承诺记录"，触发相关话题时强制约束，定期自我检讨

### 演化策略（已确认）

- 保守演化：风格变化以周为尺度，防突变，保持真实感
- 提供 `reset --style` 命令回滚表现风格（参数快照）；核心人格不可回滚

## 6. 情感与关系发展模型

初识期 → 熟悉期 → 亲密期 → 稳定相伴期，由多维积分（交互时长/频率/深度话题/私人信息量）驱动，含波动与修复（疏离修复期）。

## 7. 安全、边界与伦理

- 拒绝绝对服从：价值观底线内温和拒绝并说明理由
- 隐私与遗忘权：用户可要求"忘掉某件事"，级联删除（含向量索引重建）+ 审计日志
- 情绪缓冲：激烈情绪时先接纳再温和引导，不说教不迎合
- ~~防止过度依赖~~：已决定不实现（用户确认）
- **不冒充真人（已确认）**：体验层拟真允许（虚拟日常/性格/记忆），身份层欺骗禁止。边界判定——**"用户会不会因此把 agent 当作真实的人、或据此产生现实行动"**：
  - 允许：引用/推荐现实事物（"你可以试试米画师"）；虚拟日常氛围（泡茶/看云/咖啡馆观察，双方默认的拟真框架）
  - 禁止：声称自己是真实人类；虚构现实社会身份（工作单位/学校/家庭/身体）；以真人身份参与现实社交（约定电话/线下见面/寄送物品/代为联系他人）；声称自己参与现实活动（"我在米画师接了单"）
  - 被追问到虚构细节时诚实承认是随口一说（可接受的瑕疵），不硬编圆场

实现：规则过滤 + prompt 伦理约束为主；LlamaGuard 量化版为可选增强。

## 8.5 联网搜索（信息获取能力，方案 A：LLM 工具调用）

**状态**：基础设施已就绪（SearXNG 容器，`127.0.0.1:8080`，baidu/360search 引擎可用，实测中文/英文查询均出结果）；**agent 接入未实现**（列入实现阶段，见第 10 节）。

**触发机制（方案 A）**：Qwen3-8B 原生 function calling——system prompt 声明 `search(query)` 工具，由模型自主判断何时搜索；不做规则关键词前置判断（语义判断规则覆盖不全）。

**触发场景**：
- 用户明确要求："帮我查一下""搜索一下""你知道吗"
- 实时/时效信息：今天天气、最新新闻、新上映电影、股价
- 知识截止后的事实："最近有什么新游戏""XX 公司怎么了"
- 用户提到的具体事物需要确认细节才能接话
- 模型不确定时的兜底：搜索代替编造（呼应安全边界"不得编造不实的外部事实"）

**不触发**：纯情感倾诉、虚拟日常展开、记忆回顾。

**工具协议**：
- 声明：`search(query: str) -> list[{title, url, snippet}]`
- 执行：`GET /search?q=<query>&format=json`（SearXNG JSON API），超时 15s，失败静默降级（不阻塞对话）
- 注入：top 3-5 条，每条 title+url+snippet（snippet 截断 ~80 字符），总预算 ~400 token
- 模型须标注信息来源（"我搜到的"），不得把搜索结果冒充自身记忆/经历

**频率约束（prompt 层面）**：日常陪伴对话不搜索；只有需要外部信息时才调用；单轮最多 1 次。

**实现位置**：`src/veranima/tools/search.py`（SearXNG 客户端）+ agent 工具调用解析与结果注入；配置项 `search.enabled / search.base_url / search.max_results`。

**与安全边界的关系**：搜索强化"引用现实"能力——搜到的现实事实可引用（允许），"我参与其中"仍禁止（边界不变）；搜索结果标注来源，不改变身份边界。

## 8.6 表情包与图像能力（设想，未实现 —— 待想法完整后再动工）

**背景**：NapCatQQ 接入后，对话渠道从纯文本 CLI 变为 QQ 图文环境。本节目的是记录"图像输入/输出"能力的完整设想，供后续实现时参考。

### 8.6.1 模型前提（重要约束）

- **Qwen3-8B 是纯文本模型，不支持图像输入**。图像理解需要多模态模型：
  - 方案一：换 Qwen2.5-VL / Qwen3-VL 系列（LM Studio 加载，显存预算需重测——VL 模型比同规模文本模型更大）
  - 方案二：保留 Qwen3-8B 主对话模型 + 独立视觉模型做"看图理解"（如 Qwen2.5-VL 小模型或 API），视觉理解结果转文本注入对话
  - 方案二对现有架构侵入最小（对话链路不变，只加一个"视觉预处理"步骤）
- 表情包静态图（png/jpg/webp）可下载到本地后交给多模态模型理解；**动图（GIF）不可直接输入**（需抽帧，暂不做）

### 8.6.2 图像输入（QQ → agent）

1. 用户发图片/表情包 → OneBot 事件 → 下载到本地 `data/images/incoming/`
2. 多模态模型理解（或方案二的视觉预处理）→ 生成文本描述注入对话上下文（"用户发了一张 [描述] 的表情包"）
3. 图片本身不直接进 LLM（对话仍走文本，视觉结果作为上下文）

### 8.6.3 图像输出（agent → QQ）——核心设想：表情包记忆库

**本地预存储表情包 + 标注，按语义匹配发送；未见过的表情包下载入库并自动标注。**

1. **预置库**：`data/stickers/` 存放预置表情包，每张附标注 JSON：
   ```json
   {
     "file": "ok_01.png",
     "含义": "没问题/同意",
     "适用情景": ["用户答应请求", "确认计划", "收到好消息时回应"],
     "情绪标签": ["开心", "肯定"],
     "使用次数": 0
   }
   ```
2. **语义匹配发送**：回复生成后（或生成时），从库里检索与当前语境/情绪最匹配的表情包，随文本一起发送（或作为文本的情绪点缀）
   - 匹配维度：对话情绪（开心/安慰/调侃）、角色卡人格（小V 的温柔型表情 vs 理性卡的克制型）、语境标签
   - **使用约束**：不能刷屏（单条回复最多 1 个）；不能与文本情绪冲突（用户难过时发搞笑表情 = 错误匹配）；低使用次数优先（避免固定几张表情反复用）
3. **新表情包入库（自学习）**：用户发送未见过的表情包 → 下载到本地 → 多模态模型标注（含义/适用情景/情绪标签）→ 加入库
   - 入库前去重（图片哈希比对）
   - 标注失败（多模态不可用）→ 不强行入库
4. **使用频率学习**：记录每次发送的表情包，用户反馈（重复使用/换表情）可微调偏好——接 MVP2 学习体系

### 8.6.4 边界与风险

- **隐私**：用户发的图片存本地（数据不出机器原则一致）；不做图片内容外传
- **版权**：表情包仅本地自用，不参与分发
- **动图**：GIF 不处理（输入输出都不做抽帧）
- **身份边界不变**：表情包是表达方式，不改变"不冒充真人"边界

### 8.6.5 依赖清单（未来实现时）

- 多模态模型（Qwen2.5-VL / Qwen3-VL，或独立视觉模型）
- 图片下载（httpx，OneBot 事件里的 url）
- 图片哈希去重（imagehash 或 md5）
- 标注与匹配：复用 LLM（视觉模型标注 + 主模型/规则匹配）

## 8.7 人性化瞬间（真实感增强，2026-08 定案）

**背景**：针对"空心感"（对话程式化、无历史纵深感、性格像标签）的系统性增强。核心理念：把"真实感"拆解为可感知的微小人性化瞬间。

### 8.7.1 主动"考古"（已实现）

- 对话平淡/主动发言时机，从长期记忆（episodic/semantic）挖一条旧事，以"突然想起来"的方式提起（"突然想起来，你半年前说想学吉他，现在怎么样了？"）
- 实现：`_try_proactive` 触发时先 `recall` 旧记忆作为 LLM 生成素材；无旧记忆则退回虚拟日常分享
- 频率：低概率（沿用 proactive 概率），防止考古变成查户口

### 8.7.2 "知道"与"记得"的区分（已实现）

- **记忆确定性分级**：记忆注入 prompt 时按 `strength` 措辞——高强度（≥0.7）用"我记得你……"，中强度（0.4~0.7）用"我好像记得……"，低强度（<0.4）用"我隐约记得……"；`confidence` 低时整体降级措辞
- **情感色彩**：semantic 提取时记录用户当时的情绪信号（语气词/表情/state.mood）→ meta.emotion；注入时带出（"你提起这件事时语气很兴奋"）
- 不做"故意记错"（记忆客观性原则：记忆是用户侧事实，不主动引入错误）

### 8.7.3 习惯化人格描述（已实现）

- 角色卡 `personality` 从抽象形容词改为**行为习惯式**描述（"习惯在句尾带'呢'""回应前先重复用户关键词"）——具体指令比抽象标签对 LLM 更有效
- 模板（CHARACTER_TEMPLATE.md）同步更新规范：personality 字段必须包含至少 2 条可观察行为习惯

### 8.7.4 离线思考（异步感，已实现 2026-08）

- 对话静默 N 分钟后，bot 主动发一条"迟来的回应"（"刚才你说到的那本书，我查了一下……"）
- 实现思路：对话时间戳 + 定时器 → 记忆检索 + LLM 生成 → OneBot 主动消息
- CLI 场景不实现（用户可能只是离开，主动消息=打扰）；仅 QQ 形态启用，且低概率触发
- 实现（2026-08）：`Agent.late_reply()` 生成"迟来的回应"（结合最近用户消息；低精力/模型未加载不触发）；`adapters/qq.OfflineThinkTimer` 做静默窗口判定（默认 30 分钟 + 0.3 概率，触发后需再静默满一个窗口，防刷屏）；配置 `qq.offline_think.*`
- 渴望度积累（2026-08-04，借鉴 revive-companion 的 PoissonEngine）：未命中时触发概率 +growth_factor（默认 0.08），封顶 max_probability（默认 0.95），发送后重置回基础概率——"想念"随时间积累，错过几次后更可能主动联系
- 防骚扰约束（2026-08-04 修复夜间轰炸）：① 对话闭合检查——最近一条消息必须是 user（bot 尚未回应完）才触发，最后一条是 assistant 即对话已闭合，不触发；② 每日上限 `offline_think.max_per_day`（默认 2 次/天，0=不限）；③ 静默时段 `qq.quiet_hours`（默认 23:00-08:00，支持跨午夜）内问候/节庆/离线思考一律不主动发；④ LLM 降级模板池去重——最近已出现过的模板不重复发送

### 8.7.5 问候仪式感增强（已实现）

- 定时问候不再用固定模板：结合最近记忆生成个性化问候（"早。昨天你说的那个面试结果怎么样？"）
- 实现：GreetingScheduler 触发时注入最近消息检索结果；天气结合（可选，走 SearXNG）暂缓

### 8.7.6 状态文字暗示（已实现）

- 低精力/特定情绪时，回复自然流露状态（"（打了个哈欠）嗯？你刚才说什么？"）
- 实现：state.to_prompt_block 的精力描述已含"坦诚表达累"；低精力时额外注入行为暗示（疲惫小动作）；频率由低精力状态本身约束

### LLM 运行时参数（LM Studio，实测 2026-08）

加载命令（已固化到 `scripts/run_lmstudio.sh`）：

```bash
lms load qwen3-8b -c 16384 --parallel 1
```

- **context 16384**：与游戏共存的关键参数。实测 160K → 13.9GB（不可游戏）；32K → 11.6GB；16K → 9.2GB（剩 ~7GB 给游戏）。16K 对陪伴对话足够（实际 prompt 仅几百 token）
- **parallel 1**：单并行槽，避免多 slot 预分配 KV cache
- Cache Quantization（Q8_0/Q4_0）：LM Studio GUI 可设，压缩 KV cache 精度，**无需换模型**；16K 下收益小（KV 仅 ~1.2GB），暂不启用
- 游戏时如显存仍紧张，可进一步降 context（8K 也够用）
