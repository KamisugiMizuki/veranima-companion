# 记忆模块 · 档位 A（一页心智模型）

> 目的：30 秒建立"记忆系统由什么组成"的整体图景，适合第一次接触或复习用。
> 结构矛盾自查点放在文末。

## 一句话

记忆 = **一张 SQLite 表（memories）+ 三种索引（FTS5 全文 / numpy 向量 / 普通列）+ 一个混合打分检索（recall）**。写入永远只追加（ADD-only），修正走版本链，遗忘靠衰减（decay）而非删除。

## 五层记忆

| 层 | 存什么 | 例子 |
|---|---|---|
| core_profile | 角色自我设定（衰减豁免） | "我是凛，女仆" |
| semantic | 关于用户的稳定事实 | "用户在做后端迁移" |
| episodic | 单次事件/情节 | "08-30 用户说睡了" |
| procedural | 学到的规矩/技能 | "用户讨厌被催" |
| session | 短期会话上下文 | 当前话题摘要 |

## 数据流（4 步）

```
用户消息 → agent.handle()
  ├─ 写：候选提取(LLM) → validate_candidate 校验 → store.add（带向量）
  ├─ 读：recall(query) = 0.45×向量 + 0.20×FTS + 0.15×新近 + 0.10×重要性 + 0.10×置信
  ├─ 注入：命中的记忆拼进 system prompt（预算封顶）
  └─ 维护：夜间 decay（强度衰减）、digest（情节→摘要）
```

## 结构矛盾自查点

1. **写入只有 ADD**：任何"更新记忆"的代码都应表现为 `update_latest` 开新版本，而不是 UPDATE 原行——看到直接 UPDATE memories.content 即为矛盾。
2. **三层索引各自独立**：memories / memories_fts / memory_embedding 三张表没有数据库级联约束，一致性靠代码维护（erase 三清）——任何只写一层的路径都是矛盾点。
3. **向量归一化在 blob 里**：float32 归一化存储，点积即余弦相似度——如果哪里出现"召回时再归一化"就是重复计算矛盾。
