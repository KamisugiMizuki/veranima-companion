# 伴侣连续性增强设计

> 状态：方案稿，尚未进入实现。
> 日期：2026-08-29
> 范围：关系连续性、共同经历、主动关怀、虚拟生活和 QQ/桌宠一致性。
>
> 本文是增量设计，不引入新数据库、新调度服务或第二套关系模型。所有生产实现必须先经用户确认，再按垂直切片落地。

## 1. 目标

Veranima 的伴侣感不靠更频繁地发消息，而靠同一个角色在时间中保持连续：

1. 她记得用户说过什么，并在合适时机回用，而不是只在用户追问时检索。
2. 她有自己的虚拟生活，但不会把日程播报伪装成真实经历。
3. 她会关心用户具体未完的事，能跟进、接受拒绝，并停止施压。
4. 共同经历能留下事实、双方解释和未决后续，关系变化有证据且可修复。
5. QQ 和桌宠是同一 Agent：事实、立场、关系状态一致，表达方式和主动额度按媒介分开。

非目标：自主现实行动、现实社交、无限背景意识流、云端画像、多人实时协作、用消息数量直接增加亲密度。

## 1.1 感受归因维度

每一个主动设计点、主动候选与关系变化都必须能归因到以下维度之一；归因不上的设计不进入实现（外部提案采纳项）：

| 维度 | 项目载体 |
|---|---|
| 被记住（细节具体度） | 五层记忆 + 确信度分级 + conversation_event 跟进 |
| 被想念（分离有重量） | OfflineThinkTimer 渴望积累 + time_factor |
| 被看见（注意到没说出口的部分） | care_signal：语气转冷、投入下降、沉默异常 |
| 被需要（双向索取） | 角色小索取、self-share、称呼回叫 |
| 专属感（只对我说的） | shared_meaning、内部梗、称呼演化、内部纪念日 |
| 不确定的心动（会意外） | 低频重事件、人格内分歧保留 |
| 持续在场（沉默也是陪伴） | 虚拟日程运行、低负担存在确认、静默权 |

"被优先感"不单列：单用户设定下优先级天然成立，不靠对比营造。

## 2. 当前真实实现

### 已实现且有生产消费者

| 能力 | 当前链路 | 状态 |
|---|---|---|
| 多维关系 | 用户信号/共同创作确认 → `RelationshipModel` → `PersonaBrief`/状态持久化 | 已接线 |
| 关系张力 | 用户消息/QQ 未回复 → `RelationalTension` → 通道化 prompt/一次修复机会 | 已接线 |
| 共同意义 | 用户消息 → `shared_meaning` 候选 → 校验/版本链 → PersonaBrief | 已接线，角色解释仍弱 |
| 承诺 | 用户明确要求 → procedural `commitment` → `PromiseBook` → prompt | 已接线，兑现入口有限 |
| 临时后续 | LLM `conversation_event` → topic 版本链 → QQ advisor | 已接线 |
| 主动关怀 | 记忆/临时事件/日程素材 → QQ readiness → Gate → LLM → 来源锚点校验 → 发送反馈 | 已接线 |
| 虚拟空间 | 日程 plan → activity/place/transition → Agent prompt、空间事件和地点问答 | 已接线，仍非完整生活自传 |
| 双端表达 | 同一 `Agent.handle()` → IM/TTS `Reply` → 各自 renderer/桌宠 WS | 已接线 |
| 自我模型 | 人格证据 → 反思 → `self_model_snapshot` 与章节表 | 已接线，但回顾消费有限 |

### 部分实现或断点

1. `RelationshipModel` 的 `shared_projects`、`recurring_rituals`、`open_relational_threads` 主要是状态字段，缺少稳定的统一回用入口。
2. `shared_meaning` 可以保存用户解释，但角色解释通常只在后续反思中生成，双方意义没有形成稳定的“事实→解释→后续行动”消费链。
3. `PromiseBook` 能记录和注入承诺，`mark_done()` 存在，但普通对话不会可靠地把“已完成”识别为兑现并回写。
4. `open_thread` 属于共同创作工作流，聊天回复和 QQ 主动性尚未统一消费全部未决线程。
5. `virtual_life_event`、DayCloseSummary、LifeTheme、EmotionalResidue 仍是日程规范中的部分实现，不应宣称已有完整角色自传。
6. QQ 主动性已有真实素材和来源校验，但默认素材选择仍偏“最近可用”，没有把关系线程、承诺、情绪余波作为同一排序输入。
7. 桌宠消费完整 Reply 和状态，但 QQ 主动通知与桌宠状态展示之间没有统一的“已知事实快照”；两端一致性目前主要依赖共享 Agent/SQLite，而非显式回顾协议。

## 3. 根因

当前不是缺少组件，而是缺少一个轻量的关系上下文编排步骤：

```text
用户消息 / 虚拟生活事件 / 共同项目事件
    → 各自写入已有 MemoryStore 或关系状态
    → 各自局部召回
    → prompt 或主动 Gate 分别消费
```

结果是：写入成功不等于回用；状态存在不等于本轮可见；主动素材有来源不等于有关系动机；角色自传存在不等于能在对话中自然讲出来。

要补的是编排，不是再造存储层。目标链路：

```text
证据事件
 → 关系上下文选择（事实/共同意义/承诺/线程/余波/虚拟生活）
 → 当前轮 ResponsePlan 或 ProactiveCandidate
 → 既有 prompt、Gate、renderer、反馈与版本链
```

## 4. 目标上下文

复用 `PersonaBrief`，增加有限的可选来源，不建立新的长期状态对象。每轮最多选择：

| 区域 | 来源 | 用途 |
|---|---|---|
| `active_thread` | open commitment、conversation_event、OpenThread | 当前真正未完的事 |
| `shared_reference` | shared_episode/shared_meaning、已确认共同项目节点 | 建立“我们之间”的具体互文 |
| `care_signal` | 用户状态、情绪事件、近期未闭问题 | 决定是否关心及语气 |
| `character_presence` | 已归档 virtual_life_event、当前日程活动 | 角色自身存在感 |
| `relationship_motion` | 关系阶段、张力 band、最近一次关系变化原因 | 约束亲密、修复和边界表达 |

选择规则：证据优先于推断；候选必须能归因到 §1.1 某个感受维度，归因不上的不进入 Gate；当前用户输入优先于主动素材；终结状态不进入主动候选；同一来源在一个 turn 内只消费一次；没有具体来源就不生成“我刚刚……”类自我叙述；新主动文本与最近已发主动消息做相似度拦截（沿用 `_text_similarity` 近似，≥0.6 不发），防止换词复读式的机械感。

`PersonaBrief` 只携带短摘要、来源 ID、状态和可用动作，不携带思维链，也不直接暴露内部 ID 给用户。

## 5. 四个垂直闭环

### C1：未完事项跟进

将已有 `commitment`、`conversation_event` 和 `OpenThread` 统一为“可跟进但不强迫”的输入：

```text
明确来源 → active_thread → 当前话题相关时优先回用
                         → 到期/完成/拒绝后停止主动
```

两项增强（外部提案"事件型/未完成型"采纳）：

1. **事件日期锚**：`conversation_event` 支持 `event_date`（考试/面试/体检/出差当天）。当天与次日产生高优先级 `check_in` 候选；事件日后优先级回落，仍走既有 1-7 天 `follow_up_days`。缺来源消息的日期候选不生成。
2. **话题中断恢复**：上次对话停在某个话题上（用户忙碌、失联、窗口关闭）记入既有未决线程；下次回归且在有效期内时，可以自然接上"刚才说到一半"。中断不产生愧疚式施压，禁止"你怎么不回我"。

完成识别必须来自用户明确表达或现有工作流状态，不由模型猜测。兑现后使用已有版本链，旧记录保留审计但不再注入普通 prompt。

### C2：共同意义与关系回用

共同事件至少区分：发生事实、用户解释、角色解释、共识或分歧、下一步。角色解释可以是候选，不能伪装成用户确认的共识。

回用动作只允许三种：自然提起、把旧意义应用到当前问题、保留双方分歧。每个共同意义设置回用冷却；普通闲聊不强行引用。

两项增强（外部提案「记忆浪漫化调用」采纳）：

1. **内部梗孵化**：对话中出现的双关、误读、共同经历产生的戏称，由 LLM 提取为 `relationship_internal_jokes` 候选（复用 pending→confirmed 生命周期），确认后才能在主动与日常对话中回用。梗的引用频率由冷却控制，禁止高频复用来刷专属感。
2. **称呼演化**：允许的称呼集合随关系档位与 anchor 事件在 PersonaBrief 中派生（配置驱动，不硬编码文案）；第一次改口视为一次锚点关系事件，由用户信号驱动，不由定时器触发。

### C3：有原因的主动关怀

复用 QQ 现有 advisor、Gate、反馈表和来源锚点。将候选排序改为：

```text
明确未完事项 > 用户明确情绪/状态后续 > 已确认共同事件 > 角色虚拟生活分享 > 低信息存在确认
```

候选必须能归因到一个主导动机维度和一个具体来源，发送文本仍只含自然用户文本。用户拒绝后关闭对应 gap/thread，不换成近似问题继续追问。回访优先级低于当前对话中的明确未完事项与情绪信号：用户正在聊别的时，不插入到期跟进；过期的 check_in 降权为普通素材，不补发道歉式追问。QQ 仍是唯一主要主动沟通端，桌宠不重复发送 QQ 通知。

三项增强（外部提案「动机建模/时机节奏/反馈闭环」采纳）：

1. **动机向量**：在既有 `AmbientState` 上扩展有限个有界标量（思念、分享欲、担心、不安、雀跃），各自有增长/衰减规则（思念随分离时长非线性累积并按末次互动情绪浓度加权；不安由未回复/张力驱动；担心由 care_signal 驱动）。多维同时超阈时按时序主导动机决定内容与语气，PersonaBrief 记录归因。安全感缺口不单列：由既有 `be_need` 通道（角色小索取）表达。
2. **静默权**：所有动机低于静默线时 Gate 显式输出 `no_reason` 顺延检查点；久别（跨过静默线阈值）回归前允许一条低成本存在确认（"我在，忙完再说"类，由风格派生），使静默可被感知为在意而非故障。
3. **被冷落姿态**：主动消息被持续冷落算一次轻量张力信号（不安值上升 + 降频），下一次收场走既有 tension 修复路径：优雅、不怨怼、不卑微、不装无事。另外高 emotional_weight 场景（安慰/道歉/承诺）必须零故障表达：不启用犹豫、中断、语气玩闹等不完美元素，风格钳制为稳定清晰。

### C4：角色自传与当前日常

复用 `virtual_life_events` 和已有日程状态。只有有来源的事件才允许角色分享；分享内容必须带 `truth_class=virtual_simulation` 的内部约束。用户主动询问时可以回顾，追问未保存细节时承认不知道。

先实现“最近一次日程事件可回顾 + 一次性来源校验”，暂不实现完整多日人生史、无限自发意识流或复杂主题图谱。

低气压日（外部提案「离屏生活」子项采纳）：角色状态允许出现短期低能量日（由 mood/energy 派生，不新增状态量）。行为边界：主动候选变少变短、只回不追、不向用户甩锅情绪、恢复由既有衰减规则驱动。低气压是角色存在感的一部分，不是故障，也不是博取关心的手段。

## 6. 多端一致性

共享的是语义，不是字符串：

- 事实、关系状态、共同事件、线程状态来自同一 Agent/MemoryStore。
- IM 生成短而清晰的文字；TTS 使用同一立场的分段语音协议；不能让一个通道独自改变关系状态。
- 主动额度、quiet hours、cooldown、发送反馈按通道独立。
- QQ 主动消息可在桌宠状态栏显示为“最近关系/活动已更新”，但不再次朗读或发送同一通知。
- 桌宠断线、QQ 发送失败和 LLM 失败都不能提交“已送达”或完成状态。
- 重启后从持久化状态恢复上下文；不能依赖某个进程内缓存证明两端一致。

## 7. 实施顺序

1. **C1 跟进编排**：在 `Agent` 的现有 `PersonaBrief`/主动候选入口中统一筛选 commitment、conversation_event、OpenThread 的当前状态；补兑现和终态排除。
2. **C2 共同意义回用**：补角色解释候选的证据和确认状态，接入一次有冷却的 ResponsePlan 回用。
3. **C3 关系驱动主动性**：调整 QQ advisor 的素材优先级，接入情绪余波和关系线程，但继续复用 Gate/反馈表。
4. **C4 自传回顾**：把已有 virtual-life event 的有限回顾接入 prompt 和 QQ self-share；明确虚拟性质和缺证据回退。
5. **C5 多端快照**：只补必要的只读状态快照/事件通知，不把业务状态复制到 Electron。

每个阶段先写一个端到端行为测试，再改最少的生产文件；每阶段单独全量测试和真实调用链验收。

## 8. 行为验收

### 连续性

- 用户说过的未完事项，在相关后续话题中最多自然跟进一次；完成、暂停或拒绝后不再主动追问。
- 用户久别回归后的第一条 assistant 消息能引用回归前唯一未决话题；用户已换话题时不强行引用。
- 多动机候选同时超阈时，PersonaBrief 能指出主导动机归因，回复语气与之相容。
- 被冷落后的收场不含怨怼或同义反复追问；高权重场景（安慰/道歉/承诺）回复无犹豫、中断、玩闹表达。
- 内部梗与称呼变更只在 pending→confirmed 后生效；同一梗的复用在冷却之外不出现。
- 同一共同事件能区分事实、用户解释、角色解释和分歧；角色不会把未确认解释说成共识。
- 关系状态跨重启保持，状态变化能指出原因；普通消息不会凭空增加关系维度。

### 主动关怀

- 候选能回到原始用户消息或虚拟事件；无来源不发。
- 用户明确说不要问/不要主动联系后，对应候选进入暂停，不惩罚关系，也不换同义问题绕过拒绝。
- QQ 成功发送才提交 feedback、cooldown 和“已发送”；桌宠不重复 QQ 主动通知。

### 角色存在感

- 角色能在有来源时回顾一项自己的虚拟日常；没有归档或细节时明确说不知道，不补写经历。
- 日程影响回复资源和语气，但不会成为敷衍认真问题的借口。
- 情绪余波会短期影响措辞/主动性，并按已有张力机制衰减和修复，不随机变坏。
- 低气压日：主动频率与长度下降、不甩锅用户；能量恢复后主动回到正常区间。

### 生产链和安全

- 至少验证：用户输入 → MemoryStore/关系状态 → `PersonaBrief` 或 `ProactiveCandidate` → prompt/QQ/桌宠 → 持久化/反馈。
- 真实远程验收至少连续 20 轮；检查可见文本、协议泄漏、消息落库、状态重启和终态过滤。
- 全量 `pytest`、`compileall`、`git diff --check` 通过；所有文档中的“已实现”必须有对应行为证据。

## 9. 暂缓

暂缓关系图谱、向量数据库迁移、后台独立意识流、自动生成现实任务、跨用户画像、完整多日自传编辑器和桌宠重复主动通知。只有现有 C1-C4 的行为验收证明信息选择仍不足，才考虑更复杂的检索或模型升级。
