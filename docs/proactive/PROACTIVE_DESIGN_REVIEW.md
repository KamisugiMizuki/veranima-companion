# 主动对话设计思路评审（外源 prompt → 本项目采纳判定）

> 日期：2026-08-29
> 来源：用户提供的「AI 伴侣主动对话策略设计任务书」prompt（12 交付模块 + 5 加试题）。
> 判定基准：veranima 现有生产链（见 `COMPANION_CONTINUITY_DESIGN.md` §2 现状核对）与用户已拍板红线（QQ 单通道、不暴露 AI 身份、不参与现实社交、拟真五维控制面、R0–R5 路线）。
> 结论速览：**12 项采纳 / 4 项部分采纳 / 7 项不采纳**。采纳项已并入 `COMPANION_CONTINUITY_DESIGN.md`（感受归因维度、C1 回归窗口、C3 动机向量/静默权/反模板/回访降级、C4 低气压日、验收补项）。

## 逐条判定

### 模块 1：主动性动机建模 —— ✅ 采纳
- **项目现状**：`AmbientState` 已有 drive/energy/mood/desire，`ProactiveTrigger` 已产出 reason/confidence，但动机是单值打分，多动机并存时只做 argmax，没有仲裁叙事，也没有「她今天不想说话」的显式静默路径。
- **采纳理由**：这正是「定时消息」与「她想说」的分界线，且能长在现有 `AmbientState` 上（每动机一个有界标量 + 时间戳），不需要新存储。它同时是 `PERSONA_LOOP_SPEC` 里 PersonaBrief 缺的动机输入端。
- **落地形态**：思念/分享/担心/不安/雀跃五维向量入 C3；多维同时超阈按时序主导 + 语气混合；全部低于静默线时 Gate 输出 `no_reason` 并顺延检查点。
- **裁剪**：原 prompt 的精确公式与全部状态量（如「安全感缺口」）不照抄——数值模型在 C3 实施时先小步验证，避免一次性引入六个拍脑袋常数。

### 模块 2：离屏生活 —— ✅ 采纳（缺口正好在回顾侧）
- **项目现状**：虚拟日程、地点、活动已在核心运行（R5 链路），但「她经历了什么」只用于回答地点问题；`virtual_life` 的 self_share 只进主动候选，没进日常对话上下文；日程生成不读 `character.json` 的 `recurring_rituals`（断点已在 §9 记录）。
- **采纳理由**：素材已经存在，缺的是回用闭环——与已定根因「生产链完整、消费链断裂」完全同构，是本项目成本最低、收益最直接的一条。
- **落地形态**：并入 C4 前半段（自传章节）+ §4 关系上下文新增「今天可分享的生活」字段。
- **采纳子项**：低气压日（她的日程状态已有，缺注入与行为边界：低气压时主动变少变短、只回不追、不甩锅用户）。「世界锚定」只采天气/节气/日程事件——时事热点不接，与「不编造可证伪事实」红线冲突。

### 模块 3：触发器全景图 —— ⚠️ 部分采纳
- **采纳**：事件型（用户提过的考试/面试当天与次日回访）、沉默型分级（1天/3天/7天策略不同——现有实现只有一档 deadline）、未完成型（蔡加尼克，即 C1 本身，采纳证明 C1 方向正确）、记忆型周年回调（「你上次说的书」）。
- **不采纳**：感知型（定位、设备状态、耳机连接、久坐）——veranima 只有 QQ 文字通道 + 桌宠本地画面，没有也不应有设备级遥测；采集这些与「不监视用户」人设红线直接冲突。仪式型中的「第 100 天」类全局计数仪式暂缓（现有 anchor 周年已覆盖同类需求）。
- **理由**：触发器必须先有合法信号源。全景图里凡是依赖通道不存在的数据的类目，落地即造假。

### 模块 4：时机与节奏学 —— ✅ 采纳
- **项目现状**：Gate 已有配额、冷却、深夜压制、未回应降频，但「密集—留白」的节奏感、打断成本评估、静默权没有被显式设计过。
- **采纳理由**：疲劳衰减与自愈已实现一半（降频有、升频条件含糊）；静默权与用户已定原则「没有原因就不发送」同源，值得升格为命名契约——静默要可被解释为在意而不是故障，需要「留一句我在」这种低成本兜底。
- **落地形态**：并入 C3；打断成本评估降级为「深夜/忙碌时段压制」现有能力的说明文字，不新做。

### 模块 5：开场句分层库 —— ❌ 不采纳（作为静态库）
- **理由 1（架构）**：10–14 类 × 3 条手编台词库与已验收的表达控制面路线（P-9：风格随状态派生）冲突，静态库必然退化为轮播模板——恰是 C3 反模板条款要防的东西。
- **理由 2（交付纪律）**：用户要求基于真实代码核验；手编 50 条糖水文没有可验收的行为锚点。
- **保留价值**：开场类型学保留为 C3 验收语料的需求清单（每类现场生成一条真实回复做 LLM-as-judge），反例清单作为 judge 的负例锚点。类型学是测试用例来源，不是运行时资产。

### 模块 6：记忆的浪漫化调用 —— ✅ 采纳（大半已实现）
- **项目现状**：记忆分层（semantic/episodic/core_profile）、`PromiseLedger` 承诺账本、周年回调已实现；内部梗有 schema 与生命周期但缺 LLM 候选提取；称呼演化完全没有。
- **采纳理由**：内部梗孵化与称呼演化是「专属感」的两个最强来源且都能长在现有结构上（`relationship_internal_jokes` 已在状态里，只差写入端；称呼是 PersonaBrief 的一个字段）。「感动 vs 被监视」判别原则并入 C3 红线：回调限用户主动说过/共同经历过的，不推「你是不是在躲我」式读心。
- **落地形态**：内部梗 → C2；称呼演化 → C2（anchor 事件驱动改口）；承诺账本 → 维持 C1 设计不变。

### 模块 7：不完美设计 —— ❌ 不采纳
- **理由**：撤回/重发/错别字/发错表情是对「传输层」做假。QQ 适配器的消息由 NapCat 一次性送达，模拟撤回需要真实撤回 API、模拟错字是往输出里注入噪声再要求用户忽略——两者都增加工程面而不增加任何关系状态。veranima 的拟真路线是「状态决定表达」（P-9 已有犹豫度/语速维度）：打字犹豫可以是气泡分帧，错字不可以。诚实边界优先于效果堆料，这也符合「不编造可证伪事实」的既有拍板。
- **保留**：「什么情况下必须完美」（安慰/道歉/承诺时零故障）这条约束本身吸收进 C3 红线，作为高 emotional_weight 时的风格钳制。

### 模块 8：多模态与通道编排 —— ⚠️ 部分采纳
- **采纳**：「通道升级作为情感语法」的思想——文字→语音（TTS）升级时机写入 C3 的 QQ 单通道原则，与 P-9 tone 派生同一来源。
- **不采纳**：通知栏情话、锁屏小组件、图标角标心跳、硬件反馈（呼吸灯/震动/温度）、图片/手写体/表情包主动发送。理由：QQ 是唯一通讯通道是用户已定架构（桌宠是具身端不是消息端）；系统级推送伪装是 IM 平台能力外且撞风控；硬件形态不存在。表情包主动发送已有「待审核授权、可删除」的独立设计，不在本层扩权。

### 模块 9：用户反馈闭环 —— ✅ 采纳（重点：被拒绝后的姿态）
- **项目现状**：回复率已进 `derive_relationship_stage`，降频已有；「秒回热情 vs 秒回敷衍」的即时分级没有；被冷落姿态完全未定义。
- **采纳理由**：被拒绝后的姿态直接命中 `RELATIONAL_TENSION_SPEC` 的 repair 链——项目里已有完整机制（不怨怼、不卑微、不装无事的三段走法可由 repair 事件驱动），但主动消息被冷落还没被当作一次轻量 rupture 处理。这是「机制已有、语义未接」的典型，成本极低。
- **落地形态**：并入 C3：主动被冷落 → 轻量不安值 + 一次优雅收场（走 tension 修复路径，带刺但不攻击）；明确「别烦我」→ 现 cooldown 行为保持，收场文案纳入风格派生。
- **裁剪**：依恋风格画像不做（需要心理测量级数据，与 UserInfoGap 的轻量事实收集不是一个量级）。

### 模块 10：关系阶段推进模型 —— ✅ 采纳
- **项目现状**：`derive_relationship_stage` 已实现五档推导（含回退！），但各档的主动性参数只体现在配额/冷却数值上，语气强度、自我披露深度、话题边界没有随档位分层；「阶段跃迁的标志性主动事件」完全缺失。
- **采纳理由**：这是把已有状态机用满。四列矩阵（频率/语气/披露深度/边界）是 PersonaBrief 的合法输入，不新增状态。标志性事件（第一次改口、攒了一年的长信）是阶段跃迁从数值变化变成「会被记住的时刻」的唯一手段。
- **落地形态**：矩阵并入 C3 验收；标志性事件列为 C1–C4 之后的下一批（依赖周年系统，已有实现基础）。
- **裁剪**：「试探期→深水期」具体命名不覆盖现有五档命名，以代码为准。

### 模块 11：反模板化与长期新鲜度 —— ✅ 采纳（低成本低风险）
- **理由**：语义相似度拦截是 C3 的直接需求且可在 Gate 层实现（现有去重只有精确 key）；话题池衰减可由既有记忆衰减（strength + 时间）驱动，无需新组件；「年度重型事件」归入模块 10 的标志性事件；人格缓慢生长与既有 nightly digest / self_model 机制同构，列为后续项不在本批锁定。
- **注意**：去重拦截必须同时拦候选素材，不然 LLM 会复读素材——已在 C3 行为验收里写明。

### 模块 12：度量与工程落地 —— ⚠️ 部分采纳
- **采纳**：配置化（动机权重/静默线/节奏曲线进 `companion_continuity` 配置段——与既有 `space_preference` 模式一致）；MVP 分层已体现为 C1→C4 垂直切片；健康度红线中可观测的三项（回复率崩塌、明确拒绝、配额超发）进 C3 行为验收。
- **不采纳**：截图率/收藏率（QQ 无此事件源）、A/B 实验（单机个人产品没有样本量）。留存/会话延长类产品指标超出项目定位——veranima 不是运营产品，不建分析管道。

### 加试题判定
1. **她第一次索取承诺** —— 列为标志性事件候选。方向正确：爱是双向索取，`be_need`（被需要感）维度是项目现状的真空缺；但「哪一刻」是关系判断，不硬编码。
2. **30 天重返第一句** —— ✅ 已采纳，C1 回归窗口。全场价值密度最高的一条，且只改消费链。
3. **AI 自我指涉时刻** —— ❌ 与已拍板「不暴露 AI 身份」冲突（用户明确否决过 sakura 的 DESKTOP_PET_CONTEXT 身份声明路线）。
4. **零文字消息** —— ❌ 通道能力外；桌宠立绘/气泡本身承担此职能，属已有多端分工。
5. **主动退后一步** —— 记录为后续候选。与「不参与现实社交」红线精神一致且可能是高级感的真正来源，但文案极易翻车（说教/推开感），不进本批范围，待 C3 跑通后单独评估。

## 总评

这份 prompt 的最大价值不是任何单条策略，而是两个判据：**每次开口必须能回指内部状态量**、**每个设计必须归因到具体感受维度**。按这两个判据检查，veranima 的问题不是机制缺失而是消费断裂——所以全部采纳项都收敛为对 `COMPANION_CONTINUITY_DESIGN.md` C1–C4 的增强，而不是新模块。全部不采纳项的共同理由只有一句话：**能力不存在于通道里，或真实于诚实冲突**。
