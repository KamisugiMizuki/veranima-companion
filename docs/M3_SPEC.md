# M3 专项细化：桌宠端 MVP（docs/M3_SPEC.md）

> 依据：DESIGN.md 3.1（桌宠前端选型风险）、4.6（视觉注意力）、4.7（时空沉浸）、4.8（跨通道共享）
> 进程架构已定（2026-08）：**A 方案——Python 核心进程 + Tauri 纯 UI 壳**。
> 分两阶段：**M3a 纯 Python 逻辑**（时空沉浸/通道互斥/无缝衔接，QQ 端独立验证）→ **M3b 桌宠本体**（Tauri UI + TTS + 在场检测）。

## 1. 进程架构（A 方案）

```
┌───────────────────────── Python 核心进程（常驻） ─────────────────────────┐
│  Agent（共享单例：记忆/状态/情绪/依恋度）                                    │
│  ├─ QQ adapter（已存在，ws://127.0.0.1:8099，NapCat）                       │
│  ├─ 时空沉浸引擎（M3a：场景锁 + 后台心跳 + 主动发起仲裁）                     │
│  ├─ 在场检测器（M3b：键盘/鼠标系统事件，L0 零 token）                        │
│  └─ 通道互斥器（M3a：某通道活跃 → 其他通道感知降功耗）                       │
│  └─ 桌宠服务端（M3b：HTTP/WS，供 Tauri 壳连接）                             │
└────────────────────────────────────────────────────────────────────────────┘
                                    │ WS/HTTP（本地，127.0.0.1）
┌────────────────────────────────────────────────────────────────────────────┐
│  Tauri 纯 UI 壳（独立进程）                                                  │
│  - 窗口/桌宠形象/状态气泡（显示「在想你」等）                                 │
│  - 语音播放（接收 TTS 音频流）                                               │
│  - 无业务逻辑，一切转发给 Python 核心                                        │
└────────────────────────────────────────────────────────────────────────────┘
```

**原则**：QQ 与桌宠是**同一 Agent 的两种前端**；桌宠 UI 壳不持有任何状态，断线重连后从核心拉取。

**通信协议（M3b，本地 WS `ws://127.0.0.1:PORT`）**：
| 方向 | 消息 | 说明 |
| --- | --- | --- |
| 核心→壳 | `state` | 状态推送（情绪/依恋度/当前活动） |
| 核心→壳 | `speak {text, tts_tags}` | 语音播放指令（文本 + 语速/停顿标签） |
| 核心→壳 | `bubble {text}` | 状态气泡文案 |
| 壳→核心 | `user_said {text}` | 用户对桌宠说话（语音→文本→Agent） |
| 壳→核心 | `ping` / `pong` | 心跳 |

## 2. M3a：纯 Python 逻辑（先做，QQ 端独立验证）

### 2.1 时空沉浸引擎（DESIGN 4.7 细化）

**场景状态锁**：
- 场景识别：用户消息显式声明（「看电影了」「开会」「写稿」）→ 关键词 + LLM 确认双轨
- 场景状态机：`normal → busy（慢回/短回）→ 结束（用户主动回来或 2h 无场景相关消息）`
- 场景期间：主动发起禁止（仲裁器直接拦截）；回复长度上限 ~40 字；回复延迟可加 30~120s（模拟「在忙没看到」）
- 数据：`scene: {type, started_at, last_touch_at}` 存 AgentState（随快照持久化）

**后台心跳**：
- 复用 object_design 的 `OfflineThinkTimer`（静默窗口 + 概率）作为触发源，但**内容改为心跳素材**：
  - 「离线成长」：静默期整理聊天记录（recent_messages 摘要）→ 下次破冰用
  - 破冰模板池：`（刚在整理聊天记录，发现你上次说 X…）` 等，LLM 生成 + 模板兜底
- 心跳频率：静默 ≥30min 后每 2h 最多 1 次（防打扰）；与 4.7 仲裁器联动（闲适性机制）

**主动发起仲裁器**（DESIGN 4.7 已设计，M3a 落地最小版）：
- 输入：五机制请求（M1 已有时间仪式化/社交疲劳/闲适性）+ 场景状态 + 通道互斥状态
- 输出：允许/拦截 + 冷却
- 最小实现：优先级排序 + 频率限制 + 场景拦截 + 互斥拦截（**不做权重公式**，ponytail: 五机制各自独立触发，仲裁只做「拦截+排序」，权重计算等实测需要再加）

### 2.2 通道互斥活动检测（DESIGN 4.8）

- 规则：**任一通道有近期活动（30min 内）→ 其他通道的主动感知/主动发起暂停**
- 实现：`ChannelActivityTracker`（内存，`{channel: last_activity_ts}`）
  - QQ 消息到达 → 记 QQ 活跃
  - 在场检测器（M3b）→ 记桌宠活跃
  - 互斥查询：`active(channel) -> bool`——判断某通道当前是否「独享用户注意力」
- 消费方：仲裁器（QQ 活跃时桌宠不主动说话）、视觉调度器（M4，QQ 活跃时降功耗）

### 2.3 无缝衔接（DESIGN 4.8）

- 触发：在场检测器报告「用户回到电脑前」+ 距上次桌宠交互 >30min
- 行为：Agent 从共享历史取最近 3 条消息 → 生成一句衔接语（prompt：`用户刚离开手机聊天，现在回到电脑前。根据最近对话自然地打个招呼或接续话题，不要说「欢迎回来」这种生硬话`）
- 通过桌宠通道（TTS）输出；若 QQ 最近无对话则不触发（无事发生不硬聊）

## 3. M3b：桌宠本体

### 3.1 前端选型（DESIGN 3.1 待定，M3b 开工前定）

| 候选 | 状态 | 备注 |
| --- | --- | --- |
| Tauri v2 | MacroPhonic 未调通（窗口/GPU 问题），**不能当已验证经验** | 需重新评估，重点：透明窗口/置顶/多屏 |
| Electron | koodo-reader 已验证（Electron+React 全家桶） | 重（~100MB），但桌面壳成熟 |
| WPF | Windows 原生 | 与 Python 核心通信要自写 |

**决策时点**：M3a 完成、进入 M3b 时；先用最小 PoC 验证「透明置顶小窗 + WS 连接」再定。

### 3.2 TTS 链路

- 复用 MacroPhonic `server.py`（Qwen3-TTS sidecar，已验证）——独立进程，Python 核心 HTTP 调 `/tts`
- 流程：Agent 回复 → TTS 标签解析（`<语速>`/`[pause]`）→ 调 sidecar 合成 → 音频流发给 Tauri 壳播放
- 打断：用户新消息 → 停止当前播放（壳执行，核心发 `stop_speak`）
- 缓存：相同文本 hash 缓存音频（`data/tts_cache/`），避免重复合成

### 3.3 在场检测器

- L0 零 token：Windows 全局键盘/鼠标钩子（`pynput` 或 Win32 API），事件计数 + 时间戳
- 判定：`last_input_ts` 距现在 <5min → 用户在场；持续 >30min 无输入且屏幕锁定 → 离开
- 只发事件：`presence: on/off`，不传具体内容（隐私）

### 3.4 桌宠前台 UI 细节（MVP 必需集）

**窗口形态**：
- 尺寸 ~200×240px（形象区 + 气泡区），置顶 + 无边框 + **点击穿透**（除形象本体外区域鼠标穿透，不挡用户操作）
- 位置：默认右下角（任务栏上方），可拖拽（按住形象本体拖动）；记住位置（本地 config）
- 最小化=隐藏到托盘（不退出核心）；托盘图标点击恢复

**形象（MVP = 静态图 + 状态切换，不做骨骼动画）**：
- 状态机：`idle`（默认，轻微呼吸动画可后置）/ `speaking`（TTS 播放中）/ `thinking`（核心处理中）/ `sleeping`（用户离开）
- 形象来源：角色卡配置 `avatar` 字段（图片路径）；MVP 先提供 2-3 张占位状态图，动画后续换

**状态气泡**：
- 触发：`speak` 消息的文本同时进气泡（听+看）；`thinking` 显示「……」（打字感）
- 气泡样式：圆角白底/黑字，跟随形象；**不常驻**，无消息 3s 后消失（防挡屏）

**用户交互（MVP 最小集）**：
- 左键单击形象：触发「戳一下」→ 核心生成一句互动（复用 heartbeat 的破冰逻辑，短版）
- 右键菜单：`说话（开关）` / `去安静会儿`（进 away 场景）/ `退出桌宠`（只退壳，核心继续跑 QQ）
- 拖拽：按住移动位置
- **MVP 不做**：语音输入（麦克风转写）、拖文件投喂、形象动画编辑器

**生命周期**：
- 启动：壳启动 → 连核心 WS（失败重试，指数退避 1s→2s→4s…上限 30s）→ 拉取 state → 显示
- 退出：壳退出不杀核心（核心是常驻服务）；核心退出时壳显示「失联」气泡 + 托盘重连
- 崩溃恢复：壳重启后自动重连，状态从核心拉取（壳无状态，断线无损失）

**通信细节**：
- 协议沿用 3 节表；`speak` 带 `tts_tags`（语速/停顿），壳解析后按标签播放
- 心跳：壳每 10s ping，核心 3 次无响应判定断线 → 显示失联
