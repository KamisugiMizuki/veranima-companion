# QQ 主动对话与分通道冷却设计规范

> 状态：设计稿 v1.0；Phase 0–3 已按本规范落地，当前实现基线见提交记录。
> 范围：**只适用于 QQ 文字聊天通道**。本文不把 QQ 的主动发言策略应用到桌宠，也不改变桌宠视觉注意力的内容策略。
> 依据：`docs/newly_added/design_append.md`、`docs/R4_SPEC.md`、`docs/VISION_SPEC.md` 及当前生产调用链。

## 1. 目标与边界

### 1.1 目标

本专项解决两个问题：

1. QQ 与桌宠不再共享主动发起消息的冷却时间；两个通道拥有独立、可配置的主动间隔。
2. QQ 主动发言从“最后一条消息后固定等待，再定时尝试”改为基于 QQ 文本时间线的时机决策：先判断现在是否适合打扰，再判断是否有值得说的内容。

QQ 是异步、高打扰、高退出成本的媒介。用户关闭 QQ 对话框后，主动消息可能被理解为入侵，因此 QQ 主动发言的默认策略必须比桌宠更克制。

### 1.2 不属于本专项的内容

- 不把 QQ 的五维概率模型用于桌宠。
- 不从桌宠视觉事件生成 QQ 主动消息。
- 不因 QQ 策略改动截图、视觉注意力、`AttentionScheduler` 或桌宠 TTS。
- 不实现真实的后台活动、浏览网页、看电影、听歌等行为。
- 不把“虚拟状态前缀”写成系统实际执行过某项现实操作的证据。
- 不新增远程搜索或新的记忆后端。

桌宠仍通过自己的 `pet` 通道使用视觉注意力、观察事件、`ProactiveGate` 和桌宠 TTS。两通道可以保留“用户当前正在另一通道交互时不打扰”的活动互斥，但这不是共享冷却，不能读取或更新对方通道的最后发言时间。

## 2. 当前实现事实

### 2.1 当前主动入口

现有系统存在三类主动来源：

| 来源 | 当前入口 | 当前用途 |
|---|---|---|
| `ritual` | `Agent.tick_proactive()` | 定时问候、节日、纪念日 |
| `shared_episode` / `scene` | `Agent.late_reply()`、`Agent.heartbeat()` | QQ 后台离线思考与对话衔接 |
| `attention` | `PetServer._process_attention_event()` | 桌宠视觉观察后的主动发言 |

QQ adapter 的后台循环会调用 `tick_proactive()`、离线思考和延迟 `proactive_msg`；桌宠服务会从视觉事件进入同一个 Agent/闸门。

### 2.2 当前共享状态问题

`core/ambient.py` 的 `ProactiveGate` 当前使用单组状态：

```text
_last_any
_last_sent[source]
_today_count
_ignored_streak[source]
```

因此 QQ 或桌宠任一通道成功发言后，会影响另一通道的全局间隔和每日额度。`source` 只能区分 `ritual`、`attention` 等来源，不能区分真正的交付通道。

### 2.3 需要保留的活动互斥

`ChannelActivityTracker` 记录用户最近是否在 QQ 或桌宠交互。该机制和主动冷却是两个不同概念：

- **冷却**：某通道自己上一次主动发言后，多久才允许该通道再次主动发言。
- **活动互斥**：用户正在另一通道交互时，是否暂时不打扰。

本专项只消除前者的跨通道共享。后者默认保留：用户刚在 QQ 对话时，桌宠视觉主动可以安静；用户正在桌宠聊天时，QQ 主动也可以暂缓。活动互斥不应更新对方的 cooldown timestamp。

## 3. 通道模型

### 3.1 Candidate 增加交付通道

主动候选必须同时拥有来源和交付通道：

```python
@dataclass(frozen=True)
class ProactiveCandidate:
    channel: Literal["qq", "pet"]
    source: str
    reason: str
    relevance: float
    urgency: float
    intent: str
    context: dict
```

兼容迁移期间，缺少 `channel` 的旧候选按调用方补齐，不能通过 `source` 猜测通道。

### 3.2 Gate 状态按通道分桶

目标状态形态：

```python
_last_any: dict[str, float]
_last_sent: dict[tuple[str, str], float]
_today_count: dict[str, int]
_ignored_streak: dict[tuple[str, str], int]
```

索引关系：

```text
_last_any["qq"]
_last_any["pet"]
_last_sent[("qq", "ritual")]
_last_sent[("qq", "shared_episode")]
_last_sent[("pet", "attention")]
```

QQ 的主动消息不会更新 `pet` 的 `_last_any`；桌宠视觉主动不会更新 `qq` 的 `_last_any`。

### 3.3 配置建议

```yaml
proactive:
  enabled: true
  quiet_hours_enabled: true
  quiet_hours: [23, 8]
  # 可选的跨通道紧急总上限。默认关闭，避免再次产生隐式通道耦合。
  global_max_per_day: 0

  channels:
    qq:
      enabled: true
      min_gap_minutes: 120
      source_gap_minutes: 120
      max_per_day: 2
      evaluation_interval_minutes: 15
      post_silence_buffer_minutes: 30
      sleep_silence_hours: 8
      sleep_min_hours: 6
      sleep_max_hours: 12
      low_activity_multiplier: 0.3
      ignored_reply_window_hours: 24

    pet:
      enabled: true
      min_gap_minutes: 30
      source_gap_minutes: 120
      max_per_day: 2
```

字段含义：

- `min_gap_minutes`：该通道任意两次主动发言之间的硬下限。
- `source_gap_minutes`：同一通道、同一来源之间的硬下限。
- `max_per_day`：该通道每日主动发言上限。
- `evaluation_interval_minutes`：QQ 时机引擎重新计算的间隔，不等于发送间隔。
- `global_max_per_day`：仅作为紧急总保险；为 `0` 时关闭，不参与普通决策。

旧配置迁移：

```text
proactive.min_gap_minutes      → proactive.channels.qq.min_gap_minutes
                                → proactive.channels.pet.min_gap_minutes
proactive.source_gap_minutes   → 两个 channel 的 source_gap_minutes
proactive.max_per_day          → 两个 channel 的 max_per_day
```

迁移只用于生成初始值。之后 UI 修改的是通道字段，不再写回一个含义模糊的全局间隔字段。

## 4. QQ 主动时机引擎

### 4.1 总体流程

```text
QQ 文本消息/时间线
    ↓
用户状态识别（睡眠、忙碌、低落、离场、普通结束）
    ↓
QQ 文本时间线统计
    ↓
15 分钟一次的时机评估
    ↓
五维 readiness score
    ↓
硬闸门：静默期、最小间隔、每日上限、活动互斥、忽略退避
    ↓
内容素材选择
    ↓
最终打扰系数检查
    ↓
Agent 生成一条 QQ 文本
    ↓
发送成功后提交 cooldown 与 feedback
```

QQ 端不应在每次 60 秒 tick 时独立掷一次概率骰子。否则同一候选在一个小时内可能被重复尝试很多次，累计概率会接近必发。`P(触发)` 在本设计中首先是**时机准备度分数**，不是每次 tick 都重新独立抽样的概率。

### 4.2 评估状态

QQ 时机引擎维护：

```python
@dataclass
class QQProactiveState:
    last_user_message_at: str | None
    last_qq_proactive_at: str | None
    next_evaluation_at: str | None
    user_state: str                 # normal/sleeping/busy/low_mood/away
    user_state_started_at: str | None
    user_state_until: str | None
    pending_opportunity: dict | None
    routine_profile: dict
    social_capital: dict
```

该状态应能从本地消息时间和 `proactive_feedback` 重建。进程重启不能把 QQ 冷却清零，否则重启桌宠或 QQ bot 就会绕过反骚扰规则。

### 4.3 维度 A：时间衰减因子 T

距离最近一次 QQ 对话越久，主动准备度先缓慢上升，再快速上升，长时间完全断联后略微谨慎下降。采用可测试的 S 型分段曲线，不要求模型参与计算。

建议锚点：

| 距离最近 QQ 对话 | T 建议范围 | 行为含义 |
|---|---:|---|
| 0–2 小时 | 0.05–0.10 | 刚聊完，不急着找 |
| 2–8 小时 | 0.20–0.50 | 逐步恢复联系意愿 |
| 8–24 小时 | 0.50–0.70 | 可以认真考虑一次 |
| 24–72 小时 | 0.70 左右 | 达到高点但仍需理由 |
| 超过 72 小时 | 0.55–0.70 | 太久未联系，开口需要更好的素材 |

`qq.min_gap_minutes` 是硬门槛，T 不能绕过它。用户刚说“晚安”后，即使有高价值记忆，也不能在几分钟内由该引擎发起下一条 QQ 主动消息。

### 4.4 维度 B：对话热度惯性 M

取最近三轮 QQ 对话计算用户参与度。冷启动或数据不足时取 `M=1.0`，不凭空推断用户热情。

参与度可由以下可观测量组成：

- 用户消息长度，做上限截断后归一化；
- 用户回复间隔，过快或正常连续回复增加分数，长时间无响应降低分数；
- 明确的情绪/投入信号；
- 对主动消息是否有回应。

建议范围：`M ∈ [0.5, 1.5]`。该项只改变“更早/更晚评估”，不直接保证发送。

### 4.5 维度 C：用户行为画像 R

只通过 QQ 被动积累聚合统计，不保存额外的原始行为日志：

- 24 小时活跃时段直方图；
- 工作日与周末的活跃差异；
- 用户回复间隔的中位数与分位数；
- 稳定的长时间离线时段。

冷启动至少需要一段有效样本后才启用。样本不足时 `R=1.0`。当当前时段历史活跃度低于 20% 时，使用 `R=0.3`；一般活跃时段使用 `R=1.0`；明显高活跃时段最多使用 `R=1.2`。

该画像只保存在本地聚合数据中，不向 LLM 注入完整统计表，只在生成阶段提供“当前是用户较常回复/较少回复的时段”这一简短结论。

### 4.6 维度 D：情境素材 C

判断“现在有没有值得说的事”，素材只来自已有本地消息和记忆，不因没有素材而编造事件。

素材优先级：

1. 高置信度、强相关的用户事实或共同事件；
2. 上次中断、尚未闭合的话题；
3. 与时间间隔直接相关的 follow-up；
4. 用户明确承诺或待办的提醒；
5. 无具体素材时的低负担存在确认。

建议系数：

```text
无素材或只有弱素材：C=0.5
普通相关素材：       C=1.0
高置信度强相关素材： C=2.0
```

“外部信息”只有在项目已有联网搜索能力、用户明确允许且信息真实可验证时才可作为素材。第一阶段不依赖联网搜索，避免 QQ 主动引擎因为网络失败而失去确定性。

### 4.7 维度 E：社交资本 S

社交资本只按 QQ 主动消息计算，不混入桌宠主动结果。使用最近三次 QQ 主动发言的反馈：

- 用户在反馈窗口内回应率 `<30%`：未来 24 小时 `S=0.2`；
- 用户回应率 `30%–80%`：`S=1.0`；
- 用户回应率 `>80%`：最多 `S=1.3`；
- 少于三次样本：`S=1.0`，不提前惩罚。

连续两次 QQ 主动未回应时，同一来源冷却翻倍。用户明确表示“不想被打扰”时，QQ 主动立即暂停，直到用户主动恢复或显式解除。

### 4.8 综合分数

```text
P = clamp(T × M × R × C × S, 0, 1)
```

这里的 `P` 是 readiness score，不是每 15 分钟无条件抽样的概率。

| P | 处理 |
|---:|---|
| `P < 0.30` | 本轮不生成；下一次评估延后 60 分钟 |
| `0.30 <= P < 0.70` | 保留一次低优先级 opportunity；15 分钟后重算，不发送 |
| `P >= 0.70` | 进入内容选择和最终打扰检查 |

任何硬闸门失败都直接拒绝，不由 P 覆盖：

- QQ 通道关闭；
- 用户状态为睡眠/低落硬静默；
- quiet hours；
- `min_gap_minutes` 未到；
- QQ 当日上限已满；
- 同源冷却未到；
- QQ 近期被忽略退避；
- 用户正在桌宠交互，且活动互斥策略要求暂缓。

## 5. 用户状态感知协议

### 5.1 状态优先级

```text
sleeping > low_mood > busy > away > closing > normal
```

### 5.2 状态信号

| 状态 | 示例信号 | 默认静默期 | 解除条件 |
|---|---|---:|---|
| `sleeping` | 我去睡了、晚安、困了、先睡了 | 8 小时 | 用户主动发言；或达到最小 6 小时后进入软苏醒 |
| `busy` | 开会了、忙去了、先工作、回头聊 | 2 小时 | 用户主动发言；或到期后重新评估 |
| `low_mood` | 心情不好、不想说话、让我静静 | 不设固定自动发言 | 用户主动发言；或 24 小时后只允许低强度评估 |
| `away` | 出门了、车上、信号不好 | 1 小时 | 用户主动发言；或到期后重新评估 |
| `closing` | 嗯、好的、拜拜，且无其他信号 | 30 分钟 | 用户主动发言或到期 |
| `normal` | 无特殊状态 | 使用五维模型 | 无 |

状态识别第一阶段使用关键词和简单正则，不调用 LLM。复合信号取更高优先级，例如“晚安，今天心情也很差”进入 `sleeping`，同时保存低落证据供后续语气使用。

### 5.3 睡眠静默期

- 冷启动默认 8 小时；不允许低于 6 小时；不超过 12 小时。
- 静默期内用户发消息时，立即解除睡眠状态，正常回复用户，但不把这条消息自动解释为“已经睡醒一整晚”。
- 到达 80% 时进入软苏醒：可以处理用户消息，但不主动发起。
- 到达 100% 后再等待礼貌缓冲期，默认 30 分钟。
- 到达解除时间不等于立即发消息；仍需重新计算 P、检查素材和打扰系数。
- 静默期内错过的候选不全部排队。最多保留一个最高价值 opportunity，其余丢弃。

## 6. QQ 主动内容策略

### 6.1 内容选择顺序

```text
高置信度记忆/未闭合话题
    > 时间关联 follow-up
    > 长时间断联后的轻量状态分享
    > 存在确认式
```

### 6.2 回忆触发式

适用：存在有来源、有时间、有相关性的记忆。

示例风格：

```text
我刚刚突然想起你之前说过的那个事，后来有后续吗？
```

约束：

- 必须能追溯到本地消息或记忆；
- 不把低置信度内容说成确定事实；
- 不同时塞入多个回忆；
- 用户纠正后立即承认并停止继续围绕错误记忆展开。

### 6.3 时间关联式

适用：时间间隔本身构成自然话题，或上次对话有明确 follow-up。

示例风格：

```text
前几天你说的那个事，我后来又想了下。
```

系统必须依据真实消息时间计算“前几天/刚才/今天”，不能仅凭用户说过“睡觉”就制造跨日。

### 6.4 轻量状态分享式

适用：超过 24 小时、没有强记忆素材，但 P 达到阈值。

内容应是低投入、可回可不回的短消息，例如：

```text
刚才安静了一会儿，突然想起你了。
```

“刚忙完”“刚醒”等可以作为模糊的角色化开场，但不得编造可验证的精确外部活动、地点、人物或新闻。该前缀只是表达层状态，不代表系统真的执行了对应行为。

### 6.5 存在确认式

适用：没有高价值素材，且已经经过时间、社交资本和静默期闸门。

```text
（探头）
在吗？不急着回。
```

该类型必须低频、短文本、允许用户不回复，不能连续使用同一模板。它是最低优先级，不能成为“每隔几小时问一次在干嘛”的定时器。

### 6.6 首次解除静默的状态确认

睡眠/忙碌静默期解除后，第一次 QQ 主动发言应尊重用户刚才的状态，但不假设用户确实完成了睡眠或工作：

```text
早。昨晚后来睡着了吗？
```

不要直接断言“你睡了八小时”“你刚忙完”，除非用户的后续消息提供了证据。

## 7. 后台虚拟状态

设计允许在生成阶段使用模糊的角色化状态标签，帮助开场自然，但它不是实际后台行为。

建议映射：

| 距上次 QQ 对话 | 状态表达 |
|---:|---|
| `<2h` | 无前缀，直接延续 |
| `2–6h` | 刚忙完手头的事、刚安静下来 |
| `6–12h` | 刚醒、刚想起这件事 |
| `12–24h` | 过了大半天，突然想起 |
| `>24h` | 突然想起来、好久没聊了 |

实现时状态标签只作为生成上下文，不写入长期记忆，不作为事实证据，也不要求后台启动额外进程。

## 8. 发送与反馈闭环

### 8.1 发送时机

- QQ 用户消息到达后，所有未发送的 pending QQ opportunity 作废。
- 普通 QQ 回复与主动消息不能同轮发送。
- `proactive_msg` 继续使用现有延迟发送机制，但必须归入 `channel=qq` 并受 QQ 通道的最小间隔与社交资本约束。
- 只有 QQ API 发送成功后才提交 QQ cooldown、每日计数和 `proactive_feedback`。
- LLM 生成失败、渲染为空或发送失败不消耗主动额度；可记录 failure，但不能伪造“已发出”。

### 8.2 反馈归属

`proactive_feedback` 增加 `channel` 与候选标识：

```text
channel: qq | pet
source: ritual | shared_episode | scene | attention | offline
candidate_id: 唯一候选 ID
sent_at
responded
responded_at
interrupted
dismissed
user_sent_within
```

QQ 的用户回复只更新最近一条未完成的 QQ 主动反馈，不更新桌宠主动反馈。桌宠交互也不能提高 QQ 的回复率。

### 8.3 用户明确拒绝

当用户表达“别主动找我”“不要打扰”等明确意图：

1. 立即暂停 QQ 主动；
2. 正常处理后续用户主动消息；
3. 不把普通“没空”“晚点聊”误判为永久拒绝；
4. 只有用户再次明确允许，或设置页显式恢复，才解除暂停。

## 9. 桌宠通道的保留策略

桌宠不使用本文的 QQ 五维模型。桌宠保持：

```text
视觉事件 → Observation → 相关记忆 → attention candidate → pet gate → TTS/气泡
```

桌宠只使用自己的配置：

```yaml
proactive:
  channels:
    pet:
      min_gap_minutes: 30
      source_gap_minutes: 120
      max_per_day: 2
```

QQ 与桌宠之间保留的只有：

- 同一 Agent、记忆和人格状态；
- 用户跨通道活动互斥；
- 全局显式暂停/quiet hours（如果产品决定保留）。

不共享：

- `last_any`；
- 通道每日额度；
- 同源冷却；
- 忽略退避；
- QQ 用户回复率；
- QQ 用户状态锁与 routine profile。

## 10. 实施分期

### Phase 0：通道冷却拆分

- 为候选和 Gate 引入 `channel`；
- 将 `_last_any`、`_last_sent`、每日计数、忽略退避按通道分桶；
- 增加 `proactive.channels.qq` 与 `proactive.channels.pet`；
- 旧配置自动迁移；
- 行为测试证明 QQ 发言不会改变 pet cooldown，pet 发言不会改变 QQ cooldown。

### Phase 1：QQ 时间与状态 MVP

实现：

- T 时间衰减；
- QQ 最小间隔与 15 分钟评估周期；
- 睡眠/忙碌/低落/离场/普通结束信号；
- quiet hours 与睡眠静默期；
- 静默结束后的礼貌缓冲；
- 存在确认式和轻量状态分享式；
- 不使用独立随机骰子，采用 readiness threshold。

### Phase 2：QQ 情境素材

实现：

- 时间关联素材；
- 未闭合话题识别；
- 高置信度记忆检索；
- 回忆触发式内容；
- opportunity 合并与过期；
- 高价值素材优先，弱素材降级。

### Phase 3：个性化与社交资本

实现：

- M 对话热度；
- R 用户 routine profile；
- S QQ 主动回复率、忽略退避和显式拒绝；
- 最小样本数与冷启动默认值；
- 统计只保留本地聚合画像。

### 暂不实现

- 真正的后台生活进程；
- 自动联网获取“值得分享”的外部新闻；
- 跨用户或云端行为画像；
- 用复杂模型训练用户回复概率；
- 把 QQ 主动策略移植到桌宠。

## 11. 测试与验收

### 11.1 通道隔离

- QQ 发言后，pet 仍按自己的间隔计时；
- pet 发言后，QQ 仍按自己的间隔计时；
- 旧全局字段迁移后两个通道均有明确值；
- 活动互斥阻塞不改变另一通道 cooldown timestamp。

### 11.2 QQ 时间线

- 0–2 小时不会因一次 tick 立即发言；
- 2–8 小时分数逐步上升；
- 24–72 小时不超过峰值；
- 超过 72 小时谨慎下降；
- 每 15 分钟评估一次，不在每个 tick 重复累计概率；
- `P < 0.3` 延后 1 小时；`0.3–0.7` 延后 15 分钟；`P >= 0.7` 才进入生成。

### 11.3 用户状态

- “晚安/我去睡了”后 6 小时内不主动；
- 睡眠静默期内用户主动发消息后立即恢复正常回复；
- 睡眠静默期到期不掐点发送；
- 到期后仍需等待礼貌缓冲和完整闸门；
- “我不想被打扰”暂停 QQ 主动；
- 普通“晚点聊”不能永久暂停。

### 11.4 内容与事实

- 高置信度记忆优先于存在确认式；
- 无记忆素材时不得生成“你之前说过……”；
- 混合时间戳能正确区分“几分钟前”和“昨天”；
- 生成失败不消耗主动额度；
- 用户回复后取消 pending opportunity；
- 连续未回应会降低同源主动倾向；
- 低频模板不重复刷屏。

### 11.5 体验验收

一周连续使用中应满足：

- 用户说晚安后不会在几分钟到几十分钟内被 QQ 主动打扰；
- QQ 主动消息能解释为“有理由的联系”，而不是固定间隔问候；
- 用户不回复时，主动倾向会明显收敛；
- 用户持续回应时，联系可以适度变得自然，但不会突破硬间隔和每日上限；
- 桌宠视觉主动的频率不会因为 QQ 主动消息而被同一个 cooldown 直接吞掉，反之亦然。

## 12. 待确认决策

以下是实现前需要用户确认的产品决策，文档先给出默认建议：

1. **默认 QQ 最小主动间隔**：建议 120 分钟；桌宠保留 30 分钟。理由是 QQ 的打扰成本明显更高。
2. **每日上限是否也完全分通道**：建议分通道；保留一个默认关闭的 `global_max_per_day` 作为紧急保险。
3. **quiet hours 是否分通道**：建议先保留全局硬静默，后续如用户需要再增加 `qq.quiet_hours` 覆盖。
4. **QQ routine profile 最小样本数**：建议至少 12 条有效 QQ 用户回复后启用；此前使用中性系数 `R=1.0`。
5. **主动内容中的虚拟状态前缀**：建议只允许模糊、不可验证的角色化措辞，不允许声称执行过现实操作或编造精确外部事实。

本文件记录当前实现契约与验收结果；后续新增策略仍需先更新本文，再实现和补行为测试。
